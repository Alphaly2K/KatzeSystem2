# CSTL 多语言文本

适用基线：CatSystem2 2.6.1.90。CSTL 存放各语言的姓名和正文，不包含剧情命令；与 [CST](cst.md) 的消息系统配合使用。

## 编码

所有字符串均为 UTF-8，并以字节长度作为前缀。整数使用 FF 编码：连续读字节并求和，读到小于 `0xFF` 的字节后结束。

|整数|编码字节|
|:--|:--|
|0|`00`|
|254|`FE`|
|255|`FF 00`|
|256|`FF 01`|
|510|`FF FF 00`|
|513|`FF FF 03`|

这不是 LEB128。末尾的非 FF 字节参与求和，零长度字符串只消耗一个长度字节。

```text
FFString := FFInteger(byteLength) + byteLength 个 UTF-8 字节
```

读取时按字节长度确定下一个字段，不能按 Unicode 字符数量前移，也不应以零字节寻找字符串终点。

## 文件结构

|顺序|类型|含义|
|:--|:--|:--|
|1|4 字节|签名 `CSTL`|
|2|u32|未明字段；本次 526 份文件均为 0|
|3|FFInteger|语言数 L|
|4|L 个 FFString|语言名称|
|5|FFInteger|消息条目数 M|
|6|M 个消息条目|每条含 L 组姓名和正文|

每个消息条目依照语言表的顺序读取：

```text
语言 0 的 Name、Content
语言 1 的 Name、Content
...
语言 L-1 的 Name、Content
```

Name 可为空字符串。语言名称按配置和表项匹配；不要把语言表位置直接解释为启动配置中的语言序号，也不要将名称映射为某个固定 Windows 代码页。

## 与 CST 消息的对应关系

CST 仍负责命令、消息边界和输入。CSTL 提供的字符串需要在相应消息位置使用，文本标记及姓名／正文的角色继续保留。

不能按每条 `0x20` Message 记录直接推进一个 CSTL 条目：一个输入消息块中可能含多段正文。也不能把 CST 头中的 InputCount 用作 CSTL 条目数，该表还包含末次输入后的命令区间。

本次样本对照为：

- 526 份 CSTL 全部可读到文件末尾，均具有三个语言表项，且各有同名 CST。
- 526 组共含 40,828 个基础对白输入块和 40,861 个本地化条目。
- 513 组的条目数相等；其余 13 组多出的 **33 条全部对应末尾 `fselect` 的选项文字**，姓名字段为空。差额为 5 条的有 1 组、3 条的有 4 组、2 条的有 8 组。
- 对全部默认语言正文进行顺序比对，40,814 个对白块在规范化控制标记后相等；其余 14 个块存在单字符差异，仍能通过前后连续条目确定位置。这些文本差异不作自动修正。

因此，前述 13 组应按含选项文本的本地化数据处理。绑定消息时保留场景、块、记录和选项位置，不通过截断或补空条目改变资源。

## 条件选项索引

原剧情 KCS 的收集函数已执行核实：先计算条件，再为保留下来的选项分配从零开始的连续序号。条件为假的物理记录不消耗序号，结果 ID 和跳转目标不参与本地化索引计算。

合成示例：

```text
fselect demo_choices
if (0) 10 demo_a Hidden
if (1) 20 demo_b VisibleB
30 demo_c VisibleC
```

最终列表为 ID 20、30，分别读取选项本地化序号 0、1。

原选项 getter 使用的 CSTL 条目下标为：

```text
条目下标 = CST 输入区间数 - 1 + 保留后的选项序号
```

此处输入区间数包括最后的命令区间。该公式来自原 getter，并用合成消息表验证，不需要统计物理选项行来推算起点。

13 个实际菜单共 36 条物理选项，其中七个菜单含一对互斥条件记录。逐菜单执行零／非零两种条件状态，共 26 次，结果每种状态合计保留 **29 项**，全部使用连续序号；默认语言文字与这些实际读取项逐项相等。

33 条选项数据中的另外 **4 条未被该收集路径读取**，各位于四个菜单的末尾，默认语言内容分别与前一条重复。另有三个条件菜单本身只存两条选项本地化数据。读取时保留所有条目；执行时按收集后的序号绑定，不为未使用的条目新增选项或改变序号。

选项 getter 将同一正文的 `U+001F` 片段依次连接，遇到第一个空片段结束。例如 `first<U+001F>part` 返回 `firstpart`。缺失所请求的语言、条目越界或空正文均得到空结果；KCS 收集函数在结果长度为零时使用 CST 原选项文本。这一回退规则已用合成表和原收集函数分别核实。

## 姓名与正文片段

同一输入区间使用一个 CSTL 条目。Name 读取该条目的姓名；Message 的片段下标为当前记录之前的 Message 数量，从零开始。Name 和其他记录不增加片段号。

合成区间 `Name → Message → Name → Message` 配合姓名 `N` 和正文 `first<U+001F>second`，原文本读取函数依次返回 `N`、`first`、`N`、`second`。

原引擎的正文读取还按 `U+001F` 分隔同一条目内的文本片段：片段编号为负时返回全部正文，为零时返回首段，正数选择后续段；条目或片段越界返回空串。该路径已由读取函数和合成数据交叉核对。基线对白的换行／续写对应中也出现该分隔字节，需要将它保留为控制数据。

## 待核实

- 切换语言时当前消息、选项和历史记录的刷新与缓存规则。
- 正文／姓名路径的语言回退，以及空姓名对当前发言人状态的影响。
- 续写标记、文本替换、控制标记和消息历史记录的处理顺序。
