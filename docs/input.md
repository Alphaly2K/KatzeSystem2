# 输入区域与事件接口

适配基线为 Windows CatSystem2 **2.6.1.90**。`input::Regions` 提供区域登记、属性命令、指针选择、滚轮和移动通知，`Events` 提供按键事件分派，`Keys` 提供扫描顺序、更新计数和重复触发，`DeviceKeys` 将物理按钮映射到逻辑键槽。`InputObject` 和 `InputFactory` 已连接运行时的显式事件、对象命令、平滑定位与同步设备更新；平台采集继续实现。

命令 145 使用第一数据项选择键槽，依次查询绑定组 0、1、2、3，并将原始掩码按位合并到返回槽。查询不请求首次重复状态，不受单键扫描开关或已保存计数影响，也不主动轮询设备；第二及第三数据项不改变查询。删除对象保留返回槽且跳过设备访问。槽号限于 0～79，越界返回诊断；设备查询失败保留已经完成的返回槽写入。

## 登记与顺序

`Regions::default()` 创建空登记表。`records()` 按当前优先级返回只读记录，`get(id)` 返回排序中的首个匹配项。编号允许重复，优先级按 i32 从大到小稳定排列；相等时保持登记顺序。更改优先级会将首个匹配项移除、追加到末尾，再排序，因此即使优先级数值不变，同级位置也会改变。

命令 127 的 data1 缓冲区至少为六十字节，按小端复制十五个 DWORD。`Region::words()` 提供原始记录；其已确认字段如下：

|DWORD 索引|契约|
|--:|:--|
|0|区域编号，取自缓冲区；登记命令的 `data[0]` 不是编号|
|1|有符号优先级，登记时由 `data[0]` 覆盖|
|2|事件掩码，由命令 132 更新|
|3～6|矩形 left／top／right／bottom，保留 i32 位模式及反向边界|
|7|选择标记，登记时归零；保留非布尔值|
|8|启用值，登记时设为一；保留非布尔值|
|9|指针选择启用值，由命令 136 更新，登记时设为一|
|10|保留调用者提供的原始 DWORD，其消费语义待核实|
|11～13|位掩码存在标记／宽／高，登记时清零；原指针槽以存在标记一代替|
|14|移动通知启用值，由命令 154 更新，登记时设为一|

`id()`、`priority()`、`bounds()`、`selected()`、`enabled()`、`selection_enabled()`、`motion_enabled()` 和 `event_mask()` 查询对应字段，`hit_mask()` 返回显式位掩码。记录中的 DWORD 不作进程指针或 VM 地址解引用。区域数量超过一百万时返回诊断。

## 坐标转换

`CoordinateMap::to_logical([x, y])` 返回逻辑点及是否位于逻辑画布内。映射保存设备偏移与统一缩放、配置整数偏移、逐轴逻辑缩放及有符号逻辑尺寸。默认设备与逻辑变换为单位变换，逻辑尺寸为零。

每轴先将 i32 点转为 f32，减 device_offset，乘 device_scale 的倒数，再向零截断成 i32；随后按 i32 回绕减 configuration_offset，重新转为 f32 并乘 logical_scale，再次向零截断。每一步保持单精度舍入，不合并两次整数转换。NaN、无穷或超出 i32 范围的转换返回 i32::MIN，后续阶段照常处理这个值。

范围判定使用最终点，包含零、不包含 logical_size 端点，不裁剪坐标；负尺寸不产生有效范围。大于单精度连续整数范围的输入即使使用单位变换，也可能因 f32 舍入改变整数值。设备后端不存在时，调用方仅将设备偏移／缩放设为零／一，配置及逻辑变换仍参与。运行时的自动更新、对象 126 和普通 native 149 使用共享映射；显式逻辑事件入口保持调用方提供的坐标。

`CoordinateMap::to_device([x, y])` 提供指针定位所需的反向转换，返回设备点及原始逻辑点是否位于画布内。先对输入点按 logical_size 判断范围，再逐轴乘独立的 `device_units_per_logical` 并截断为 i32，按回绕加 configuration_offset，转 f32 后除以单精度的 device_scale 倒数，加 device_offset，再截断为 i32。倒数计算和除法各自舍入，不能改写为直接乘 device_scale；异常转换仍返回 i32::MIN，后续步骤继续。

device_units_per_logical 初值为一，与 logical_scale 分别保存，调用方按配置赋值；不在运行时自动取 reciprocal，也不保证两个方向逐点互逆。反向换算不裁剪画布外点，范围标志也不受变换后设备位置影响；138／139 只接受范围标志为真的目标。

普通 739 在 Runtime 中接受两个输出 VM 地址，查询绘图设备偏移经加倍和逻辑转换后的值，返回状态二，不压值。它读取同一 CoordinateMap，设备后端缺失时同样由调用方提供零设备偏移和单位设备缩放。

查询先向第二、第一输出依次写零；drawing.mode 为零且 enabled 开启时，再将 device_offset 的两个 f32 依次向零截断并写回。随后依次对两处当前 DWORD 作回绕加倍，再按第一、第二轴依序执行上述逻辑转换。mode 或 enabled 关闭时，起始值保持零，后面的逻辑转换仍执行。active 和画布目标不参与该查询。

每一步都读取此前写回后的存储。输出同址或部分重叠时，第二次加倍及第二轴转换会读到前一次的结果；不能先独立计算两个坐标再统一写入。普通区、外部区和地址零均有效，容量不足返回诊断并保留此前写入。3,456 组完整原调用与 Runtime 的返回协议及两份存储逐字节一致，覆盖状态门控、后端缺失、分数、非有限数、整数回绕、同址与部分重叠。

## 位掩码

`HitMask::new([width, height], bytes)` 接收紧密排列的位图，长度必须精确等于 `ceil(width / 8) * height`，每行独立按字节对齐，同一字节低位对应较小 X。尺寸使用非负 i32 范围，宽度加七不得溢出，字节数量受库的 64 MiB 上限约束。`contains(origin, point)` 按 i32 回绕计算相对坐标，负值、越界或未置位均不命中。

`HitMask::from_image(image)` 从已解码的 32 位 Image 生成独立位图。每轴优先使用画布尺寸，为零时使用该轴裁剪尺寸；图像像素按 offset 放入画布范围，Alpha 非零即置位，Base 不参与。负偏移裁去画布外像素，RGB 和非零 Alpha 的具体大小保持相同命中含义。各行尾部填充位为零，空尺寸生成空字节区；尺寸及字节上限沿用 new 的约束。

`Regions::set_hit_mask(id, mask)` 修改首个匹配项；None 清除位图及三个相关 DWORD。该显式宿主接口保持区域重算标记和 DWORD 14。

输入命令 147 通过 `Host::image(handle)` 查询解码图像；Runtime 使用普通 111／112 管理的同一份图像，365 的原始资源句柄不用于此处。区域不存在时直接跳过查询。非零句柄替换先释放旧位图、清存在标记，再查询图像、保存新尺寸并生成位图；查询失败保留原尺寸，尺寸验证失败保留新尺寸，均保持空位图。零句柄只在已有位图时清位图和尺寸，原先空位图的残留尺寸保持原值。以上路径保留其他区域字段及 output；已删除输入对象在入口跳过全部处理。

生成后的字节归输入区域持有，图像修改或释放不改变已保存位图，后续 147 重新生成。位图生成本身不触发选择重算。平面命令 98 查询根输入任务并转发 147，自身编号作为区域编号，`data[1]` 为图像句柄，保留原第三数据项；该转发不要求已绑定事件接收者。

## 按键事件分派

`Events::default()` 提供零捕获、零全局状态及零抑制值。`KeyEvent` 包含事件类别、消息编号、0～79 的键槽、原始按下值、事件掩码及已转换的逻辑坐标。`dispatch_key(sender, regions, event, route)` 同步分派；回调接收可变区域表及 `Command`。返回 None 表示不可达，Some(0) 表示消费，其他结果表示未消费。路由错误原样返回，错误前已发生的状态修改保留。

所有消息保持传入编号，sender 为输入任务编号，target 为区域编号，data 固定为 `[key, pressed, 0]`。掩码只用于筛选及保存全局状态，不转发到第三数据项。

|事件|候选与筛选|捕获变化|
|:--|:--|:--|
|Change 且 pressed 非零|按当前顺序检查启用且掩码相交的区域；未消费时继续|开始前清零；首个消费目标成为该键捕获|
|Change 且 pressed 为零|只检查启用值；有捕获时限于相同编号，无捕获时可投递全部启用项；跳过掩码、矩形及位图|无论消费与否，正常结束时清零|
|Repeat 且 pressed 非零|有捕获时只检查首个相同编号，无捕获时只检查排序首项；使用按下筛选，失败即结束|保持原值|
|Repeat 且 pressed 为零|不投递|保持原值|

掩码含数值二时才检查空间命中：非空矩形包含左上、排除右下，空或反向矩形不限制命中；设置位图后还需相对矩形左上角的位图命中。其他事件掩码跳过全部空间检查。编号零可以消费按下事件，但捕获零仍表示无捕获。重复编号按表中规则分别参与遍历。

回调可使用区域接口追加、删除后续项或修改属性和优先级；后续遍历从当前登记项变动后的下一项继续，新插入在当前项之前的记录本次跳过。回调应在同一登记表上调用这些接口。删除或重新登记当前项后，若原入口还需访问该项，库返回明确诊断；基线在这条路径上继续访问已释放的节点。单次遍历超过一百万项也返回诊断。

`set_suppressed(value)` 非零时拒绝事件，保留捕获和全局状态。其他合法事件先保存掩码到 `raw_state()`，包括 Repeat 的释放；`state()` 提供输入命令 137 的查询映射，仅将原值十六映射为二。InputObject 已将该状态绑定到命令及设备更新。

## 物理按钮映射

`DeviceKeys::from_xml(bytes)` 读取 `KEYCUSTOMIZE/key00`～`key79`。非空 name 启用对应槽，缺失或空 name 禁用；缺失数值取零。keyboard1～4、mouse1～4、joypad1～4、touch1～4 为四个绑定，rep_keyboard1～4 等为对应重复字段。XML 中的代码和重复值均截取低八位。`DeviceKeys::new([DeviceBinding; 80])` 接受显式配置，repeat 在这个接口保留完整 u32。`Default` 创建全部禁用的配置。

`DeviceBinding` 的 codes 和 repeat 第一维按 `ButtonSource` 的 Keyboard、Mouse、Joypad、Touch 排列，第二维为第一至第四个绑定。扫描中的四组对应绑定编号，事件来源由掩码表示。`bindings()` 只读查询配置；`set_binding(key, binding)` 替换单槽，并清空该槽的按键掩码、重复元数据及强制查询计数。

`button(source, code, pressed)` 接收平台按钮事件。code 截取低八位，pressed 非零视为按下。来源掩码分别为 1、2、4、16；Keyboard、Joypad 各自匹配对应来源的代码，Mouse 和 Touch 均匹配两类代码，同组同时匹配时优先取 Mouse 的重复值。掩码始终使用事件实际来源。同一事件按绑定组再按键槽更新，debug_mode 为零只更新前 32 槽，非零更新全部 80 槽；跳过的高槽保留旧状态且仍可查询。

按下同时写本轮状态和持有状态，释放只清持有状态；一轮中按下后释放仍能产生一次按下。任一匹配事件都会改写该键槽唯一的 repeat 元数据，包括释放，四组共享最新值。`sample(key, group, repeat_requested)` 返回本轮 `KeySample`；repeat_requested 为 false 时只把返回的 repeat 设零，查询仍执行。

`force(key, queries)` 设置强制按下的查询次数。计数非零时 sample 返回掩码一并递减计数，四组及额外查询共用同一计数，单位为查询次数。`commit()` 用持有态替换本轮状态，消费短按脉冲；`clear_pressed()` 仅清两份掩码，保留配置、repeat 及强制计数。键槽限于 0～79，组限于 0～3，越界返回诊断。

平台 `InputDevice` 可在 poll 中调用 button，在 key 中调用 sample，在 commit 中调用同名方法。鼠标左／中／右键的代码为 1／2／3，滚轮上／下为 6／7。两个启动示例从启动配置建立绑定，无窗口点击使用相同映射；窗口示例提供键鼠采集。

`WheelButtons` 将垂直滚轮消息转换为鼠标 6／7 的按钮事件。`scroll(up, emit)` 立即按下，连续同向消息累加延迟重复，反向消息替换重复方向；`finish(emit)` 在扫描后、设备 commit 前释放当前脉冲，再按交替帧重放剩余重复。`cancel_repeat()` 只清方向和计数，保留当前脉冲及其释放。窗口示例将每次取得的非零垂直滚动快照送入该状态，保留独立的滚动通知；窗口库已合并的消息无法逐条还原。

## 设备按键扫描

`Keys::default()` 创建四组、每组八十键的零状态，八十个键开关均为一。`scan(services)` 按组 0～3、每组键 0～79 的顺序调用 `KeyServices::sample`，取得 `KeySample { mask, repeat }`。键开关为零时四组都跳过查询和状态更新，已有状态冻结。命令 151 以 `data[0]` 选择键槽、`data[1]` 设置原始开关；152 将全部开关恢复为一，均保留结果槽。非法键槽返回诊断。普通 404 已由 Runtime 接入：忽略参数，经根命令 34 取得输入编号，再发送 152；两次路由均使用调用任务为发送者、三个数据项为零，不修改按键计数、掩码或消费标记，以状态二保留返回槽。

`records()` 的第一维为键、第二维为组，每项 `KeyState` 保存原始 count、设备掩码和上次分派的消费标记；`enabled()` 返回键开关。count 每次参与扫描时按 u32 回绕加一，不使用毫秒或帧增量。相同非零掩码延续计数，不同非零掩码从一开始；原值十六每轮都重新从一开始。计数一产生按下，非零计数遇到零掩码产生释放并清零计数和设备掩码。

首次重复阈值固定为三十：该轮 sample.repeat 非零才进入重复阶段。阶段中的 count 最高位保持一，低位到五时再次重复并重置低位。首次阈值错过后不会因开关后来开启而补发；进入重复阶段后间隔检查不再读取 repeat。两个阈值来自基线构造，不是时间单位。

`KeyServices::dispatch(keys, transition)` 同步接收按下、释放或重复，返回 true 表示消费。消费立即结束本轮剩余扫描，`scan` 返回 true；否则继续，完整扫描结束返回 false。首次重复之前，正计数的已有消费标记也会中断下一轮扫描，即使本轮没有新事件。进入重复阶段后，未达到间隔阈值的轮次允许继续扫描。释放消费结束后，下一轮零计数不会继续阻挡后续键。

`KeyTransition` 保留绑定组 group，事件掩码将设备原值十六映射为二，`Keys` 中仍保存十六。`Events::dispatch_transition(sender, regions, transition, point, route)` 将它转换为消息 4 和 `[key, pressed, 0]`；group 不写入消息。按下或释放先解除分派抑制，重复保留抑制。point 由输入宿主提供当前逻辑坐标。

查询和分派交错执行，设备可在后续查询时提供新状态；分派回调也可通过 Keys 命令改变本轮后续键开关。错误原样返回，已发生的状态更新保留。Keys 单独负责扫描，InputState 的设备更新再组合轮询前后处理、滚轮、移动阈值和自动光标。

## 指针选择重算

`Regions::update_pointer_selection(sender, point, route)` 接收可选逻辑坐标和同步通知回调；None 使用 `[i32::MIN, i32::MIN]` 哨兵坐标。它更新区域选择值，不修改按键捕获、全局按键状态或区域重算标记，也不读取按键分派抑制值。调用时机由输入宿主决定。

首先按当前顺序查找启用且指针选择启用的首个命中项。这里忽略事件掩码；存在位图时只按位图判断，没有位图时只按非空矩形判断，空或反向矩形不命中。

随后遍历启用、指针选择启用且已选择的记录。与候选编号相同时保留选择原值，并取消本次进入候选；其他记录先发送命令 8，再把选择值清零。最后从当前顺序中查找候选编号的首个未选择项，将选择值设为一，再发送命令 7。这次查找不重新检查启用值或命中，因此重复编号可能使更早的禁用记录被选中。被禁用的已有选择在清理阶段保留。

编号全一是无候选哨兵，命中这个编号不会触发进入；没有候选时，同编号的已有选择也不会被清除。重复编号的已有选择按实时遍历处理，首个保留后，后续项可能收到离开通知。

通知 sender 为输入任务，target 为区域编号，data 为 `[x, y, 0]`，坐标保留 i32 位模式。路由响应不参与选择；回调错误原样返回。离开回调期间能看到原选择值，返回后的清零会覆盖回调对当前选择值的修改；进入回调期间能看到新值一。后续遍历使用回调修改后的区域表，当前节点失效的诊断规则与按键分派相同。

## 指针移动通知

`Regions::dispatch_pointer_motion(sender, motion, route)` 接收 `PointerMotion { code, previous, current }`，两点均为逻辑坐标。原输入主体使用命令 6；接口保留显式消息编号。区域须启用、移动通知启用且事件掩码含二。非空矩形按 previous 筛选，空或反向矩形不限制；位图、选择标记和指针选择启用值均不参与。

每条通知的 sender 为输入任务、target 为区域编号。data0／data1 显式缓冲区分别保存 previous／current，每项为两个小端 i32，共八字节；Command 的原指针槽使用零，data[2] 也为零。回调可以修改两个缓冲区，后续接收者看到同一组修改后的数据，后续矩形筛选也读取修改后的 previous。缓冲区在本次分派结束后释放，不回写传入的 `PointerMotion`。

本入口遍历全部合格区域，不使用消费响应，也不修改按键状态、捕获、选择或重算标记。回调可通过区域接口改变后续遍历，错误与当前节点失效规则沿用其他事件入口。何时达到移动阈值并产生通知由输入宿主负责。

## 同步设备更新

`InputDevice` 提供 poll、pointer、key、take_wheel、is_foreground、finish、commit、history、show_cursor、cursor_visible、set_pointer、clear_keys 和 cancel_wheel_repeat；每次调用返回 Result，错误停止当前推进，先前已发生的状态和回调修改保留。pointer 返回 `PointerSample { position, active }`，位置为物理设备整数。key 的 repeat 参数表示是否需要首次重复开关元数据，false 时仍须查询掩码。take_wheel 返回本轮待处理的原始非零标记，平台后端负责消费设备积累值。history 返回三十二个原始字节。set_pointer 请求设备移动到物理点，不自动替换本轮已保存位置；clear_keys 清理设备键状态，后续查询继续由设备提供。

`InputState::pointer()`／`pointer_mut()` 提供 `PointerState`。position 保存本轮位置，origin 保存按下／滚轮时额外查询的物理起点，移动通知结束后更新为 position；两者不能合并。active 保存帧首查询的原始值。cursor_requested 是手动显示意愿的设备读回，cursor_shown 是任务维护的自动显示状态，二者初值均为一；auto_hide、idle_limit、idle_count 和 forced 初值为零，drag_threshold 初值为二，history 初始清零。forced 是命令 146 的强制重算标记，定位字段见下文。

`InputState::update_device(id, host)` 按以下次序同步执行，InputObject 的主体自动调用它：

1. poll 后查询 pointer。位置变化或 geometry_dirty 时重算选择，活动状态非零使用逻辑点，否则使用 None；随后保存物理位置。强制重算结束清 forced，正常位置变化清 idle_count 并按需自动显示光标。
2. 位置不变且无重算标记时，活动且处于前台才递增 idle_count；auto_hide、cursor_requested、cursor_shown 均非零且达到 idle_limit 时隐藏并广播。非活动且 forced 为零时清计数，并按需显示，这次显示不广播。
3. 执行 Keys 扫描。首次按下在事件前额外查询 pointer 保存 origin；按下／释放解除抑制，事件使用已保存的本轮位置换算。消费仅结束按键扫描，继续后续设备处理。
4. take_wheel 非零时额外查询 pointer 保存 origin，以本轮保存位置换算后分派消息 5。`Regions::dispatch_wheel` 遍历启用且命中的区域；非空矩形和可选位图参与，空／反向矩形不限，忽略事件掩码、选择和移动通知开关。data 为 `[0, 0, 0]`，响应不参与消费。
5. 依次查询 key(0, 0, false) 和 key(0, 1, false)。合并掩码含二时，未抑制则任一物理轴与 origin 的回绕差绝对值达到 drag_threshold 后设置抑制一并发送移动 6；已抑制则任一位移非零就发送。移动使用换算后的 origin／position，返回后 origin 更新为本轮 position。
6. finish、commit，清 geometry_dirty，最后保存 history。

自动光标显示／隐藏先更新 cursor_shown，再调用 show_cursor；需通知时广播消息 22，sender 为输入任务、target 为根编号零、data 为 `[0, visible, 0]`。回调可查询 149 或调用 150，修改即时影响后续判断；消费某个接收者不终止广播。手动命令 150 自身不广播，也不改变自动状态。

move_remaining 为正时，帧首取样后进入下文的平滑定位分支，再继续按键、滚轮、拖动和收尾。DeviceKeys 提供配置绑定，平台采集尚未提供。未绑定设备时，InputObject 主体返回缺少设备的诊断，显式事件入口仍可调用。

## 平滑定位

`Runtime::set_input_pointer_control(enabled)` 设置 138 的配置门控，默认关闭；独立宿主实现 `Host::input_pointer_control()`，默认返回 false。138 配置关闭时直接消费，跳过设备访问；139 不检查这项配置。其他情况下先查询 is_foreground，再对打包的逻辑点调用 to_device；非前台或逻辑范围外均保留已有定位和按键状态。两个坐标均为 0～65535，低／高字不作 i16 符号扩展。

目标有效时先执行按键清理。抑制为零时全部跳过；非零时清除启用且计数非零项的计数、设备掩码与消费值，零计数项和禁用键原样保留。捕获槽和原始事件状态均保持；随后解除抑制并调用 clear_keys。原事件入口在抑制下拒绝释放，因此没有释放通知。设备清理失败时已发生的修改保留，定位字段尚未替换；回调中同样即时生效。

清理成功后，move_target 保存设备目标，move_remaining 保存 `data[0] as i32`，move_started 保存任务 `clock.elapsed()`；三者初值均为零。零或负剩余值仍替换目标与起点时间，但后续不进入自动移动分支。命令自身不调用 set_pointer。

更新时若 move_remaining 为正，每轴按 i32 回绕计算 `old + (target - old) / remaining`，除法向零截断，然后调用 set_pointer(next)。原剩余值大于一时，新值按 u32 回绕计算 `remaining + move_started - now`，转为 i32 后至少为一；原值为一时归零。now 为本轮外层时刻，Runtime 使用 `clock.previous_time`，暂停不冻结这个输入；帧增量不参与该计算。

原物理取样点不为 `[0, 0]` 时，按 next 重算选择，非活动状态仍使用 None；随后按自动光标门控显示并广播。原点取样跳过这两项。该分支清 idle_count，保留 forced；本轮保存位置按基线行为设置为 `[next.y, old.y]`，设备请求和选择通知继续使用 next。后续按键坐标及拖动检查使用这份保存位置。

## 输入对象与运行时

`InputFactory { fallback }` 创建类型十一的 `InputObject::new(id)`、类型六的 `ButtonObject::new(id)`、类型四十二的 `SliderObject::new(id)` 和类型四十一的 `Scroll2Object::new(id)`，其他类型委托已有工厂，可与图形、KCS 工厂组合。InputObject 保存编号、独立的 `InputState`、控制与时钟；非空创建上下文、普通 KCS 消息队列及同步 VM 消息尚不支持，返回诊断。删除先恢复光标并标记，树更新时释放，重新创建取得全新的区域、键和捕获状态。

`Runtime::set_input_device(device)` 绑定同步设备，并逐个读取已有输入对象的初始位置；绑定后新建输入对象在树登记前读取初始位置，失败不占用编号。初始化只修改 position 和 active，不覆盖按键、捕获或其他指针状态。绑定及初始化错误保留此前完成的修改。`input_coordinates()`／`input_coordinates_mut()` 提供共享 CoordinateMap，配置由调用方准备。

运行时提供以下显式入口，目标须为已创建的输入对象：

|入口|契约|
|:--|:--|
|`input_state(id)`／`input_state_mut(id)`|查询对象持有的输入状态；InputState 提供 regions、keys、events、pointer 及必要可变视图|
|`dispatch_input_key(id, event)`|同步分派已经带逻辑坐标的事件，返回是否被消费|
|`scan_input_keys(id, point, sample)`|按实际顺序调用 sample(key, group)，分派消息 4；返回是否因消费中断扫描|
|`update_input_selection(id, point)`|重算选择并完成命令 7／8 通知|
|`dispatch_input_motion(id, motion)`|完成移动通知，前后坐标缓冲区共享修改|

同步接收者可以直接向正在执行的输入任务发送区域、键开关、已实现的指针或基类命令。修改即时作用于后续事件游标和设备查询；输入任务的删除标记、属性及暂停值也保持。所有错误路径都会恢复对象及回调状态，错误前的修改保留。消息路由的结果槽初值为一，未写回的接收者按未消费处理；这是库的明确缺省值，原按键入口的临时结果槽未初始化。

`TaskObject::input_state`／`input_state_mut` 提供可选输入视图。独立宿主调用 InputState 的事件方法时，传入 id 必须对应宿主当前任务，并实现 `Host::dispatch_input_command(state, delivery, command, buffers, output)`：delivery 为 `InputDelivery::Direct` 或 Broadcast，路由期间允许嵌套输入命令通过同一 CommandState 分派，返回前保留这些修改。CommandState 的处理器接受 Host，返回树传播状态；宿主路由方法返回目标是否可达。自动更新还需实现 `Host::input_device` 和 `input_coordinates`，默认分别为 None 和单位映射。

Runtime 在处理输入回调的直接命令时切换到输入任务的宿主编号和时钟，返回后恢复外层任务状态。命令触发的广播仍按实时树遍历；若再次命中仍在执行且需要借用完整对象的接收任务，当前运行时返回执行中诊断，错误前的输入状态修改保留。

普通 native 149 在运行时已绑定设备时即时查询 pointer 并使用共享映射，更新 HostState.pointer_position 后按原顺序写 VM 的 X／Y；无设备时使用既有缓存。这与主体保存的本轮位置各自保留查询时点。

## 矩形按钮任务

类型 6 的 `ButtonObject` 独立保存矩形输入区域、显示门控和事件接收者。它通过根命令 34 查询输入任务，不创建图元。`InputFactory` 与图形／FES 工厂组合后可直接创建；逻辑屏幕尺寸使用共享 `CoordinateMap.logical_size`。

|命令|契约|
|:--|:--|
|90|data1 提供六个 DWORD：left、top、right、bottom、priority、parameter。尚未绑定时登记事件掩码 7 的区域，接收者设为 sender，返回槽写 1；重复登记写 0，保留原状态|
|91／3|解除区域登记；91 清接收者并保存响应 1，3 标记删除。树析构不重复解除|
|93／94|已绑定时设置区域启用／选择值；93 禁用时另外清选择|
|95／96／97|保存同步响应／查询输入原始状态／直接设置接收者；97 不登记或解除区域|
|98／99／100|绑定图像 Alpha 掩码／设置区域选择开关／设置移动开关；后两项要求已绑定|
|101／19|101 从 data1 的四个 i32 更新实际区域，保留自身缓存矩形；19 在全屏标记有效时重新提交全屏区域|
|53／50／52／54|53 从 data1 的三个 f32 保存偏移并立即绑定父级；50／52 重算绑定；54 解除绑定并保留偏移|

## 普通 KCS 按钮调用

运行时的 104 接收七项：目标、x、y、width、height、优先级、原始参数。x／y 及尺寸按整数 DWORD 解释，以回绕加法得到 right／bottom，再通过命令 90 提供六 DWORD 的登记缓冲区。sender 为当前任务，三个命令数据项为零，输出槽不转成 native 返回值。区域登记与重复登记行为沿用按钮对象协议。
