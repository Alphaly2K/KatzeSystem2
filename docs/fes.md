# FES 界面脚本

适用基线：CatSystem2 2.6.1.90。FES 是 Front End Script，负责界面对象、输入事件和流程。它使用独立的块与对象语法；表达式的差异见[词法与表达式](expressions.md)。

## 容器与文本

|偏移|类型|字段|
|:--|:--|:--|
|`0x00`|4 字节|签名 `FES` 加零字节|
|`0x04`|u32|压缩长度|
|`0x08`|u32|解压长度|
|`0x0C`|u32|保留字段，语义待核实|
|`0x10`|字节序列|Zlib 压缩的脚本文本|

解压后仍然需要解析文本。基线的编译产物保留了 `#MACRO`、对象声明和子命令声明，不能把它们当作已经消失的源文件信息。

基线 50 份 FES 中，15 份为纯 ASCII；其余含非 ASCII 文本的文件中，32 份可整体按 CP932 解码，3 份无法整体按 CP932 或 UTF-8 解码。进一步定位到这三份文件共 26 行无法按 CP932 解码：这些行的语法前缀均为 ASCII，末尾文本参数为合法 UTF-8，整行也可按 UTF-8 解码。混合发生在文件内部。

`STRING8` 和 `LOGSTRING8` 对象实际存在。加载层保留原始字节和位置，语法符号在字符边界识别，文本参数按对象／命令契约解码；不在读文件时统一转为 CP932。执行行读取时先展开字符串引用，再按词替换宏；参数读取还会执行字符串展开和文本转换。混合编码参数的最终转换仍需按对象／命令核对。

## 词法与头块

FES 支持 `//` 行注释和 `/* ... */` 块注释。字符串中的内容需要与注释分开识别。

以 `#` 开始的头将后续内容划为一个块，直到下一个头或文件结束。头名称区分大小写。普通执行块名、对象事件名和系统声明头需要分别保存。

```ebnf
document      = { headerLine, blockContent } ;
headerLine    = "#", name, { headerParameter }, endOfLine ;
declaration   = objectType, objectName, [ "[", expression, "]" ] ;
objectRef     = objectName, [ "[", expression, "]" ] | "@" ;
objectCommand = objectRef, commandName, argumentTail ;
normalCommand = commandName, argumentTail ;
```

参数、表达式和声明的具体边界依照其类别解析。`#OBJECT` 头的参数是后续行的列定义，不能丢弃。

### 声明头

|头|作用|
|:--|:--|
|`#INCLUDE`|源文件包含；基线已编译文本未出现该头|
|`#PRELOAD`|资源预加载声明|
|`#MACRO`|按词替换的宏定义|
|`#DEFINE`|创建对象和对象数组|
|`#OBJECT columns...`|按指定的列初始化对象|
|`#KEYBLOCK`|键盘／手柄焦点关系|
|`#SUBCOMMAND`|基线中保留的子命令绑定声明|
|`#START`|初始执行块|

官方规则允许相同名称的头分段出现并按顺序连接。基线有 45 份文件出现重复头名，其中包括声明段。汇集普通执行块时保留源顺序；处理多个 `#OBJECT` 段时，仍需保留每段自己的列定义。

### 图像预加载声明

`#PRELOAD` 各行保存完整图像名称；空格、引号和冒号均保留，不进行表达式求值或字符串变量展开。多个 PRELOAD 段按顺序合并，头后的附加文本不改变这一类别。解释器报告声明后，Runtime 在所有对象属性初始化完成、下层媒体创建之前读取并缓存原始字节；具体缓存及消费者规则见[图像预加载](graphics.md#fes-图像预加载)。

### 对象声明与初始化

```text
#DEFINE
IMAGE backdrop
BUTTON choices[2]

#OBJECT POS DISP
backdrop 0,0 1
```

声明中的 `[2]` 表示创建两个对象；执行命令中的 `[1]` 表示第二个对象。执行时省略银行号可表示对整个对象数组操作。

原声明函数按类型名进行不分大小写的匹配，但 `#DEFINE` 行不经过宏替换。数量为 0 时创建一个对象；省略数量或表达式值为 −1 时，查询已有同名对象，已有多个银行则要求明确给出数量，否则按一个对象处理。方括号内的数量表达式不能包含半角空格，`[(1+2)]` 有效。

解释器先报告 INCLUDE／PRELOAD／KEYBLOCK 声明，再逐条发出 `CreateObject` 和 `InitializeObject` 请求，随后报告 SUBCOMMAND，最后执行 START。原始声明仍保留在 `Program.declarations`。588 条基线对象声明均生成创建请求，共涉及 1,678 个银行。负数量、空方括号及超过库上限的数量返回诊断；具体对象更新及图形／音频服务继续接入。

实际对象集合另有一条需要保留的规则：重复声明仍分配新对象，名称与各银行的绑定保持首次登记值，新增银行才取得新绑定；数组数量也保持首次登记值。删除具体对象会移除对应绑定及后代，但保留名称数量，不把先前未绑定的重复对象提升为绑定。显式银行因此可以访问首次数量以外的新银行，省略银行号的数组展开仍只使用首次数量。每条图像声明记录另保存独立媒体包装；重复声明后的当前对象包装与记录包装可能不同，详见[媒体记录](graphics.md#fes-媒体记录与来源包装)。FES 对象标识与其下层任务编号分别使用；初始 `_TOPOBJ_` 为 BASE 根对象，各声明对象先挂在它下面。

`runtime::fes::Objects` 已提供 BASE／CIMAGE／IMAGE／CPLANE／PLANE 的对象身份、银行、父子关系与初始化，处理创建后用 `publish_bindings` 将实际绑定和首次数量同步到对应解释器。CPLANE／PLANE 可通过 Runtime 的显式对象更新入口创建二维任务并绘制；CIMAGE／IMAGE 的共享绘制服务及 FES 主体调度继续接入，接口约束见 [API](api.md)。

对象初始化的列由头指定，逗号连接坐标等复合值。对象还可有父对象，子对象的位置以父对象为坐标原点。

列名区分大小写。ID.N／D／F／P 对应偏移 0／1／2／3；未知字母后缀取偏移 0。数字后缀按十进制或十六进制前缀读取，可带尾随字符。偏移直接加到列代码，因此 `ID.32` 会设置 POS，`POS.1` 会设置 PL。代码超过 66 的列仍消耗输入词项，但不设置属性。原列函数遇到未知列名会报告错误并省略该列；本库返回诊断，要求调用者修正输入。

初始化解码覆盖全部 67 个列代码。未出现的字段保持缺省，明确的零值仍需应用。POS 分量独立覆盖，重复列只更新实际给出的分量；BASE／SIZE／VRAM／KEYBLOCK 首次出现时将其余分量置零，重复出现时保留此前未覆盖的分量。逗号之间的显式空分量取零，缺少尾部分量不会继续覆盖。数组的 PRI 由基础值加银行号计算。

POS2／SIZE2 指定图像资源，写法为 `resource[:frameId]`。对象应用入口拆出名称和编号，稍后从图像元数据取得 POS2 所需的裁剪偏移或 SIZE2 所需的裁剪宽高；两者分别区别于绘制基点和完整画布尺寸。帧号缺省为 0，支持带符号十进制／十六进制整数前缀，不求值表达式。重复 HG-3 帧 ID 按文件顺序选择第一个匹配项。

初始化数值使用 FES 求值入口，不套用 KCS 数值宿主去掉末尾 `%` 的规则。对 `50%` 等不完整表达式，原 FES 返回零，本库返回语法诊断。

387 个合法合成输入的目标、银行、全部属性标记和值、数值副作用与原解码结果一致；另有 49 个不完整百分号表达式得到预期诊断。在为字符串变量提供统一合成资源名的条件下，50 份基线 FES 的 1,815 条初始化行全部生成请求；实际图像和音频对象的创建及属性应用仍待接入。

CIMAGE 状态应用已实现并用上述 387 个合法输入核对原应用函数。该类型使用 POS 的前两个分量、POS2、SIZE、SIZE2、PL、COLOR、BLEND、PRI、DISP、MASK 和 BTYPE；其他列不应用于该类型，PARENT 由公共对象分派层先处理。单独更新一个坐标时，另一个已有坐标也会经过整数读取和 f32 写回。PRI 的数组递增完成后，绘制优先级设置函数还按当前值决定是否加 20；父优先级保存传入值。元数据更新先执行 SIZE2，再执行一次性的 POS2。

IMAGE 另应用 FILE、IDN、32 项 ID 映射和 PATHMODE，不使用 CIMAGE 的 SIZE／COLOR 初始化列。FILE 先保存请求名，再按宿主配置转换；空请求不改变当前资源名。IDN 先于本行 ID 映射执行，映射未启用时可直接指定帧 ID，启用后只接受 0～31 的映射槽位。范围外的映射读取返回 0。相同的 387 个合法输入已与原 IMAGE 状态应用结果一致，名称转换在此对照中关闭；配置驱动的名称转换继续接入。普通文件的实际像素装载、失败和登记规则见 [IMAGE 文件更新](graphics.md#fes-image-文件更新)。

BUTTON 的 `fes::ButtonState` 继承 IMAGE，另应用 SIZE、ENABLE、DEFAULT、KEY_U／D／L／R、TYPE、KEYBLOCK 和 SYSKEY。SIZE 仅在变化时请求来源重建；ENABLE 初值为一，保留原始数值，只在变化时标记按钮自身，不递归使后代失效。默认事件组为空，方向目标为空，KEYBLOCK 初值为 −1,0,0，SYSKEY 初值为 −1。TYPE 保存原值，在下层区域登记时决定是否使用图像 Alpha 掩码，与图像的 MASK／BTYPE 分别维护。TYPE、事件和导航配置单独变化不请求属性更新。387 组合法属性输入已与原 BUTTON 应用入口一致。运行时已接入装载创建、图像及区域更新，详见[BUTTON 区域更新](graphics.md#fes-button-区域更新)；输入回调、默认事件组、网格导航与 [SYSKEY 扫描](graphics.md#fes-系统键分派)均已接入，关联控件继续推进。

CPLANE 使用 POS、BASE、SIZE、POS2、SIZE2、PRI、DISP、COLOR、BLEND、TYPE、EXPOS 和 VIEWPORT。POS 仅在 X／Y 至少一项存在时生效，未指定分量保持，单独 Z 不生效；BASE 的 W 写零。PRI 按银行递增后直接保存。BLEND 在 COLOR 之后覆盖颜色高字节。TYPE 只将输入 2 映射为 2，其余映射为 1；TYPE／EXPOS 单独变化不使属性或尺寸失效。387 组有效输入的属性、资源引用和标记均与原应用入口一致。

CPLANE 的尺寸重建与属性更新分别触发。SIZE 总使尺寸失效，即使数值未变；SIZE2 保留引用，在重建时读取裁剪尺寸。重建先标记旧任务删除，再在 FES 所属任务下创建类型 2 的二维任务；只发创建类型和矩形命令，不自动恢复旧任务的位置、基点或显示。属性失效时先应用一次性 POS2，再提交有效位置、基点 XY 与 PRI、默认缩放及矩阵、颜色、显示和混合模式。位置沿 CPLANE／PLANE 父级累加，基点只沿直接为 PLANE 的父级累加；属性失效会标记 FES 后代。运动、有效 VIEWPORT 对应的二维命令 89 仍待接入。缺失的元数据文件或帧得到零尺寸／零位置，无法读取的格式返回诊断。

PLANE 复用上述平面列，另外应用 VRAM，不读取 FILE。VRAM 初值为四维 `[0,0,0,1]`，初始化列写成 `[x,y,0,0]` 并在值变化时使属性失效。它从共享画布取样，与屏幕位置分别维护；资源来自当前绘图画布，SIZE2 只读取几何元数据。PLANE 重建时先创建二维任务并设置 TYPE，再读取 SIZE2、建立画布纹理矩形，并总是重发有效屏幕位置。后续属性更新在基点之后提交 VRAM 与画布偏移的和；这两个坐标先将 VRAM 向零截断为 i32，再与偏移回绕相加，最后转回 f32。画布偏移改变本身不触发重新提交。基点、显示等仍按属性失效标记更新；仅 SIZE 重建后保留屏幕位置，其余属性恢复下层任务初值。

CIMAGE／IMAGE 的运动传递区已接入：基点 XY 位于 DWORD 3、4；优先级减 20 后转为 f32 位于 5；位置 XY 位于 6、7；缩放 XYZ 位于 25～27，Z 固定为 1；28 的高字节为 Alpha；31 为 Z 旋转弧度；35 为 display。二维类型的其余字段清零，包括 DWORD 9～24 的矩阵区。传递区的 Alpha 与子命令换算使用的对象 COLOR 分开处理；运动回写保留 COLOR 和父优先级。

回写两个分量时先比较整组浮点值，全部相等时保留原位模式，因此正负零不会触发替换。优先级先向零截断到 i32，异常转换取最小值，再按当前值决定是否加 20。128 组原打包及回写入口对照覆盖负零、非有限值、整数边界、Alpha 和原始 display，全部位模式一致。常规合成测试另串联子命令换算、运动参数、VM 执行和图像状态回写。

|平面与图像|`CPLANE`、`PLANE`、`CIMAGE`、`IMAGE`、`DIFIMAGE`|
|输入与控件|`BUTTON`、`SLIDER`、`SCROLL2`|

### 宏

```text
#MACRO
COUNTER 7

#START
\COUNTER=1
next POLL
```

宏按词法器的完整标识符替换，区分大小写。标识符以 ASCII 字母或下划线开头，后续可含数字。宏可出现在变量编号、数组下标、路径片段和命令名位置；例如 `\COUNTER` 变为 `\7`，`COUNTER123` 保持原样。数字后的独立标识符仍可替换，如 `123COUNTER` 变为 `1237`。

同名定义以最后一次为准，值来自定义行的第二个参数，双引号可以保留值中的空格。替换只进行一遍：`A B`、`B 9` 定义下，`A` 展开为 `B`。单引号及双引号内不替换；字节和空白保留。宏读取不改变执行块或事件头的名称。

执行器在运行时先展开该行的 `$str` 引用，再展开宏，随后分派命令。`Program::expand_macros` 提供独立的宏展开接口，供声明宿主及检查工具使用。宏声明仍保留在原始声明列表中，执行器已经处理它们，不将宏声明交给宿主确认。

批量核对全部 50 份 FES 的 23,800 行文本，原宏函数与 Rust 展开结果逐字节一致。合成用例另覆盖递归、重复定义、命令名冲突、引号和数字边界。

### 命令参数

FES 参数入口以半角空格分隔词项，Tab 保留；圆括号可包含空格，`(:text)` 去掉包裹并与相邻字节拼接。ASCII 字母后遇到左括号会另起词项，数字后则继续同一词项；例如 `a(b)c(d)` 读为 `a`、`(b)c`、`(d)`，`1(2)` 保持完整。

双引号入口去掉引号，单引号保持普通字节。原参数表在双引号内容之后留下连续零字节，因此 `cmd "a b" tail` 只读到 `cmd`、`a b`；后续 `tail` 不再可见。引号前的反斜杠不构成这个入口的转义。该规则与宏词法器识别引号的规则不同。

行级字符串及宏展开之后，提取出的各个参数还会再做字符串变量展开；宏引入的 `$str` 因此能够在参数阶段生效。内建控制命令按对应词项读取参数，`break 4 + 5` 的值是 4，`break (4 + 5)` 的值是 9。

全部 23,800 行展开文本共提取 78,775 个词项，原参数函数与 Rust 结果逐字节一致。文本编码转换对应的宿主配置仍需接入。

## 变量与条件

|写法|含义|
|:--|:--|
|`$n`、`$(expr)`|与 CST 共享的数值变量|
|反斜杠加 n 或括号表达式|当前 FES 的局部数值变量|
|`$strN`|字符串变量引用|
|`strvar n value [v1 ... v4]`|运行时写入字符串，最多四个整数用于格式化|
|`strvar get n source`|复制另一个编号字符串；get 忽略 ASCII 大小写|
|`_FRAME_` 等|只读系统值|

本基线实际访问了高于旧手册上限的共享变量编号；配置与启动调用链已确认共享区为 2048 槽，见[表达式](expressions.md)。原生求值器存在未检查边界的访问路径，本项目执行时检查存储范围。CST 的 `#n` 与 FES 的 `$n` 是各自公开的语法前缀，局部反斜杠变量属于另一存储域。

### 运行时字符串写入

`strvar` 在运行时主体、系统块和对象处理器中写入同一份 `expression::State::strings`。先求值目标编号，再按顺序求值最多四个整数参数；额外参数忽略。编号保留转换后的原始 u32，不使用数值共享槽的范围限制。没有目标时直接继续；只有目标时写入空字符串。原始文本及结果保留字节编码，写入到首个零字节结束。

没有整数参数时直接复制文本，百分号保持原样；存在整数参数时执行整数格式化。参数可使用 `(:文本)` 保留空格并允许后续数值参数，例如 `strvar 4 (:voice_%03d) 7` 写入 `voice_007`。双引号后的隐藏词项规则仍然适用。

当前支持 d／i／u／o／x／X／c、双百分号、正负号／空格／左对齐／补零／进制前缀标记、位宽、精度，以及星号位宽和精度。h 和 hh 均按十六位处理；l、I32 按三十二位处理；ll、I64 按低 DWORD 在前的两个参数组合为六十四位。字符格式支持字节 c，零填充标记对它同样生效。零精度的零值八进制输出为空，包括带 # 标记时。

格式字段或完整输出达到 2,560 字节时诊断；缺少格式参数、指针／浮点转换及带长度修饰的字符格式也返回诊断，已有目标字符串保持。上述限制不用于直接按编号复制已有字符串。

`strvar get n source` 先求值目标，再求值来源并复制。来源缺失时写入空字符串；缺少目标时跳过，缺少来源时只保留目标表达式的副作用，不写入。复制及格式化都先取得完整结果再替换目标，因此可以引用或复制目标自身。

FES 同时支持单行条件与块条件：

```ebnf
inlineIf = "if", "(", expression, ")", statement, endOfLine ;
blockIf  = "if", "(", expression, ")", endOfLine,
           { statement },
           [ "else", endOfLine, { statement } ],
           "endif", endOfLine ;
```

```text
#START
$6=1
next POLL

#POLL
if ($6!=0)
    call UPDATE
else
    next FINISH
endif

#UPDATE
\7+=1
break

#FINISH
exit 0
```

零为假，非零为真。块条件可嵌套，必须按结构匹配；实际编译文本中的 2,345 条条件都采用块形式。

## 执行块与调度

|位置／命令|规则|
|:--|:--|
|普通块到末尾|等待下一逻辑帧，然后重新从本块开头执行|
|`next header`|立即转到目标块，本身不引入帧等待|
|`call header`|调用子程序，块结束或 `break` 时回到调用处|
|`break [expression]`|结束当前块，保存表达式值；省略时保存 0。子程序随后返回调用者，普通块随后等待下一帧|
|`exit code`|发布退出通知；基线任务处理后从下一语句继续，生命周期由上层决定|
|`wait frames`|等待指定逻辑时长，数值小于一时按一处理|
|`wait frame [value]`|等待场景帧值达到绝对无符号阈值，缺省零|
|`wait object`|等待指定对象及其后代动作结束|
|`wait`|等待相关对象动作结束，排除音频类|
|`keyskip [options...]`|设置等待取消及连续／强制模式；运行时行为见[等待取消](graphics.md#fes-等待取消与-keyskip)|

逻辑时间单位为 1/60 秒。正常块到末尾与子程序到末尾的行为不同，不能共用一种“文件执行结束”处理。

在不断 `next` 回同一块而没有等待时，手册明确指出可能形成同帧死循环，输入状态也不会更新。解释器应能定位这种执行停滞；暂停后继续、快进和动作取消的细节仍需核实。

普通主体的 `exit` 生成内部事件 6 并请求同一逻辑时刻再次推进。宿主写入任务属性后，继续 exit 后的语句，子程序返回位置也保留；随后到达等待或块末尾才结束本轮。睡眠／唤醒系统块使用另一分派入口：其中的 exit 结束本次分派，事件延迟到下一次普通主体处理。

手册要求子程序内部避免使用 `next`。基线处理函数已确认：`next` 会清空全部子程序返回位置，再转入目标块；目标块结束时按普通块等待下一逻辑帧，不返回原调用者。

## 事件

```text
#choices.PUSH_L
if (@==1)
    @ setid 2
endif
```

事件头格式是 `#对象名.事件名`，不带数组银行号。事件来自具体银行时，通过上下文取得目标对象及编号。

- `@ command ...` 中的 `@` 表示触发事件的对象。
- 事件表达式中的 `@` 可表示触发事件对象的银行号。
- 普通位置参数中的 `@` 表示该参数的当前值。

这三个位置需要不同的上下文绑定。基线使用了 `FOCUS`、`UNFOCUS`、`PUSH_L`、`PUSH_R`、`RELEASE_L`、`SCRL_P`、`STOP` 等事件。

默认事件处理器可供多个对象共用。原分派函数已确认默认处理器先执行，再执行对象自身处理器；处理过程中保留对象名与银行号，结束后恢复先前上下文。

基线两条执行路径有不同的控制流：

- 默认处理器中的 `next` 在事件内部继续执行目标块，随后仍执行对象自身处理器；主流程位置与等待保持原值。
- 对象自身处理器中，目标块名与原事件头不同且调用深度回到进入事件时的深度，便将目标和位置交给主流程，并清除等待。目标第一条语句留给后续主流程执行。
- 对象自身处理器的 `call` 在子程序结束后返回事件。默认处理器的执行循环不弹出返回位置；留下的位置会影响随后对象事件的返回，可能把默认处理器的后续位置交给主流程。
- `next` 清空全部调用栈。若进入事件时主流程已有子程序调用，清空后的深度不再等于进入时深度，目标会在事件内部执行，主流程保留原位置及等待，但原调用栈已经清空。

上述转移规则由独立合成脚本对照。另 26 组合成控制器分派确认：局部 `wait`／`exit` 结束当前处理器，默认组结束后仍执行对象自身处理器；`exit` 另外排队退出通知。进入分派前的主等待和事件内尚未返回的调用保持。控制器返回值取对象自身处理器是否存在，默认组单独存在时为零；它与主流程是否转移分别维护。运行时已提供预算续跑入口，见 [API](api.md)。嵌套事件及动画完成事件的其他分派入口继续核实。

## 焦点网格

```text
#KEYBLOCK 3
0 3,1 -1,1,-1,-1
1 1,4 0,-1,-1,2
2 1,2 0,-1,1,-1
```

KEYBLOCK 在块头指定网格数量；各行依次给出网格编号、横向／纵向按钮数和上／下／左／右离开网格后的目标块。−1 表示没有对应目标。对象的 KEYBLOCK 三元组另用于绑定网格及其坐标。`Objects::navigate_button` 提供基础网格选择，Scene 装载保存此表；任务层已接通默认焦点回退、方向命名值和指针移动，见[方向输入](graphics.md#fes-方向输入与指针定位)。

基线入口只读取第一段 KEYBLOCK，后续同名段忽略。数量使用带符号十进制／十六进制整数前缀，不进行表达式求值；尺寸和方向分量则使用数值求值器。未设置条目初始化为尺寸 0,0 和四个方向 −1。重复行只覆盖实际给出的方向，显式空分量写零。网格编号越界时跳过整行。库对非法数量前缀、超过分配上限的数量和缺少尺寸分量返回诊断；原函数对部分不完整行直接跳过且保留此前写入的分量。

九组合成输入核实默认值、重复行、参数副作用和重复块；实际 15 张表、50 个分配条目的六个数值均与原装载函数一致。

2.6.1.90 的基础 BUTTON 导航不使用 KEY_U／D／L／R；属性仍按原格式保存。源对象为 BUTTON、ENABLE 非零且网格号非负时，才按方向从相邻单元开始搜索。对象枚举取当前名称／银行绑定的字典序，重复声明产生的未绑定对象不参与；同一单元只取第一个对象，其 ENABLE 为零时，该单元的后续对象不会递补。

上下方向先找相同横坐标；没有启用对象时，在该行按横坐标减一、加一、减二、加二的顺序找，再推进下一行。左右方向先找相同纵坐标；其额外搜索仍以纵坐标为中心查询同一行的横坐标，保留基线的轴选择，因此可能返回源按钮。不能将其替换为通常的上下扩散搜索。

当前网格没有结果时，沿对应方向的相邻网格链继续查找，空网格跳过。相邻网格中只考虑启用的 BUTTON，按实际位置先转有符号整数、再转 f32 后计算平方距离；距离严格小于 100,000,000 才是候选，相同距离保留枚举首项。选中后以该对象的网格坐标继续单元查询。无效邻接编号结束查找；无效源网格和超出查询上限的搜索由库诊断。关联滑动控件的调整仍待接入，基础任务路由沿上述方向输入规则执行。

## 子命令绑定

49 份基线 FES 保留 `#SUBCOMMAND`。已识别到 980 条 `oneshot` 和 294 条 `continue` 绑定，结构为：

```ebnf
binding = bindingClass, commandName, targetName,
          { descriptor, "[", defaultValue, "]" },
          ":", { mappedOperand } ;
bindingClass = "oneshot" | "continue" ;
mappedOperand = "[", integer, "]" | literal ;
```

左侧声明描述符及默认值，右侧包含描述符编号和字面参数。描述符区分大小写，包括 p、BX／bx、BY／by、BZ／bz、PX／px、PY／py、PZ／pz、VX／vx、VY／vy、VZ／vz、RX／rx、RY／ry、RZ／rz、SX／sx、SY／sy、SZ／sz、CR／cr、CG／cg、CB／cb、CA／ca、CX／cx。省略默认值时保存文本 `-1`；带方括号时保存其中的文本，在调用阶段再处理。默认文本中的百分号或赋值表达式不会在声明阶段执行。

映射参数 `[n]` 读取括号内的带符号整数前缀，字面整数同样可使用十六进制或尾随字符。cxr／cxg／cxb／cxa／CA 是独立的上下文标记。左右参数表各有 16 项容量，默认文本按 15 字节上限检查。原函数对非法字面前缀可能沿用未初始化数值，本库报告诊断并跳过该行。

目标按运动资源类别解析，结构化接口先保留原资源名，由宿主结合配置查找。多个 SUBCOMMAND 段的有效绑定均参与读取；原函数会对中间的重复头报告一次错误后继续，本库按已识别的声明段处理。同名命令保留第一次定义。解释器在初始化完成、发出子命令声明事件时注册绑定，之后自动识别调用并发出结构化 `Subcommand` 事件；125 个原生命令优先，名称大小写分别匹配。低层接口由宿主补全资源名并装载程序；Runtime 的 Scene 已连接 BASE、CIMAGE、IMAGE 和 BUTTON 的子命令装载、分组零入队及自动运动阶段，详见[对象运动](graphics.md#fes-对象运动)。

结构化调用保存源码位置、目标对象与银行、已注册绑定和已展开输入。事件内的 `@` 对象使用触发对象及银行，银行表达式仅在调用产生时执行一次；重复读取待处理事件保持原调用。银行 −1 由宿主按顺序遍历数组，每个银行分别提供属性并执行参数换算。注册表的诊断可通过 `registered_subcommands()` 读取，无效绑定继续保留逐行诊断。

目标对象存在时，既非内置命令、也未注册为 SUBCOMMAND 的名称只记录日志并继续执行，后续参数不求值；大小写不同的名称分别匹配。只有对象名而没有命令时直接继续。Runtime 在主体、系统块和对象处理器中均保留此规则，将日志写入 `HostState::debug_messages`，前缀为 `Unknown FES object command: `，后接展开后的整行字节。已识别但尚未接入的内置命令仍返回诊断；起始目标缺失的整行表达式回退仍待接入。

`baseimg [object]` 是独立的全局背景命令。当前支持 CIMAGE、IMAGE、BUTTON 来源和 PLANE 裁剪快照；名称与银行只求一次，缺少目标时不遍历数组，缺参或空参数清除背景。它先排队，主体消费请求后在同一帧继续；系统块与对象处理器结束当前片段，下一次普通更新才消费。背景持有、列表命令和提交时点见[背景快照](graphics.md#背景快照)。

`getsndconfex output volume name` 查询分类名称的当前音量，精确小写 master 查询独立主音量。名称和额外参数不作表达式求值；名称缺失或为空时只求值输出参数。分类按声明顺序先父后子查找，单字节名称忽略 ASCII 大小写，多字节字符保持。缺失分类返回 100；该命令不消耗随机数。配置与编号查询见[声音配置查询](audio.md#分类名称与主音量查询)。

调用时，每遇到右侧 `[n]` 就顺序消耗一个实际输入；`n` 选择左侧描述符，缺参时使用该描述符的默认文本。例如 `[1] [0]` 配合输入 `101 202` 仍生成 `101 202`，两项都缺少时才按描述符顺序选择默认值。整数及颜色上下文标记不消耗实际输入。显式空输入改用输出位置对应的默认文本。

|描述符|当前值及百分比基数|换算|
|:--|:--|:--|
|`p`|均为 0|整数求值后转 f32|
|`B*`／`b*`|对象基点分量|小写减去当前值|
|`P*`／`p*`|对象位置分量|小写减去当前值；单字母 `p` 除外|
|`V*`／`v*`|对象速度分量|小写减去当前值|
|`R*`／`r*`|当前弧度分量|输入整数乘 f32 π 再除 180，小写再减当前值|
|`S*`／`s*`|当前值为缩放分量，百分比基数为 1|小写减去当前值|
|`CR/CG/CB/CA` 及小写|对应颜色字节|小写减去当前值|
|`CX/cx`|不读取属性|返回 0，不求值输入|

星号表示 X／Y／Z。`@` 按当前属性值向零截断为 i32，越界或非有限值取 i32 最小值。换算只去掉一个末尾 `%`；百分比在整数转 f32 后按 `value * base / 100` 计算，旋转先完成角度转换。减去当前值时保留其小数。求值后恢复调用前的 `@`，包括事件处理器内的调用；表达式对共享和 FES 局部变量的副作用保留。每个目标银行分别换算，不能复用另一银行的结果。

1,274 条实际绑定的 5,096 个参数描述及默认文本、7,301 个映射项均与原解析结果一致。结构化读取覆盖 49 份文件，保留一条无效裸标记的诊断。

还存在一个不符合绑定结构的裸标记；它没有冒号和参数，不作为有效绑定读取。原声明入口报告类别错误后继续，库同样保存该行诊断并继续读取后续绑定。

一处孤立 `endif` 已与原引擎的控制流整理函数对照：该函数遇到它便返回当前位置，结束本层结构扫描。四个合成块分别覆盖正常条件、多余尾部终止符、开头孤立终止符和 `else`；实际异常块也得到相同行为，70 条非空语句均完成元数据初始化，返回位置是最后的孤立终止符。该符号位于块尾，前面的条件结构已完成整理。读取器应保留它并给出结构诊断。运行时分派该符号及其后的语句仍需单独验证，不自动将它删除或终止整个文件。

## 与宿主的边界

对象内建控制 `disp`／`size`／`keypos`／`setid`／`getid`／`enable`／`pri`／`pos2` 已由运行时对象存储消费，普通推进和睡眠／唤醒系统块共用。签名、类型分派、数组遍历及尚未接入的表达式回退见[图形接口](graphics.md#fes-对象控制命令)。

Scene 另消费 `button noact [value]` 与 `lockactive [value]`，分别排队默认焦点和原始焦点锁。普通主体消费通知；对象／系统处理器内的 lockactive 结束当前处理器。参数与时点见[默认焦点与焦点锁](graphics.md#fes-默认焦点与焦点锁)。

`execfes`、`execkcs`、`endfes`、`endkcs`、`send` 等命令需要子任务和父子通信接口；`_EXITCODE_` 表示子任务状态。对象命令也有不同签名，例如同名 `load` 对图像与音频的参数不同。

完整运行需解释对象初始化列、宏、子命令绑定、事件和子任务协议。只识别普通命令头无法覆盖这些输入。
