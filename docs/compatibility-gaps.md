# 2.6.1.90 兼容缺口

以统一注册表、两套普通 KCS 调用点表和现有运行记录为依据。两款游戏的已验证路线均可推进到标题；引擎兼容性还需覆盖其他脚本、宿主能力和存档状态。

## 延期的引擎兼容项

|范围|缺口|两款游戏的关联|
|:--|:--|:--|
|麻将 470～513|未注册：482、484～487、489～491、493～494、496～513，共 28 个槽。已注册部分仍缺其他调牌预设、出牌前特殊选项、碰杠和牌、后续副露和结算。|两套普通脚本均无直接调用。|
|BMB 983～987|包装和命令 567～571 已路由；实际任务接收端及状态仍待定位。|两套普通脚本均无直接调用。|
|类型 59 与 61|任务协议已接入，实际平台插件、效果播放器留给宿主。|两套普通脚本均无直接调用其包装。|
|语音合成|声音命令和 PCM 合成接口已接入，当前示例未提供合成器。|两套普通脚本均无直接调用合成包装；通常的录制语音播放继续作为回归。|
|开发及窗口扩展|开发窗口、菜单待接入。答题调试面板、图片导入、目录选择、部分输入设备和呈现路径待实际窗口核验。|不阻塞已覆盖的离屏剧情路线；涉及运行期展示及交互，保留已实现的宿主入口。|
|普通 588|默认声音接收端有未写结果槽路径，遇到时仍诊断。|两套普通脚本均无直接调用。|
|社交发帖 1018～1023|类型 62 的默认接收者未接入。原接收者收集账号配置、附件及文字，启动后台发帖，并提供完整 DWORD 结果。库已保留包装及任务路由；后续接入时由宿主决定是否提交并负责网络传输。|两套普通脚本各有一组静态调用，属于附加发帖功能。|

## 重构时保留的 VN 行为

|范围|依据与迁移要求|
|:--|:--|
|系统变更命令|两套普通脚本各调用一次 600／601。包装和任务记录已接入，默认系统变更任务仍缺；继续核实其调用条件及等待顺序。|
|普通 549|两套各一处调用，受类型 43 的启用状态保护。原入口不写返回槽，默认类型 43 为空构造。保留诊断及空构造行为，检查存档恢复后分支是否仍受保护。普通 66 对类型 14／43 的空构造分支继续保留未写结果槽的诊断。|
|FES 旧版声音配置|另一个发行版在启动时使用旧配置的播放动作并中止。播放动作与属性更新尚待核实；两套主回归发行版的启动路径均已通过。|
|常用游戏流程|两款继续验证汉化剧情、Backlog 回放及回跳、保存加载、自动档恢复，以及电影、截图、语音和 BGM 的时序。发现失败时以相关运行路径优先。|
