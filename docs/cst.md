# CST 剧情脚本

适用基线：CatSystem2 2.6.1.90。数值词法见[表达式](expressions.md)，本地化数据见 [CSTL](cstl.md)。

## 运行时上下文

普通 323／324 已通过 Runtime 接入独立 CST 上下文的创建和释放。创建时从全局语言配置复制前缀，按原始 CP932 字节排序去重，空名称同样注册；修改全局语言配置只影响后续创建。初始没有装载脚本，`Runtime::cst_context`、`CstContext::languages` 和 `script` 提供只读查询。句柄与图像及其他数据对象共用递增编号源，不复用，创建任务结束后继续存活，须显式释放。普通 326 查询输入段内的原始记录类型；负段编号查询总段数，负记录编号查询段内记录数，普通越界及未装载上下文返回 0xffffffff，零句柄返回零。`Script::record_kind(input, record)` 提供同样的已装载脚本查询。普通脚本驱动的事件分派继续接入；下文的独立解释器已经提供剧情事件。

96 份原构造快照核实语言注册、重复名、空名、大小写、长名称及配置变化后的实例独立性，Rust 结果一致。常规合成回归连接普通任务、两种预算、共享句柄及显式释放，不依赖设备或外部材料。

### 装载与记录文本

325 接收上下文和文件名格式地址，经 `scene` 类别补全后以散装优先模式读取 CST 和同名 `.cstl`，以状态一返回 CST 是否装载成功。格式名称小于 260 字节。缺失或空 CST 保留全部旧状态且不读取 CSTL；非空错误签名保留旧脚本并重新绑定 CSTL；正确签名但外层长度不符清除脚本，仍尝试 CSTL。成功装载将当前位置重置为零，接受合法的零输入段脚本。畸形主体返回受检诊断。

上下文只绑定构造时登记的语言，按原始字节匹配 CSTL 的 UTF-8 语言名；非 ASCII 的 CP932 前缀可能无法命中 UTF-8 名称。`localization()` 查询当前表，`bound_languages()` 枚举匹配的语言。运行时接受 CSTL 尾部附加字节，独立的 `cstl::Table::parse` 仍严格检查完整容器。

|native|参数|输出编码|
|:--|:--|:--|
|327|上下文、输出地址、输入段、记录|CST 原始字节|
|1033|同上、语言格式地址|命中时 CSTL UTF-8，否则 CST 原始字节|
|1037|同 327|CST CP932 转 UTF-8|
|1038|同 1033|命中时 CSTL UTF-8，否则 CST CP932 转 UTF-8|

四种查询均以状态一返回输出字节长度，末尾写零。零上下文跳过其余参数；无效输出起点、未装载或索引越界返回零并保留输出。输出地址零有效。负输入段／记录分别使用 `position()` 中的当前索引；场景推进方通过 `Runtime::cst_context_mut` 和 `set_position` 保存当前位置，这与 326 的计数查询语义不同。语言格式名称小于 64 字节。

本地化只替换姓名和正文：姓名读取输入段对应的 name，正文按该段内先前正文记录数量选择 `0x1f` 分片。绑定命中但消息或分片缺失时输出空文本；其他记录类型保留原文。27 份装载快照和 3,840 次文本查询与原入口逐字节一致，覆盖返回值、完整 VM 两区、语言匹配及重装载；另一个会访问未初始化主体的畸形容器由 Rust 返回诊断。

### 登记与历史存档

普通 385 接收数据容器、记录编号、CST 上下文、表选择和附加数据开关，共五个 DWORD；386 接收前四项并恢复。表选择零为登记表，其他值为历史表。385 向容器追加记录，386 读取首个同编号记录并替换所选表；另一张表、脚本、当前位置和语言绑定保持。空表可保存，恢复有效空表会清空目标表。两者以状态一返回成功一；任一对象句柄为零或恢复记录缺失时返回零，失效或类型错误句柄返回诊断。

导出总是使用当前格式：四字节零标记，随后连续存储登记项。每项头部为四十八字节，字段如下：

|项内偏移|内容|
|--:|:--|
|0|三十二字节名称区，包含终止零；导入后保留完整字段，查询按首个零截取|
|32|原始无符号值|
|36|七十二字节附加记录的数量|
|40|附加数据字节数|
|44|附加数据相对本项开头的偏移；无数据时为零|
|48|连续附加记录，随后为附加数据|

附加数据开关为零时只省略数据正文，附加记录始终保存。恢复也接受首 DWORD 非零的旧格式：无前置标记，每项为四十字节名称／值／数量头部和连续七十二字节附加记录。再次保存时转为当前格式。导入不按名称合并，重复名和顺序保持；后续 328／329 的值合并保留该项的附加记录及数据。附加记录通过下列字符串接口编辑，未修改的字节继续原样保存。

当前基线的登记表附加数据恢复分支使用第二输入块的地址计算数据位置；386 的该地址为空，一次独立调用确认原入口访问异常。库对此组合返回明确诊断。历史表按当前项的相对偏移读取附加数据；截断、区外偏移、缺少名称终止零和超过读取上限的输入也返回诊断。

132 组原入口场景集中覆盖两种格式、零至三项、重复名、名称尾部字节、原始无符号值、七十二字节附加记录、附加数据及三种相对偏移。两张表在保留／省略数据两种导出模式下的 528 份完整结果，共 72,132 字节，与优化实现全部一致；原登记附加数据异常另用独立调用确认。常规合成回归固定双预算、旧格式转换、值合并后元数据保留、重复容器编号的首项读取和畸形输入诊断。

### 历史变量快照

普通 991／992／994 在历史项的附加数据中保存、查找和裁剪数值／字符串快照，与下文按位置登记的短字符串记录分别维护。三者均先检查上下文；零句柄跳过后续地址和服务访问，992 返回零，其他两项保持返回槽。失效非零句柄返回诊断。

|native|参数|行为|
|--:|:--|:--|
|991|上下文、位置 DWORD、配置名格式地址|为末条历史前置快照，保留旧链；状态二|
|992|上下文、历史索引地址、位置地址、配置名格式地址|向前查找快照，依序写回实际索引和位置，再恢复变量；状态一返回是否找到|
|994|上下文、历史索引、位置 DWORD|裁剪快照及后续历史，更新所选项的值；状态二|

991／992 将首零截止的配置名按 `config` 类别补全，以散装优先模式读取 XML。展开名称须小于 1,024 字节，`localstr` 正文须小于 2,048 字节；它以逗号分隔字符串编号，忽略空段，保留非空段的空白并按引擎整数前缀转换。数值编号来自全局设置的八组局部标志范围，起点及回绕终点按 i32 比较，重复范围保留重复编号。未绑定任务共享数值区时保存零值，恢复时跳过数值写入；正常越界数值同样读零。

992 对负历史索引返回零；非负索引超出末项时从末项向前查找。在原请求的同一历史项中，跳过位置大于请求位置的快照，位置按 i32 比较；更早历史项直接采用其最新快照。数值按快照内保存的编号恢复，不受当前配置范围筛选；字符串仅恢复当前配置选中的编号，快照缺失值恢复为空串。脚本、上下文当前位置及语言绑定保持。

994 在所选项中跳过位置大于或等于请求位置的快照；如找到剩余链，基线写入入口先更新末条历史，再删除后续历史。请求较早项时该次链写入随末项一起被删除；整链都被跳过时原附加数据保持。历史项的值仍更新为请求位置。删除起点为历史索引回绕加一，结果为 `u32::MAX` 时跳过，按 i32 为负时从头删除，结果为零时清空。此入口不读取资源。

每个快照块以五个小端 DWORD 开头，依次为旧块相对偏移（零表示无旧块）、本块末端偏移、数值正文长度、字符串正文长度及位置。后接 Zlib 正文，再接旧链。数值正文为连续的编号／值 DWORD 对；字符串正文为数量 DWORD 和按无符号编号排序的编号／零结尾原始字节串。字符串长度还包含八个未写入尾字节，库固定置零。385／386 的附加数据选项可保存和恢复完整快照链，损坏的长度、偏移或压缩流返回诊断。

### 历史枚举与字符串记录

普通 333～337 使用上下文的历史表，无需先装载 CST。历史索引按无符号数选择，越界时选末项；空表保持为空。位置值为原始无符号 DWORD，接口不作单位换算。

|native|参数与结果|
|--:|:--|
|333|上下文、历史索引、名称输出地址、值输出地址；先写首零截止的名称及一个零，再写 DWORD 值，状态一返回实际索引。空表写空名称和 `u32::MAX`，返回 `u32::MAX`|
|334|上下文、历史索引、位置、字符串编号、来源地址；保存首零截止的原始字节，状态一返回一，空表返回零|
|335|同上，末项为目标地址；查询成功写正文及一个零并返回一，查询失败返回零|
|336|上下文、历史索引、位置、原始文本地址；扫描 `$str` 引用，把全局字符串表中已存在的值保存到该历史项，状态二|
|337|同 336；从历史字符串记录取得引用值并原地替换文本，末尾写两个零，状态二|

334 的键为位置和字符串编号，更新首个相同键，其他键顺序保持。每条记录含两个 DWORD 和六十四字节字符串区；正文最多保留六十二字节，过长时写两个结尾零，其他情况只写一个。更新保留结尾零以后的原有字节，新建记录的未定义尾部由库清零；截断按字节执行。

335 先查精确键。没有精确键时，在该历史项全部字符串记录中选取严格小于查询位置的最大位置，再查该位置的字符串编号；没有更早位置时使用零。此选择跨全部编号，因此较早位置中存在该编号仍可能查询失败。历史项尚无字符串记录时保持目标字节；已有记录但未找到键时写一个零。恢复后的字符串区若缺少终止零，查询返回诊断。

336／337 直接读取 VM 原始文本，不作 KCS 格式展开；地址零有效。`$str` 后的整数沿用有符号十进制、十六进制及 DWORD 回绕规则。336 跳过全局表中不存在的编号；337 移除可解析但未命中的引用，保留其他字节。分号保留，替换结果不递归扫描。零上下文只需首个参数，333～335 返回零并保留目标，336／337 保留操作栈。

72 组序列共 1,464 次原入口调用在两种执行预算下匹配状态、返回值、完整 VM 两区和存档定义字段；覆盖空表、末项选择、全局位置回退、短串更新、长串截断、空值、CP932 字节、标记语法与普通／外部地址。常规回归另外固定导入记录更新后的尾部保留及再导出。

## 源文本与运行时记录

官方 `mc.exe` 将剧情源文本编译为 CST。源文件中的 `#label` 决定产生的场景文件；一个源文件可以产生多个 CST。源宏和包含文件属于编译阶段。

源文本的主要规则为：

- 官方命令按手册使用半角小写字母；扩展名称保留原大小写。官方手册规定资源名和场景标签名不区分大小写。
- 姓名和正文由行首及半角空白区分。源文本中的空行会影响消息块划分，不能先全局删除。
- 支持 `//` 行注释，不支持 `/* ... */` 块注释。
- `#include`、`%` 宏定义和宏参数按源编译语法处理。已编译 CST 中的宏调用已展开。

从归档读取 CST 时，直接使用其类型化记录。不要根据缩进重新推断姓名、正文和命令。

## 二进制结构

所有整数为小端。文件头共 16 字节。

|偏移|类型|字段|
|:--|:--|:--|
|`0x00`|8 字节|签名 `CatScene`|
|`0x08`|u32|压缩长度 C|
|`0x0C`|u32|解压长度 U|
|`0x10`|字节序列|脚本主体|

`C>0` 时主体为 Zlib 数据；公开格式也定义了 `C=0` 时直接存储 U 字节的写法。本次 604 份 CST 均为压缩形式。

解压主体的前 16 字节为：

|偏移|类型|字段|
|:--|:--|:--|
|`0x00`|u32|主体长度，不含这 16 字节|
|`0x04`|u32|输入区间数 N|
|`0x08`|u32|记录偏移表相对位置 O|
|`0x0C`|u32|字符串区相对位置 S|

O 和 S 相对于主体头结束处。记录数为 `(S-O)/4`；每个记录偏移相对于字符串区起点。

```text
主体头
输入区间表：N × 8 字节
记录偏移表：每项 u32
字符串区：01 type payload 00
```

基线核实到输入区间的每项为 `(区间记录数, 起始记录索引)`，连续区间覆盖整个记录序列。除最后区间外，各区间末尾为输入等待记录；最后区间包含末次输入后的命令。本次所有文件均满足 `N = 输入等待记录数 + 1`，最后区间均非空。

这些是记录索引和记录数量，不是字节地址，也不是本地化消息表的条目数。

## 记录类型

|值|含义|处理边界|
|:--|:--|:--|
|`0x02`|Input|当前消息之后等待输入|
|`0x03`|Page|翻页并等待输入；本次样本未使用|
|`0x20`|Message|向消息系统提供正文与内嵌标记|
|`0x21`|Name|设置发言人|
|`0x30`|Command|解析命令文本|
|`0xF0`|ScriptName|源文件调试信息；本次样本未使用|
|`0xF1`|LineNumber|源行号调试信息；本次样本未使用|

正文和姓名在基础 CST 中为 CP932。CSTL 替换文本具有独立的 UTF-8 编码；配置中的场景编码值不能用于重新解释所有原始 CST 字节。

## 命令语法

```ebnf
command       = assignment
              | "if", "(", expression, ")", singleCommand
              | imageCommand
              | namedCommand
              | choiceRow ;
imageCommand  = imageType, [ selector, [ argumentTail ] ] ;
imageType     = "bg" | "cg" | "fg" | "eg" | "fw" | "pl" ;
selector      = integer | "[", integer, "-", integer, "]"
              | "[", integer, { ",", integer }, "]" ;
namedCommand  = commandName, argumentTail ;
choiceRow     = integer, target, choiceText ;
```

这里省略了用于区分参数的空白符。`argumentTail` 的结构由具体命令决定；选择器的区间和枚举支持范围也由命令决定。

银行号读取完整整数，不能限制为一位数字。区间和枚举是两种写法，手册不接受 `[0,2-4]` 这样的混合形式。只有选择项收集上下文中的数字开头记录才按 `choiceRow` 解释。

部分图像命令省略银行或资源参数时具有初始化／清理用途，按具体类型的签名处理。

### 条件

`if (expr) command` 只控制同一记录中的一个命令。条件非零时执行，否则继续下一记录。CST 没有由该语法派生的 `else/endif` 块。

手册示例包含右括号后直接连接命令的写法；本次 38,739 条条件均使用空白分隔。条件边界应由匹配的右括号确定。

```text
#8=3
if (#8>=2) next demo_route
next demo_fallback
```

### 场景与调用

|写法|手册规则|
|:--|:--|
|`next target`|加载目标场景并转移执行|
|`call target`|保存返回位置并调用目标场景；支持嵌套|
|`return`|提前返回调用者|
|被调用场景到达末尾|返回调用者，无需显式 `next`|

样本有大量 `call` 和 `next`，没有固定的 `start.cst`。场景初始入口应来自启动／宿主流程。

### 选择项

```text
fselect demo_choices
1 demo_left Left
2 demo_right Right
```

`fselect [界面脚本]` 后面跟随 ID、目标和显示文本。手册规定 ID 可以重复，因此选择列表需要保留顺序和每个条目，不能按 ID 去重。

原收集函数逐条读取后续 Command，并处理可选的 `if`。条件为假时跳过该记录；条件为真时提取 ID、目标和文本，向结果列表追加一项。遇到其他记录类型或数据末尾时结束；若当前 Command 缺少必需字段，则退回该记录，交回外层解释流程。保留下来的选项使用从零开始的连续本地化序号，详见 [CSTL](cstl.md)。选项窗口的调用、交互和返回调度仍待核实。

### 字符串

|写法|含义|
|:--|:--|
|`str n value`|写入字符串变量|
|`strn n value`|将数值转成十进制字符串|
|`$strN`|在正文或参数中引用字符串变量|
|`strcmp dst a b [caseSensitive]`|比较后写入数值变量；相同为 0|

字符串引用可嵌入资源名，不限于独立参数。原读取函数在读取记录时展开 `$str`；Command 随后将剩余 `$` 替换为 `0x`，Name 和 Message 走文本分支，见[表达式](expressions.md)。手册对 `strn` 的紧邻正文引用还有延迟限制，其与消息缓存的关系仍待核实。

## 等待与调度

手册的时间单位为 **1 帧 = 1/60 秒**。

|写法|手册规则|
|:--|:--|
|`wait`|等待之前的相关运动、效果完成|
|`wait frames`|等待给定时间；frames 是数值表达式|
|`wait key`|等待输入|
|`wait pcm [bank]`|等待语音结束|
|`wait se [bank]`|等待音效结束|
|`wait pt [bank]`|等待粒子结束|
|`wait tag name [fallbackFrames]`|等待当前音频中的标签，未找到时按备用时长等待|

无参等待不自动等待 BGM 或 SE 的完整播放。循环动作、被停止的动作、快进、音频尚未加载及并发动作的等待状态需要有明确结束条件。

基线还使用 `wait mpl ...`，其等待对象及完成条件尚待确认。样本也使用算术表达式作为时长，不能仅接受连续十进制数字。

手册将部分画面命令的提交边界放在消息、输入或等待处，音频加载则可以立即开始播放。`rdraw` 表示画面重绘策略，其默认时间由 `drawdef` 设置；不能统一简化为“每张图各自淡入”或“所有命令都立即提交”。

## 文本标记

正文的语法与命令语法分开解析，至少保留文本片段及其控制标记。

|写法|手册规则|
|:--|:--|
|`\n`|正文内换行；源文本中独立成行还有输入等待含义|
|`\@`|使后续消息／命令延续到之后的等待或输入边界|
|`[word/ruby]`|注音|
|`[word]`|禁止词内断行|
|`\\`、`\[`|显示字面反斜杠、左方括号|
|`\c0x...;`、`\cr0x...;`、`\cs0x...;`|正文、注音、阴影颜色，顺序为 AABBGGRR|
|`\f...`、`\fr...`|字体及注音尺寸|
|`\pl`、`\pc`、`\pr`|对齐方式|
|`\w...;`、`\wf...;`|字符显示等待或按帧等待|

标记的大小写不敏感。字体和颜色标记有默认恢复写法和消息页范围，具体绘制由消息系统处理。已接入的基线解析与具体恢复消费规则见 [消息标记接口](message.md)。将方括号直接删除、把 `\n` 换成空格或每遇 Message 就覆盖全部正文，都会丢失语义。
