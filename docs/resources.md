# 资源名称与类别

本文固定使用 Windows CatSystem2 2.6.1.90 的名称补全规则。脚本中的资源名先按配置类别解析为虚拟名称，再由资源宿主查找归档或散装文件。

## 配置与接口

启动配置的 `INT/intNN` 条目使用 `name`、`int`、`ext`、`dir` 描述类别标识、归档路径、缺省扩展名和散装目录。`resource::Category` 接收 `int` 对应的虚拟名前缀及 `ext` 对应的扩展名，均保留原始字节；`resolve(input)` 返回补全后的虚拟名称。

```rust
use katze_system2::resource::Category;

let category = Category {
    prefix: b"mot".to_vec(),
    extension: b"kcs".to_vec(),
};
assert_eq!(category.resolve(b"sample").unwrap(), b"mot/sample.kcs");
```

`ArchiveConfig::from_xml` 读取已解码为 UTF-8 的启动 XML，`find(name)` 返回类别槽位，`resolve(category, name)` 完成类别查找及名称补全。`resolve_slot(slot, name)` 直接按 INT 槽位补全，声音装载等只携带槽位的入口使用它；带目录的名称与按名称查询一样直接返回，槽位越界诊断。资源宿主提供已装载的归档、列表和补丁顺序，`ResourceRouter` 按下述规则查找。`Category` 只处理名称；不检查文件是否存在，不访问文件系统，也不规范化目录或大小写。

## 已确认的补全规则

输入、前缀和扩展名都在第一个零字节处结束。

1. 按基线双字节范围扫描名称并记下最后一个目录分隔符。分隔符为 `/` 或 `\`。最后一个分隔符的下标大于零时，直接返回输入。
2. 其余名称检查最后一个路径分量中是否包含点。没有点时，依次追加一个点和配置扩展名；空扩展名仍追加点。
3. 前缀非空时，返回 `prefix/name`；空前缀直接返回名称。原有末尾斜杠、开头斜杠及点均保留。

|输入|前缀 `mot`、扩展名 `kcs` 时的结果|
|:--|:--|
|`sample`|`mot/sample.kcs`|
|`sample.KCS`|`mot/sample.KCS`|
|`sample.`|`mot/sample.`|
|`folder/sample`|`folder/sample`|
|`/sample`|`mot//sample.kcs`|
|空名称|`mot/.kcs`|

目录扫描的双字节首字节范围为 `0x81～0x9F` 或 `0xE0～0xEF`，尾字节为 `0x40～0x7E` 或 `0x80～0xFC`。合法双字节中的 `0x5C` 不作为目录分隔符。随后的扩展名检查按原始字节反向查找，使用另一套路径分量判断；包含此类字节的名称可能继续追加扩展名。两步按各自规则执行。

合成原入口对照覆盖 384 组前缀、扩展名、目录、点、空输入和双字节边界，结果全部一致。

## 启动配置

`ArchiveConfig` 提供 128 个 `entries` 和 64 项 `required`。每个 `ArchiveEntry` 包含类别标识 `name`、名称补全参数 `category` 以及散装目录 `directory`。默认条目的四个字符串均为空，必需归档列表默认为 −1。

```rust
use katze_system2::resource::ArchiveConfig;

let config = ArchiveConfig::from_xml(r#"<?xml version="1.0" encoding="UTF-8"?>
<document><INT><int00>
  <name>mot</name><int>motion.int</int><ext>kcs</ext><dir>loose</dir>
</int00><need00>0</need00></INT></document>"#)?;
assert_eq!(config.find(b"MOT"), Some(0));
assert_eq!(config.resolve(b"mot", b"sample")?, b"motion.int/sample.kcs");
# Ok::<(), katze_system2::Error>(())
```

`name` 是类别查找标识，`int` 是加入虚拟名称的归档前缀，两者具有不同用途；`dir` 不参与虚拟名称补全。实际配置的 50 个条目中，两字段全部不同，`int` 全部为带归档扩展名的路径。虚拟名称的归档部分和归档内部条目名需由资源宿主分开处理。

XML 路径及字段名称区分大小写，类别标识查询忽略 ASCII 大小写，按槽位顺序选择首项。空标识会匹配第一个空槽位。`int00`～`int127` 采用十进制编号，少于两位时补零；`int0` 和超出容量的编号不参与读取。重复 `INT`、重复槽位及字段按路径合并，后出现的同一字段覆盖旧值，未重写的其他字段保留。

`need00`～`need63` 存放必需归档的槽位编号，各项保留原始 i32；它们不是各个类别的布尔开关。缺失项为 −1，已出现的空文本或无数字前缀为零。数值支持正负号、十进制和 `0x` 十六进制，32 位回绕，忽略数字后的普通后缀；十进制数字后紧接点时返回零。前导空白不会跳过。

基线读取器要求 XML 声明位于首字节，版本为 `1.0`，编码为 `UTF-8`；前置 BOM、空白、CDATA 和嵌套自闭合节点返回诊断。空字段使用成对标签。字符串不去除首尾空格，CRLF／LF 和 Tab 转为空格，单独 CR 保留；注释和子元素内容从字段的直接文本中排除。实体引用保留字面文本，例如 `a&amp;b` 读取为同样的七个字节，不展开成 `a&b`。非 ASCII 字段保留 UTF-8 字节。

库按原固定字段容量限制读取：`name` 和 `int` 各最多 31 字节，`ext` 最多 7 字节，`dir` 最多 259 字节，超长返回诊断。带目录的资源名在类别查找之前直接返回，因此此路径不要求类别存在；仅开头分隔符仍执行类别查找。

34 份合成 XML 的装载结果、13,501 个字段与查询，以及一份实际启动配置的全部 128 个槽位、64 项必需列表和类别查询，均已对照原入口。实际配置的 50 个类别和 24 个非负必需编号全部一致。超出原固定字段容量的合成输入由库返回诊断，避免原路径的缓冲区覆盖。

## 配置目录展开

`FolderPaths` 由宿主提供用户／公共应用数据目录、品牌、标题及当前 save／imglib 目录，均使用 UTF-16。`expand(source)` 按大小写识别 `%USERPROFILE%`、`%ProgramData%`、`%ALLUSERSPROFILE%`、`%brand%`、`%title%`、`%save%`、`%imglib%`。其中 `%USERPROFILE%` 指用户应用数据目录，另两个系统目录标记共用公共应用数据目录。

展开仅扫描一次，替换结果中的标记不再展开；未知、大小写不同及未闭合标记保留字面值。输入与上下文字段在首零结束，分隔符及 UTF-16 单元保持，输出至多 259 个单元，超限返回诊断。此接口只处理文本，目录定位与创建由平台负责。

## 脚本 XML 字段

`XmlDocument::parse(bytes)` 读取带上述声明的 UTF-8 XML，`text(path)` 返回可选字段字节，`integer(path, default)` 返回整数或缺失默认值。启动配置复用同一读取器。输入在首零结束；读取第一个完整根节点后忽略尾随内容，空根可用自闭合标签。

`float(path, default)` 在字段缺失时保留默认浮点值。存在的字段只接受数字或负号开头，不跳过空白或加号；连续整数部分后可接小数点，小数点后取首字节及其后的连续数字，`f`／`F` 结束数值。例如 `1e3` 得到 1，`1.e3` 得到 1000，`1.2e3` 得到 1.2。转换先经过 double 再转为 float，保留负零；截取文本必须少于 1024 字节。

`wide_text(path)` 返回可选 UTF-16 配置文字，存在的空字段返回空向量。它沿用宽字符 XML 入口的字符块转换规则：每个 UTF-8 字符仅保留首个 UTF-16 单元，因此补充平面字符只留下高代理单元；上限为 4095 个单元。字符串表文件的键和值采用完整 UTF-16 转换，不使用这一配置入口。

路径区分大小写，按正斜杠拆分并忽略空分段，每段至多 511 字节。根名为 `document` 时自动略过这一层，查询 `a/b`；其他根名需包含在路径中。空路径没有字段。冒号属于名称本身，命名空间声明和其他属性不作为可查询字段，点、反斜杠和 `@` 没有特殊意义。

重复路径合并，后出现节点的直接文本覆盖旧文本，未重写的子字段保留；字段直接文本按顺序拼接，排除注释及子元素正文。存在但为空或不含合法整数前缀的字段返回零，只有缺失字段采用默认值。文本与整数规则已用 61 份合成 XML 及一份启动配置、16,864 组查询对照原入口。

`XmlWriter::new()` 建立 `document` 根节点。`write(&["group", "field"], bytes)` 按名称分段写入，空路径选择根；名称和值均在首零截止。新节点放在同级首位，重写已有字段保留位置；有子节点时只输出子节点，自身保存的文本不参与输出。`write_integer(path, value)` 将原始 DWORD 按带符号十进制写出。`to_bytes()` 返回带 UTF-8 声明、两空格缩进和 CRLF 的字节，不附加结束零；宿主负责文件写入。名称和文本按字面输出，调用者需保证它们与基线读取器兼容。

`write_float(path, value)` 将 float 提升到 double 后以固定六位小数输出，保留负零；非有限值输出 `inf`、`-inf`、`nan` 或 `-nan(ind)`。重新读取时仍按上述配置规则转换。

`write_wide(path, units)` 逐个 UTF-16 单元转换，不合并代理对；每个代理单元输出 U+FFFD，`FFFF` 输出两个 `FF` 字节。首零截止，转换结果最多 4095 字节，超限返回诊断并保留旧字段。输出的字面实体、空成对标签和节点顺序与配置写出入口一致。

## 归档内部目录

`ArchiveDirectory::new(entries)` 接收已经解密的 `DirectoryEntry { name, offset, length }`，名称使用原始 CP932 字节。`entries()` 按输入顺序提供完整目录，重复名称仍保留在列表中；名称索引只保留首个匹配条目。`find` 查询 CP932 名称，`find_utf16` 对应原宽字符查询入口。返回条目提供原始名称及主体范围，不自行读取或解密数据。

`ArchiveDirectory::from_plain_kif(bytes)` 可读取完整的未加密 KIF：头部为 `KIF` 加零字节及 u32 条目数，随后每项为 64 字节 NUL 终止名称、u32 偏移和 u32 长度。目录及主体范围必须落在输入内，目录不得超过 64 MiB。首项名称忽略 ASCII 大小写等于 `__key__.dat` 时返回需要解密的诊断。加密目录和数据块使用下节的 `KifArchive` 读取。

索引和查询都执行基线的大写转换，但使用不同的字符步长。索引扫描 CP932 字节，跳过合法双字节后继续处理后继 ASCII。宽字符查询遇到高字节非零的 UTF-16 单元时跳过两个单元，这会连同后继字符一起跳过；其余单元只将 ASCII 小写字母转为大写。名称在首个 NUL 结束。斜杠、反斜杠、重复分隔符和点分量全部保持原样。

例如目录项 `あa.kcs` 的索引为 `あA.KCS`，查询 `あa.kcs` 会因紧随 `あ` 的小写 a 被跳过而未命中，查询 `あA.kcs` 则命中。两个连续日文字符会一起被跨过，随后 ASCII 再正常转换。该差异来自原查询路径，当前分支保留这一行为。

100 组合成查询覆盖大小写重名、目录分隔符、日文、半角片假名、空名称及未命中路径。24 个归档中去重名称表的 34,738 个名称另各执行两种查询，共 69,476 次，对照原目录索引全部一致；此批验证的归档主体使用合成占位数据。

实际 1,274 个运动子命令绑定共有 26 个目标。通过类别配置补全后，归档路径作为虚拟名前缀，去除该前缀及分隔符后查询对应归档内部目录，26 个全部命中。大小写敏感的直接比较只命中 25 个；剩余差异已确认来自大小写。跨归档选择和散装文件回退使用下节路由。

## KIF 加密读取

`KifArchive::parse(bytes, name_seed)` 借用完整归档输入，读取并解密目录，再建立内部名称索引。`verification_seed(code)` 接收已解密的校验码字节并在首个 NUL 终止，用于计算 name_seed；校验码从何处取得由启动资源宿主提供。未加密 KIF 忽略 name_seed。

`directory()` 返回目录，`is_encrypted()` 返回是否存在首项加密标记。`read(name)` 按 CP932 内部名称查询并返回可选明文，`read_entry(entry)` 按给定条目范围返回明文。查询沿用目录的大小写及字符步长规则。接口不打开文件，不选择归档；调用者可以从普通缓冲区或映射文件提供完整输入切片。单次条目读取上限为 64 MiB。

首项 `__key__.dat` 的长度字段用于旧版 MT 初始化，首个随机整数的小端四字节作为 Blowfish 密钥。后续目录项先给存储偏移加上原始目录下标，再把偏移／长度两项按小端双字块解密。名称使用 `name_seed + 原始目录下标` 对应的 MT 首值及字母表变换。索引排除加密标记，资源条目从目录中保留原有顺序。全部范围在解密之后检查。

数据按每个条目独立划分八字节块，使用小端双字 Blowfish 解密；末尾不足八字节的原始数据直接保留。零长度条目返回空向量。校验码只参与名称变换，数据块密钥由归档标记生成，当前格式没有附加完整性校验。

48 份合成归档的 1,536 个条目已与原装载／读取入口核对，覆盖六组校验码、八个归档种子和 0～31 字节正文，名称、偏移、长度与全部数据均一致。常规回归使用独立 Blowfish 实现生成的 322 字节固定合成归档，不依赖外部材料。

逐归档完整对照得到 35,264 个普通条目，另有 24 个加密标记。全部名称、偏移及长度均与独立解密器一致；全部 1,812 份脚本实例的解密字节及容器读取也通过。归档之间有 526 组内容相同的 CSTL 重名项，按名称去重后共 34,738 项、1,286 份脚本。资源宿主保留归档身份，不平铺成全局同名覆盖表。

## 虚拟名称装载路由

`ResourceRouter` 包含 256 个 `slots`、按顺序排列的 `groups` 和 `patches`。每个 `ResourceSlot` 保存注册前缀、散装目录、散装启用标记及可选的 `ArchiveMount`。挂载记录单独保存归档装载路径，两种路径可以不同。`ResourceGroup` 保存 `.lst` 前缀及按输入顺序排列的成员；每个 `ResourceMember` 保存可选槽位编号、独立散装目录和启用标记。未装载、失效的归档均以 `None` 提供；只有散装目录的成员仍参与混合模式。

这些结构接收宿主已准备的数据，不自行发现文件或解析 `.lst`。补丁发现、注册顺序、缓存及别名重写仍待接入。当前路由前缀限定 ASCII，忽略 ASCII 大小写；遇到非 ASCII 前缀比较返回诊断。基线实际注册前缀均满足此条件。散装目录和内部文件名可含非 ASCII，均保留 UTF-16；内部归档查询继续使用已经核实的目录索引规则。

`read(name, mode, file)` 接收 CP932 虚拟名称，`read_utf16` 接收宽字符名称。名称在首个 NUL 截止，按**第一个正斜杠**拆为前缀和内部名称；后续正斜杠保留在内部名称中，反斜杠不参与拆分。没有正斜杠时前缀为空，整个输入作为内部名称。输入及生成的散装路径最多 259 个 UTF-16 单元，超长返回诊断。

|模式|普通前缀的查找规则|
|:--|:--|
|`File`（1）|尝试原始完整名称，保留原始分隔符。|
|`Archive`（2）|按槽位顺序比较 `ArchiveMount.path`，在匹配归档内查找内部名称。|
|`LooseFirst`（3）|按槽位顺序比较注册前缀，每槽先尝试启用的散装目录，再尝试该归档。|
|`ArchiveFirst`（4）|按槽位顺序比较注册前缀，每槽先尝试该归档，再尝试启用的散装目录。|

每次尝试失败后继续后续匹配槽位；优先顺序按槽位逐项执行。例如第一个槽位归档命中时，`ArchiveFirst` 不再查看第二个槽位的散装文件。`LooseFirst` 在空前缀下遍历全部 256 个槽位，并强制尝试每个散装目录；其余模式不具有这个特例。

前缀最后一个路径分量的扩展名忽略大小写等于 `lst` 时，三个归档模式改为按分组及成员顺序查找。匹配的多个同名组均可继续回退，组之间保持注册顺序。每个成员独立按当前模式选择散装或归档；`Archive` 只查看成员的挂载归档。

散装路径使用反斜杠连接目录与内部名称。列表成员和普通前缀的 `ArchiveFirst` 即使目录为空也保留开头反斜杠；普通前缀的 `LooseFirst` 在目录为空时直接使用内部名称。末尾分隔符和点分量均不规范化。

所有模式都先按 `patches` 顺序仅用内部名称查找，首个命中补丁优先于直接文件和普通归档。补丁查找不受虚拟前缀限制。原引擎的缓存查询及别名重写位于这一步之前；当前接口要求宿主在需要时先完成这些操作。

启动示例会发现游戏目录中的 `updateNN.int`（两位十进制编号，文件名忽略 ASCII 大小写），按编号从大到小挂载。普通读取、宽字符读取和程序预载共用补丁优先规则，补丁新增的 KCS 也进入预载。未加密归档保留原始名称，加密归档继续使用工具的名称还原与精确反查。

`ResourceServices::script_encoding()` 提供 CST 和名称表的原始文字编码，默认 CP932，引用包装及共享缓存转发此设置。启动示例可通过 `KATZE_SCRIPT_ENCODING=gbk` 选择汉化资源编码；不设置时沿用默认。该设置只用于需要转为 Unicode 的剧情和姓名，不改变资源路径、FES 语法或 CSTL 的 UTF-8 文本。

文件回调接收 UTF-16 路径，返回 `Ok(None)` 表示打开失败并继续后续尝试，`Ok(Some(bytes))` 表示成功，空数据也算命中；`Err` 中止读取并传播诊断。返回的 `ResourceData` 同时提供正文和 `ResourceSource`，区分文件路径、普通归档槽位及补丁列表下标。归档正文由 `KifArchive` 按需解密。

运行时 `kcs::ResourceServices::read_utf16` 提供宽字符名称读取；默认转换为 CP932 后调用字节入口，无法表示的名称或无效 UTF-16 返回诊断。需要完整宽字符名称的宿主应覆盖该方法，`CachedResources` 和可变引用包装会转发宿主实现。启动示例的宽字符入口直接使用宿主文件名，并保留直接文件读取与资源回退的区别。

`ResourceServices::open(name, mode)` 返回可选的 `io::SharedSource`，名称及模式沿用 `read`，缺失与读取失败分别返回 `Ok(None)` 和诊断。默认实现持有 `read` 返回的字节；宿主可覆盖以提供独立文件或其他存储源，可变引用包装转发该实现。`CachedResources` 优先使用已预读的字节，未命中时调用内部服务的 `open`；已打开的源在缓存淘汰后继续有效。声音装载通过该入口取得源，解码仍同步执行。

`io::ReadSource: Send + Sync` 提供 `len`、`is_empty`、`read_at(offset, output)` 及 `read_exact_at`。偏移不改变其他读取者的位置，允许短读，到达末尾返回零；完整读取遇到提前结束返回诊断，并保留已写入的前缀。源实现负责保证并发读取安全，读取期间内容须保持一致。`[u8]`、`Vec<u8>` 可直接作为源，`SharedSource` 为共享源句柄；`FileSource::open(path)` 提供文件源，调用方须避免读取期间外部修改文件。

`io::SourceReader::new(&source)` 将源适配为标准 `Read`／`Seek`，每个适配器保存独立游标，允许定位到末尾之后；无效负偏移或位置溢出返回错误并保留原位置。适配器借用的源须在读取期间存活；解码器无需持有资源服务或宿主路径。

`SourceReader::from_shared(source)` 持有共享来源，游标可随消费者移交其他线程；释放原共享句柄不影响读取。`audio::VorbisDecoder::from_shared(source)` 同样持有来源和逐包解码状态，可在预取线程继续读取。

4,608 组合成原入口对照覆盖四种模式、重复挂载路径、注册路径差异、空与失效槽位、列表顺序、散装启用标记、空目录、空前缀、未命中、分隔符及补丁优先级，返回来源和全部散装尝试顺序均一致。全部 1,812 份实际脚本经三个归档模式读取，共 5,436 次，来源和字节全部正确。合成运动集成测试已串联类别补全、归档读取、KCS 容器解析和运动队列执行。


## 三整数分组表

普通 594 读取按行保存的分组与条目名称，596 查询组名，597 先由条目名称找到组，再读取该组的三个整数。数据按原始字节解析，首个零结束；CR、LF、CRLF 均可分行。先删除 `//` 行尾注释和可跨行的 `/* … */`，再删除每行全部半角空格、制表符及空行。引号不保护注释标记；分号是普通名称字符。

例如合成文本：

```text
#normal(100,90,80)
item_a
item_b
#other(1,2,3)
item_c
```

`#normal` 是组名，包含井号；`item_a`、`item_b` 是该组的条目名称。分组头从行中第一个井号开始，取随后第一个左括号之前的内容作组名；此前内容和右括号之后的内容不参与登记。三个整数分别在两个逗号、一个右括号处完成解析，保留原始 DWORD，不压值。没有井号或没有左括号的非空行按条目名称处理。

初始当前组为 `__UNKNOWN__`，三个整数均为一百。分组头本身只更新当前状态，遇到后续条目才登记该组和条目。重复组保留首次登记的三值，重复条目保留首次绑定；新组即使遇到重复条目也会独立登记。因此只有分组头而没有条目的组查询不到。

不完整的分组头仍更新组名；每遇到对应分隔符才更新一个整数，未完成的分量保留此前值。例如已有 `[11,22,33]` 时，`#next(9,` 把当前状态改为组 `#next`、值 `[9,22,33]`，后续条目使用该状态。该继承顺序与重复组的首次值保留分别处理。

登记和查询忽略 ASCII 大小写，保留普通 KCS 字符规则识别的双字节字符；名称不转为 Unicode。查询不会额外删除名称中的空格。组名及文件条目最多 511 字节，直接组查询最多 511 字节，条目查询最多 1023 字节；超限返回诊断。

594 使用格式展开后的 C 字符串直接访问资源服务，模式为 `LooseFirst`，不进行类别补全；打开失败返回零，成功读取的空数据创建有效空表。服务错误或安全长度检查失败返回诊断，既有对象保持。595 仅释放对应分组表；类型错误和已释放的非零句柄返回诊断。三种资源类型使用独立存储，并共享宿主的句柄分配器。

596／597 的参数为 `[句柄, 名称格式地址, 输出一, 输出二, 输出三]`。零句柄跳过其余参数，可只提供零 DWORD；未找到名称时不写输出。找到后依序写入三个 DWORD，支持普通区、外部区、零地址、同址及重叠输出；容量不足返回诊断，保留此前完成的写入。返回状态一、返回值表示是否找到，595 则以状态二继续。
