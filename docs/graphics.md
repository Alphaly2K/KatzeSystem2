# 图像与像素接口

适用基线为 Windows CatSystem2 **2.6.1.90**。图形模块复用现有资源读取及 HG-3 元数据，开发顺序见 [GOAL.md](../GOAL.md)，子系统边界见 [设计文档](subsystems.md)。

## HG-3 帧解码

`hg3::decode_frame(bytes, id)` 接受完整 HG-3 文件及带原始位模式的 i32 帧 ID，返回 `Result<Option<DecodedFrame>>`。缺失 ID 返回 `None`，结构、压缩流或编码错误返回诊断。按文件顺序选择第一个匹配 ID，与元数据查询一致。

`DecodedFrame` 保存 `id`、完整 `StandardInfo` 和 `pixels`。像素按从上到下、每行从左到右的 BGRA8 紧密排列，行跨度为裁剪宽度乘四；Alpha 保持独立通道，不预乘、不因 Alpha 为零而清除颜色。

像素只包含裁剪区域。`info.offset`、`canvas_size` 和 `base` 继续交给绘制宿主组合，解码时不扩展到完整画布，也不将偏移或基点加到像素位置。

当前接受 HG-3 0x300、低有符号 16 位位深为 32、覆盖完整裁剪高度的 `img0000` 原生编码。尺寸必须非零，像素总长度最多 64 MiB。其他位深、切片、JPEG 和 WebP 返回未支持诊断；`Metadata` 仍可单独读取其支持的标准字段。

原生数据通过独立 Zlib 数据／命令流还原，命令按低位先读、正整数 Gamma 长度执行交替复制／清零游程。游程输出长度必须与像素尺寸相符，越界和截断均返回诊断。随后恢复四组位平面、有符号差值及行内／行间预测，保持字节回绕。

## 对照与使用约束

72 份合成图像的 34,384 个像素，以及 32 份实际图像的 33 次帧请求，均按原解码对象的逻辑行顺序逐字节核对；几何字段同时核对。原对象内部倒序存行，公开解码接口使用从上到下的顺序。

常规回归使用固定合成游程数据，覆盖位重排、正负差值、行方向、独立 Alpha、负位模式 ID、缺失帧和完整元数据；另检查尺寸溢出、损坏压缩流、截断／越界游程及未支持编码。原引擎和实际图像不参与默认测试。

资源名称补全和文件读取由资源宿主完成，解码器只访问传入字节，不访问归档、文件系统、窗口或 GPU。
