# 图像与像素接口

适用基线为 Windows CatSystem2 **2.6.1.90**。图形模块复用现有资源读取及 HG-3 元数据，开发顺序见 [GOAL.md](../GOAL.md)，子系统边界见 [设计文档](subsystems.md)。

## HG-3 帧解码

`hg3::decode_frame(bytes, id)` 接受完整 HG-3 文件及带原始位模式的 i32 帧 ID，返回 `Result<Option<DecodedFrame>>`。缺失 ID 返回 `None`，结构、压缩流或编码错误返回诊断。按文件顺序选择第一个匹配 ID，与元数据查询一致。

`DecodedFrame` 保存 `id`、完整 `StandardInfo` 和 `pixels`。像素按从上到下、每行从左到右的 BGRA8 紧密排列，行跨度为裁剪宽度乘四；Alpha 保持独立通道，不预乘、不因 Alpha 为零而清除颜色。

像素只包含裁剪区域。`info.offset`、`canvas_size` 和 `base` 继续交给绘制宿主组合，解码时不扩展到完整画布，也不将偏移或基点加到像素位置。

当前接受 HG-3 0x300、低有符号 16 位位深为 32、覆盖完整裁剪高度的 `img0000` 原生编码。尺寸必须非零，像素总长度最多 64 MiB。其他位深、切片、JPEG 和 WebP 返回未支持诊断；`Metadata` 仍可单独读取其支持的标准字段。

原生数据通过独立 Zlib 数据／命令流还原，命令按低位先读、正整数 Gamma 长度执行交替复制／清零游程。游程输出长度必须与像素尺寸相符，越界和截断均返回诊断。随后恢复四组位平面、有符号差值及行内／行间预测，保持字节回绕。

## 对照与使用约束

72 份合成图像的 34,384 个像素，以及 32 份实际图像的 33 次帧请求，均按原解码对象的逻辑行顺序逐字节核对；几何字段同时核对。原对象内部倒序存行，公开解码接口使用从上到下的顺序。

常规回归使用固定合成游程数据，覆盖位重排、正负差值、行方向、独立 Alpha、负位模式 ID、缺失帧和完整元数据；另检查尺寸溢出、损坏压缩流、截断／越界游程及未支持编码。原引擎和实际图像不参与默认测试。

资源名称补全和文件读取由资源宿主完成，解码器只访问传入字节，不访问归档、文件系统、窗口或 GPU。

## 基础渲染面

`graphics::Surface::new([width, height])` 创建零初始化的 BGRA8 像素缓冲区。`from_bgra(size, pixels)` 接收已有像素的所有权，可使用解码帧的像素；长度必须恰好为宽乘高乘四。几何元数据继续由图像对象保存。

渲染面从上到下存行，左上角为 `(0, 0)`，行跨度为宽乘四。`size()`、`stride()`、`bounds()` 提供布局，`pixels()`／`pixels_mut()` 提供固定长度的像素视图，`pixel(x, y)` 返回原始 ARGB DWORD，越界返回 `None`。任一维为零时允许空渲染面；尺寸必须可由正 i32 坐标表示，总像素长度最多 64 MiB。

`clear(argb)` 覆盖整个缓冲区。`fill_rect(rect, argb)` 与渲染面边界相交后覆盖区域，返回是否存在非空目标。两者将 ARGB DWORD 按小端写为 BGRA 字节，保留全部位模式，包括 Alpha 为零时的颜色。

`fill_rect_from_bottom(rect, argb)` 接收原图像对象从底部起算的 Y 坐标，先按原尺寸裁剪，再换算为顶端起始的渲染面行。这是普通 117 非零图像分支所需的坐标适配；该分支覆盖原始 ARGB，始终以状态 2 继续，保留返回槽。2,640 组完整 native 对照的状态、返回槽和带保护区的缓冲区全部一致。

`copy_from(source, rect, at)` 将源矩形映射到目标左上位置 `at`，同时裁剪源和目标边界，并保持请求的相对位置。它直接复制全部 BGRA 位模式，返回是否复制了非空区域；源和目标必须是不同渲染面。

`blend_from(source, rect, at, opacity)` 提供基线普通 32 位 Alpha 绘制，透明度为 0～255。源和目标矩形先分别与各自边界相交，再取两者共同宽高；左上裁剪不会让另一端同步平移。`rect` 的宽高按 i32 回绕端点差生成目标矩形。返回是否存在非空绘制区域，源和目标必须是不同渲染面。

普通混合保持引擎的整数舍入：有效源 Alpha 为 `opacity × (source_alpha + 1) >> 8`；半透明目标使用独立 Alpha 权重及整数倒数，低 Alpha 下可能得到黑色，两个半透明白色像素也可能得到略低于白色的结果。全零目标可保留有效 Alpha 为零的源 RGB；绘制区域左右各一格的全零邻接像素同样接收边缘源 RGB，Alpha 继续为零。透明度为零时仍执行这些颜色写入，已有非零 RGB 或 Alpha 的透明像素保持原值。

`Rect { left, top, right, bottom }` 包含左上边，不包含右下边。`Rect::from_xywh(x, y, width, height)` 用 i32 回绕加法生成端点；反向边界不交换，交集为空时跳过。`intersect(other)` 返回可选的非空交集。

2,640 组原像素填充入口对照覆盖四种尺寸、110 组矩形和六种颜色，返回值及带保护区的完整缓冲区全部一致。对照使用相同的缓冲区行序；原图像对象的倒序存行由其对象适配处理。普通 117 的两条路径已接入运行时，窗口呈现继续开发。

普通混合另外核对所有 256 × 256 种源／目标 Alpha、三种颜色分布、六种全局透明度及两种 CPU 路径，共 2,359,296 个像素；1,296 组矩形对照覆盖两端裁剪、空矩形、透明边缘和完整保护区，全部一致。常规回归只保留固定合成像素及裁剪案例，不依赖外部引擎或图像资源。缩放、翻转和特殊混合继续单独接入。

## 图像对象与名称

`graphics::Image::from_frame(frame)` 将一个 `DecodedFrame` 转为图像对象，保留帧 ID 和全部元数据。`id()`、`info()` 和 `surface()` 提供查询，`pixels_mut()` 允许原位修改固定长度的像素；`fill_rect_from_bottom` 提供普通 117 的填充坐标。像素尺寸和长度须符合渲染面约束，位深的低有符号 16 位须为 32。

`Image::new(size)` 创建普通 112 使用的 BGRA8 空白图像，全部像素清零；帧 ID、偏移、画布尺寸、基点和保留字段均为零。画布尺寸保留零值，宽高只写入像素尺寸。允许任一维为零，尺寸和存储上限沿用 `Surface`。

`graphics::ImageReference::parse` 专用于普通 111。它以首个冒号定位帧号，从名称末尾逐字节查找最后一个扩展名，先移除扩展名、读取帧号、在原冒号处截断，再替换扩展名。目录分隔符之后的句点才参与扩展名识别；这些步骤按原字节位置执行。十进制数值前缀若紧接句点，帧号为零；十六进制前缀保留整数。无冒号时原样保留名称并选择帧零。名称以首个零结束，长度须小于 260 字节。

|输入|资源名称|帧号|
|:--|:--|--:|
|`a:3.hg3`|`a.hg3`|3|
|`a:3`|`a.`|3|
|`a.hg3:4`|`a.hg3:4`|4|
|`a.b.c:3`|`a.c:3`|3|
|`a:7.gz.hg3`|`a.hg3`|0|
|`a:-0x10.gz.hg3`|`a.hg3`|−16|

这一名称规则与 FES POS2／SIZE2 的 `fes::ImageReference` 分别保留；两者使用不同的原入口。

## 普通 111 的装载与合成

`Images::load(owner, names, services)` 接收已经完成 KCS 格式展开的名称列表，按 ASCII 空格拆分并忽略空段；制表符和换行留在名称中，引号没有分组作用。每段解析后经 `ResourceServices::resolve(b"image", name)` 补全，再以 `LooseFirst` 读取完整资源。缺失文件、空文件及缺失帧跳过；结构损坏、未支持编码和资源服务错误返回诊断。

第一个成功解码对象成为目标，后续对象依序通过 `Image::composite` 合成，处理后释放。首图的裁剪尺寸、偏移、画布、基点和帧 ID 始终保留。全部缺失时返回零；成功时分配非零递增句柄。`get`／`get_mut` 查询该对象，失效句柄返回诊断；`release_owner(owner)` 释放该任务持有的全部图像，句柄不复用。每个图像的像素最多 64 MiB，存活图像最多一百万个。

合成保留基线的特殊规则：全局透明度为零，使用普通 32 位混合，因此只向全零目标写入透明 RGB，包括左右邻接像素。目标可见性先由“源偏移加目标尺寸”与目标全局矩形求交，源使用自身完整局部区域；目标起点换算为裁剪后的局部位置，两端独立裁剪，再按底端起始的内存坐标转换至公开像素行。负偏移不会同步移动源起点。这一操作不扩展首图画布。

`Runtime::set_resources(services)` 配置拥有的同步资源服务，普通 111 随后装载并以状态 1 压入句柄；`Runtime::images()` 可读取结果。普通 117 接受该句柄及 x／y／width／height／ARGB，以状态 2 填充并保留操作栈上的原值。任务实际释放时回收其图像；仅设置删除标记时图像继续存活。原始数据 365／366 的句柄属于另一接口，不能传给 117。

额外图形持有者、资源管理器缓存及特殊混合仍待接入；目前每次成功装载独立持有解码图像。

301 组名称／帧号、400 组完整 native 合成调用（其中 107 组进入绘制），以及 432 组保留对象创建、HG-3 解码、合成和释放的完整装载调用全部一致。后者核对 206,304 个像素、几何字段、资源请求和持有列表。常规四项合成回归覆盖名称重组、几何与行方向、缺失跳过、句柄寿命，以及真实 KCS 的装载／填充与两种预算续跑。

## 空白图像与显式释放

`Images::create(owner, size)` 无需资源服务，创建空白图像并分配与 `load` 同一序列的句柄。普通 112 接受 width、height 两项，以状态 1 返回该句柄；零尺寸同样创建非零句柄。超过库的尺寸／容量上限时返回诊断。

`Images::release(handle)` 对应普通 114，零句柄跳过，非零失效句柄返回诊断。释放后从所属任务的图像存储移除，任务随后销毁时不会重复释放；其他图像继续存活，后续句柄不复用。114 接受一项，以状态 2 继续且保留操作栈原值。当前图像尚无额外共享使用者，缓存与引用计数接入后继续扩展其持有规则。

20 组完整创建／释放对照覆盖宽高分别为零和不同非零组合，全部几何、初始像素、状态、返回槽及持有列表一致。常规合成 KCS 回归串联 112 创建、117 填充、115 图像混合、114 释放及任务回收，覆盖零尺寸和两种预算；释放、空源与失效句柄检查复用现有生命周期回归。

## 普通 115 的图像绘制

参数为 `target, dx, dy, requested_dw, requested_dh, source, sx, sy, sw, sh`，以状态 2 继续并保留操作栈原值。源句柄为零时直接跳过，此时只需前六项，目标句柄不被查询。非零源需要完整十项；两个请求目标尺寸保留在调用接口中，像素操作不产生缩放。

目标为非零图像句柄时，`Image::blend_from(source, source_rect, at)` 使用透明度 255 的普通 Alpha 混合，源和目标均从底部起算 Y。目标起点为 `at + source.info().offset`，目标自身偏移与两端基点不参与定位。源矩形直接使用局部像素坐标；源、目标独立裁剪，实际宽高取共同可用尺寸，裁剪一端不会同步移动另一端。透明 RGB 及左右一格延展沿用普通混合规则。

`Image::blend_within(source_rect, at)` 处理同图重叠：按底端起始的行顺序、每行从左向右即时读写，后续像素会读取先前写入的结果。右侧颜色延展在该行混合后重新读取源末像素。`Images::blend(target, at, source, source_rect)` 按句柄选择两种混合路径，无效非零句柄返回诊断；失败不移除仍存活的源图像。

目标为零时调用当前绘图上下文的 `copy_image(source, rect, at)`，直接复制全部 BGRA，保留源 Alpha 和透明 RGB。该分支的源矩形使用全局图像坐标，先与 `[offset, offset + size]` 相交，再减去 offset 得到局部区域。目标起点仍为 `at + offset`，源裁剪不平移它；目标宽高由裁剪后的源区域决定。源按底端起始顺序读取，目标按顶端起始顺序写入，因此公开像素中的源行被反转。该路径没有 Alpha 混合或左右颜色延展，写入后独立于源句柄的生命周期。

2,692 组完整 native 调用包括当前目标 817 组、独立图像和同图重叠各 937 组及空源跳过一组。全部目标／源像素、保护区、状态、返回槽和面块更新标记一致；保护页另确认空源只需六项。四项新增合成回归固定两种坐标与裁剪、同图反馈、BGRA 覆盖及运行时分派／预算续跑，不依赖外部数据。

## 绘图变换

`graphics::Transform` 保存基点、平移、缩放、弧度旋转及可选显式矩阵。默认基点为 `[0, 0, 5000]`，平移和旋转为零，缩放为一，矩阵为单位矩阵，dirty 为 false。属性由同名查询方法读取，`set_base_point`、`set_position`、`set_scale`、`set_rotation` 和 `set_matrix` 更新状态；`clear_dirty` 消费变更标记。

向量属性按浮点相等比较整组：全组相等时保留原值的位模式，任一分量不同才整组替换，因此正负零不会单独触发更新，NaN 会触发更新。显式矩阵按 16 个 DWORD 位模式比较，重复设置同一 NaN payload 不触发更新。`set_rotation` 即使角度相等，也退出显式矩阵模式；`set_scale` 保留该模式。

`matrix()` 为 `Identity × Scale × RotateX × RotateY × RotateZ`，显式矩阵模式则为 `Identity × Scale × matrix_override`。起始单位矩阵相乘保留非有限值的传播和求和顺序。旋转沿用原 x87 三角约化：有限大角度使用 66 位 π，NaN 保留符号和 payload 并置 quiet 位，无穷与超出 FSINCOS 范围的输入保留原异常结果。

`transform_point([x, y, z])` 只减去基点 X／Y，保留输入 Z，以 W=1 乘本对象矩阵，再加四维平移 `[px, py, pz, 1]`。普通仿射路径的结果 W 因而为 2。`transform_point_with_parent(point, parent)` 随后乘父级／绘图上下文矩阵，保留该 W，不执行 W 除法；父矩阵的平移同样受它影响。基点 Z 独立保存，不参与这一顶点变换。

12,981 组状态及 38,943 个完整变换后顶点已与原入口核对，有效属性、矩阵、dirty 和顶点结果一致。三项纯合成回归固定几何顺序、父级 W、正负零与矩阵模式、常规三轴旋转和非有限／大角度行为。该接口已用于二维对象属性和三角形查询；像素栅格化与帧提交继续实现。

## 绘图投影

`Projection` 接收绘图中心 `center`、摄像深度 `camera_depth`、最终平移 `translation` 和矩阵 `matrix`，以及已选择坐标组的 `coordinate_offset`／`coordinate_scale`／`coordinate_matrix`。默认中心、深度、偏移和平移为零，比例为一，矩阵为单位矩阵；实际配置由调用者提供，当前尚未从根对象自动装载。

`project_triangle(vertices, base_depth, origin, perspective)` 接收对象／父级变换后的三个顶点、对象基点 Z、已选择的投影原点及开关，返回 `ProjectedVertex { position, rhw, color }`。颜色原样保留，不自动裁剪，不隐式执行 W 除法。

关闭透视或顶点 Z 为正／负零时，先围绕中心应用坐标组缩放与矩阵，再加中心减坐标组偏移；此时 Z 独立改写为 `(65000 − (z + base_depth)) × f32(1/65000)`，坐标组矩阵不改变该 Z。最后乘最终矩阵，再加最终二维平移。矩阵乘法保留完整四维输入。

透视且顶点 Z 非零时，距离先按单精度计算为 `(65000 − base_depth) − camera_depth`。分母为 `z − distance`，两者浮点相等时改用一；二维比例为 `camera_depth / denominator`，负值钳为零。围绕 origin 处理后的四维顶点乘投影矩阵，其 Z 系数为 f32(1/65000)、W 系数为 `1 / denominator`。然后加 origin、减中心、应用坐标组缩放／矩阵，加中心减偏移，再乘最终矩阵及平移。RHW 参与后续矩阵的平移项，不能固定为一。

`Drawable::projected_triangle(index, parent, projection, origin, perspective)` 组合对象变换、父矩阵、颜色覆盖与上述投影；越界返回 None。它使用本对象的基点 Z，不用变换后顶点 Z 代替排序深度。1,266 组三角形的 75,960 字节完整投影顶点已与原入口一致，覆盖两条分支、两级矩阵、负比例、相等分母、正负零及非有限值。两项常规合成回归固定 RHW 平移、分支深度及图元组合；像素栅格化与帧提交继续接入。

## 绘图登记与三角形

`Drawable::rectangle(at, size, argb)` 创建两个原始三角形，保留负尺寸和退化边；端点按单精度求和。`bounds()` 返回独立原始边界，矩形为 `[x,y,0]` 至 `[x+width,y+height,0]`；通用列表和空图元的边界为零。

`Drawable::new(triangles)` 保存不带纹理的三角形列表，每个 `Vertex` 含三维位置及原始 ARGB 颜色；`Drawable::default()` 为空列表。单个对象的原始顶点最多 64 MiB。默认使用 `Transform::default()`，覆盖颜色为全一、覆盖开关和 display 为零、混合模式为零。`triangles()` 保留原始顶点，`transformed_triangle(index, parent)` 返回应用本对象及父级矩阵后的三角形，索引越界返回 `None`。颜色覆盖仅影响变换后的查询，原始顶点颜色不被改写。

`Drawables::insert(id, drawable)` 按对象编号登记，成功返回 true，已有编号返回 false 并保留原对象；`remove(id)` 立即移除登记，返回是否存在。`get(id)` 只读查询，`order()` 在有排序更新时按基点 Z 从小到大稳定归并。排序使用上次保留的顺序，相等优先级保留该顺序；删除后重新登记放到末尾。NaN 与其他值比较时不构成大于关系，沿原归并次序处理，不将它转换为整数或强行指定全序。平移 Z 不改变排序优先级。

`set_base_point` 总登记重排，即使向量属性比较相等；`set_position`、`set_scale`、`set_rotation` 和 `set_matrix` 沿用 `Transform` 的更新规则。`set_color(id, argb, enabled)` 保存覆盖颜色及原始启用 DWORD，零值使用每个顶点自己的颜色；`set_alpha(id, alpha)` 保留已保存覆盖色的 RGB，将 alpha 的低八位写入高字节并开启覆盖。`set_display` 保留原始 DWORD，`set_blend_mode` 接受 0～5，其他值归零。以上设置在编号不存在时返回 false。

192 组批量登记的返回值、两轮排序及颜色状态与原入口一致，覆盖重复编号、登记顺序、同级、优先级变化、正负零、无穷及 NaN。两项纯合成回归固定原归并序列、重新登记、父级 W、颜色覆盖和原始顶点保留。这一阶段尚未进行像素栅格化或帧提交。

## 当前绘图目标

`RenderTarget::new(size)` 创建一块零初始化的 CPU 渲染面。`from_tiles(tile_size, grid, tiles)` 接收按行排列的等尺寸面块，`None` 表示缺失槽位。总尺寸为面块尺寸乘列／行数，`size()`、`tile_size()`、`grid()` 和 `tiles()` 提供只读查询。布局必须精确匹配，总像素容量最多 64 MiB，槽位最多一百万个；允许空尺寸。

`pixel(x, y)` 按整个目标的顶端起始坐标查询原始 ARGB，越界或缺失槽位返回 `None`。`clear_rect(rect)` 将相交且存在的面块局部区域全部清零，包含 Alpha，并将对应块的更新标记设为 true；即使该区域已经为零，仍登记更新。`dirty_tiles()` 查询标记，`clear_dirty()` 在呈现宿主消费更新后统一清除标记，像素保持原样。矩形端点沿用 `Rect` 的 i32 回绕及空区域规则。

`RenderTarget::copy_image` 提供普通 115 的全局源坐标和行方向规则，逐块裁剪、跳过缺失块，并标记实际写入的块。

`DrawingContext` 保存 `mode`、`enabled`、`active` 和可选 `target`。`clear_rect` 与 `copy_image` 只在 mode 为零、enabled 与 active 均为 true 且目标存在时执行；其他情况跳过。默认上下文两个开关均关闭、没有目标，由绘图调度宿主设置。`Runtime::drawing()`／`drawing_mut()` 提供当前上下文，普通任务在该上下文上同步操作；对象更新和设备呈现尚未自动切换这些状态。

普通 117 的首参为零时，只读取零句柄、x、y、width、height 五项，清零当前绘图目标。可以传入五项，也可保留第六项，后者的颜色被忽略；未开启绘图或没有目标同样以状态 2 继续，操作栈原值保留。目标坐标从顶部起算；非零图像句柄分支继续从底部起算并写入第六项的原始 ARGB。

普通 8 查询的配置渲染尺寸由宿主单独保存，不随当前目标绑定改变。CPU 渲染目标不执行设备锁定；设备创建、锁定失败和呈现仍由后续平台接入实现。

2,304 组完整 117 调用核对上下文模式、两个开关、缺失目标、缺失面块、跨块裁剪、空／回绕矩形和三种颜色。状态、返回槽、全部像素／保护区、面块标记及锁定／解锁次数一致。紧邻不可读保护页的五参数数组另外确认零句柄分支不读取第六项。四项常规合成回归验证布局、清除、状态门控及真实 KCS 的共享目标操作，覆盖五／六参数、两种预算、无目标和配置尺寸独立性。
