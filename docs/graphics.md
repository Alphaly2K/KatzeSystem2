# 图像与像素接口

适用基线为 Windows CatSystem2 **2.6.1.90**。图形模块复用现有资源读取及 HG-3 元数据，开发顺序见 [GOAL.md](../GOAL.md)，子系统边界见 [设计文档](subsystems.md)。

## HG-3 帧解码

`hg3::decode_frame(bytes, id)` 接受完整 HG-3 文件及带原始位模式的 i32 帧 ID，返回 `Result<Option<DecodedFrame>>`。缺失 ID 返回 `None`，结构、压缩流或编码错误返回诊断。按文件顺序选择第一个匹配 ID，与元数据查询一致。

`DecodedFrame` 保存 `id`、完整 `StandardInfo` 和 `pixels`。像素按从上到下、每行从左到右的 BGRA8 紧密排列，行跨度为裁剪宽度乘四；Alpha 保持独立通道，不预乘、不因 Alpha 为零而清除颜色。

像素只包含裁剪区域。`info.offset`、`canvas_size` 和 `base` 继续交给绘制宿主组合，解码时不扩展到完整画布，也不将偏移或基点加到像素位置。

当前接受 HG-3 0x300、低有符号 16 位位深为 32、覆盖完整裁剪高度的 `img0000` 原生编码。尺寸必须非零，像素总长度最多 64 MiB。其他位深、切片、JPEG 和 WebP 返回未支持诊断；`Metadata` 仍可单独读取其支持的标准字段。

原生数据通过独立 Zlib 数据／命令流还原，命令按低位先读、正整数 Gamma 长度执行交替复制／清零游程。游程输出长度必须与像素尺寸相符，越界和截断均返回诊断。随后恢复四组位平面、有符号差值及行内／行间预测，保持字节回绕。

## 对照与使用约束

72 份合成图像的 34,384 个像素，以及 32 份实际图像的 33 次帧请求，均按原解码对象的逻辑行顺序逐字节核对；几何字段同时核对。原对象内部倒序存行，公开解码接口使用从上到下的顺序。

常规回归使用固定合成游程数据，覆盖位重排、正负差值、行方向、独立 Alpha、负位模式 ID、缺失帧和完整元数据；另检查尺寸溢出、损坏压缩流、截断／越界游程及未支持编码。原引擎和实际图像不参与默认测试。

资源名称补全和文件读取由资源宿主完成，解码器只访问传入字节，不访问归档、文件系统、窗口或 GPU。

## 基础渲染面

`graphics::Surface::new([width, height])` 创建零初始化的 BGRA8 像素缓冲区。`from_bgra(size, pixels)` 接收已有像素的所有权，可使用解码帧的像素；长度必须恰好为宽乘高乘四。几何元数据继续由图像对象保存。

渲染面从上到下存行，左上角为 `(0, 0)`，行跨度为宽乘四。`size()`、`stride()`、`bounds()` 提供布局，`pixels()`／`pixels_mut()` 提供固定长度的像素视图，`pixel(x, y)` 返回原始 ARGB DWORD，越界返回 `None`。任一维为零时允许空渲染面；尺寸必须可由正 i32 坐标表示，总像素长度最多 64 MiB。

`clear(argb)` 覆盖整个缓冲区。`fill_rect(rect, argb)` 与渲染面边界相交后覆盖区域，返回是否存在非空目标。两者将 ARGB DWORD 按小端写为 BGRA 字节，保留全部位模式，包括 Alpha 为零时的颜色。

`fill_rect_from_bottom(rect, argb)` 接收原图像对象从底部起算的 Y 坐标，先按原尺寸裁剪，再换算为顶端起始的渲染面行。这是普通 117 非零图像分支所需的坐标适配；该分支覆盖原始 ARGB，始终以状态 2 继续，保留返回槽。2,640 组完整 native 对照的状态、返回槽和带保护区的缓冲区全部一致。

`copy_from(source, rect, at)` 将源矩形映射到目标左上位置 `at`，同时裁剪源和目标边界，并保持请求的相对位置。它直接复制全部 BGRA 位模式，返回是否复制了非空区域；源和目标必须是不同渲染面。

`blend_from(source, rect, at, opacity)` 提供基线普通 32 位 Alpha 绘制，透明度为 0～255。源和目标矩形先分别与各自边界相交，再取两者共同宽高；左上裁剪不会让另一端同步平移。`rect` 的宽高按 i32 回绕端点差生成目标矩形。返回是否存在非空绘制区域，源和目标必须是不同渲染面。

普通混合保持引擎的整数舍入：有效源 Alpha 为 `opacity × (source_alpha + 1) >> 8`；半透明目标使用独立 Alpha 权重及整数倒数，低 Alpha 下可能得到黑色，两个半透明白色像素也可能得到略低于白色的结果。全零目标可保留有效 Alpha 为零的源 RGB；绘制区域左右各一格的全零邻接像素同样接收边缘源 RGB，Alpha 继续为零。透明度为零时仍执行这些颜色写入，已有非零 RGB 或 Alpha 的透明像素保持原值。

`Rect { left, top, right, bottom }` 包含左上边，不包含右下边。`Rect::from_xywh(x, y, width, height)` 用 i32 回绕加法生成端点；反向边界不交换，交集为空时跳过。`intersect(other)` 返回可选的非空交集。

2,640 组原像素填充入口对照覆盖四种尺寸、110 组矩形和六种颜色，返回值及带保护区的完整缓冲区全部一致。对照使用相同的缓冲区行序；原图像对象的倒序存行由其对象适配处理。普通 117 的两条路径已接入运行时，窗口呈现继续开发。

普通混合另外核对所有 256 × 256 种源／目标 Alpha、三种颜色分布、六种全局透明度及两种 CPU 路径，共 2,359,296 个像素；1,296 组矩形对照覆盖两端裁剪、空矩形、透明边缘和完整保护区，全部一致。常规回归只保留固定合成像素及裁剪案例，不依赖外部引擎或图像资源。缩放、翻转和特殊混合继续单独接入。

## 图像对象与名称

`graphics::Image::from_frame(frame)` 将一个 `DecodedFrame` 转为图像对象，保留帧 ID 和全部元数据。`id()`、`info()` 和 `surface()` 提供查询，`pixels_mut()` 允许原位修改固定长度的像素；`fill_rect_from_bottom` 提供普通 117 的填充坐标。像素尺寸和长度须符合渲染面约束，位深的低有符号 16 位须为 32。

`Image::new(size)` 创建普通 112 使用的 BGRA8 空白图像，全部像素清零；帧 ID、偏移、画布尺寸、基点和 Alpha 标记均为零。画布尺寸保留零值，宽高只写入像素尺寸。允许任一维为零，尺寸和存储上限沿用 `Surface`。

`graphics::ImageReference::parse` 专用于普通 111。它以首个冒号定位帧号，从名称末尾逐字节查找最后一个扩展名，先移除扩展名、读取帧号、在原冒号处截断，再替换扩展名。目录分隔符之后的句点才参与扩展名识别；这些步骤按原字节位置执行。十进制数值前缀若紧接句点，帧号为零；十六进制前缀保留整数。无冒号时原样保留名称并选择帧零。名称以首个零结束，长度须小于 260 字节。

|输入|资源名称|帧号|
|:--|:--|--:|
|`a:3.hg3`|`a.hg3`|3|
|`a:3`|`a.`|3|
|`a.hg3:4`|`a.hg3:4`|4|
|`a.b.c:3`|`a.c:3`|3|
|`a:7.gz.hg3`|`a.hg3`|0|
|`a:-0x10.gz.hg3`|`a.hg3`|−16|

这一名称规则与 FES POS2／SIZE2 的 `fes::ImageReference` 分别保留；两者使用不同的原入口。

## 普通 111 的装载与合成

`Images::load(owner, names, services)` 接收已经完成 KCS 格式展开的名称列表，按 ASCII 空格拆分并忽略空段；制表符和换行留在名称中，引号没有分组作用。每段解析后经 `ResourceServices::resolve(b"image", name)` 补全，再以 `LooseFirst` 读取完整资源。缺失文件、空文件及缺失帧跳过；结构损坏、未支持编码和资源服务错误返回诊断。

第一个成功解码对象成为目标，后续对象依序通过 `Image::composite` 合成，处理后释放。首图的裁剪尺寸、偏移、画布、基点和帧 ID 始终保留。全部缺失时返回零；成功时分配非零递增句柄。`get`／`get_mut` 查询该对象，失效句柄返回诊断；`release_owner(owner)` 释放该任务持有的全部图像，句柄不复用。每个图像的像素最多 64 MiB，存活图像最多一百万个。

`Images::default()` 使用独立编号源；与其他资源存储组合时使用 `Images::with_handles(handles)` 共享 `HandleAllocator`。Runtime 已自动共享图像、原始数据、XML 及脚本集合的编号源，各类型查询仍分别检查对象是否存活。

合成保留基线的特殊规则：全局透明度为零，使用普通 32 位混合，因此只向全零目标写入透明 RGB，包括左右邻接像素。目标可见性先由“源偏移加目标尺寸”与目标全局矩形求交，源使用自身完整局部区域；目标起点换算为裁剪后的局部位置，两端独立裁剪，再按底端起始的内存坐标转换至公开像素行。负偏移不会同步移动源起点。这一操作不扩展首图画布。

`Runtime::set_resources(services)` 配置拥有的同步资源服务，普通 111 随后装载并以状态 1 压入句柄；`Runtime::images()` 可读取结果。普通 117 接受该句柄及 x／y／width／height／ARGB，以状态 2 填充并保留操作栈上的原值。任务实际释放时回收其图像；仅设置删除标记时图像继续存活。原始数据 365／366 的句柄属于另一接口，不能传给 117。

每次成功装载独立创建图像；额外绘制使用者可共享持有同一对象。资源管理器缓存及特殊混合仍待接入。

301 组名称／帧号、400 组完整 native 合成调用（其中 107 组进入绘制），以及 432 组保留对象创建、HG-3 解码、合成和释放的完整装载调用全部一致。后者核对 206,304 个像素、几何字段、资源请求和持有列表。常规四项合成回归覆盖名称重组、几何与行方向、缺失跳过、句柄寿命，以及真实 KCS 的装载／填充与两种预算续跑。

## 空白图像与显式释放

`Images::create(owner, size)` 无需资源服务，创建空白图像并分配与 `load` 同一序列的句柄。普通 112 接受 width、height 两项，以状态 1 返回该句柄；零尺寸同样创建非零句柄。超过库的尺寸／容量上限时返回诊断。

普通 114 使用 `Images::release_for(caller, handle)`，解除调用任务的匹配持有登记，并释放一个引用。其他任务调用时仍减少引用，原任务的登记继续保留。`release(handle)` 解除所属任务登记并释放一个引用，供独立调用者使用。两者均跳过零句柄，非零失效句柄返回诊断；后续句柄不复用。114 接受一项，以状态 2 继续且保留操作栈原值。

`retain(handle)` 为额外使用者增加一个引用，`release_reference(handle)` 配对释放且保留任务登记。最后一个引用释放后句柄失效；`release_owner(owner)` 只释放尚有登记的任务引用，可以重复清理。共享使用者持有期间，显式释放或任务回收后仍可查询和修改同一图像，修改对其他使用者立即可见。

`Images::share(handle)` 创建没有任务登记的独立包装，并共享原像素与几何；调用方须显式释放新包装。源包装的最后一个引用释放后，源句柄立即失效，新句柄继续有效。它与 `retain` 保留原包装的行为分别提供；两个包装指向同一像素时，115 仍按同图重叠顺序即时读写。

`pixel_handle(wrapper)` 查询当前绑定的底层像素句柄，不增加引用。包装与像素使用共享编号源分配不同句柄，不能互换；像素句柄在至少一个包装持有时有效。原包装释放后，其他包装或列表条目仍持有的像素句柄可继续登记。

`Images::recreate(wrapper, size)` 保留包装及任务登记，按空白图像创建路径重配像素。基线只在宽高均不同时替换像素；任一轴相同就保留原尺寸、像素、几何和 Alpha 分类。替换后绑定新的全零图像，旧像素由其他包装继续持有。库的尺寸检查或分配失败保留原绑定。该路径用于 FES CIMAGE 的纯色来源准备，后续矩形填充仍按实际像素尺寸裁剪。

`Images::create_empty(owner)` 创建尚未绑定像素的包装，`pixel_handle` 返回零；`get`／`get_mut` 返回诊断。首次 `recreate` 分配像素，包括 `[0, 0]` 请求；后续才应用任一轴相同即复用的规则。`share` 共享调用当时的像素绑定，空包装的独立副本仍为空，后续重建互不改绑。引用及任务回收规则与普通包装相同。

20 组完整创建／释放对照覆盖宽高分别为零和不同非零组合，全部几何、初始像素、状态、返回槽及持有列表一致。常规合成 KCS 回归串联 112 创建、117 填充、115 图像混合、114 释放及任务回收，覆盖零尺寸和两种预算；释放、空源与失效句柄检查复用现有生命周期回归。

CIMAGE 的十三阶段纯色来源核对 496 字节完整像素和实际尺寸，确认单轴复用、双轴重建及零尺寸组合。一项合成回归另固定旧包装共享像素的继续存活、重建后的独立编号和失败保留绑定。

## 图像列表的重绘与脏区

`ImageList::new(owner, size, images)` 创建独立的全透明自有图像，并使用一个完整面块。`new_tiled(owner, size, tile_size, images)` 配置横纵步长；基线以横向配置计算面块高度，纵向步长仍使用纵向配置，非正方形配置可能产生重叠区或间隙。来源、列表自有图像和共享画布分别持有；`image()` 返回自有图像包装。列表与传入的 `Images` 存储配对使用，所属任务释放后应停止使用该列表。

`set(key, source, properties, images)` 接收普通图像包装和 `ImageListProperties`。新条目为来源建立独立包装，已有条目保留自己的包装并替换来源。释放来源包装不影响已登记条目，像素修改仍相互可见。`key(sender, slot)` 按 `(slot << 16) | sender` 打包，不先裁去 sender 的高位；默认优先级取 key 的高 16 位，绘制先按有符号优先级、再按无符号 key 排序。同一 key 的再次登记替换旧条目。

`set_pixels(key, pixels, properties, images)` 直接接收底层像素句柄，与命令 286 的第一来源对应。它同样建立独立包装，拒绝普通图像包装及其他资源句柄；`set` 先查询包装绑定的像素，再执行这一登记。

当前支持无变换来源，位置的 Y 从自有图像底部起算，像素查询仍按顶部起算。位置和基点分别转为 i32，再以回绕算术计算 `position - base + source.offset`。裁剪按来源与目标的对应位置进行；透明度为零或不可见时跳过。来源分类为不透明且透明度为 255 时直接复制，其他情况保留普通 Alpha 混合及左右全零邻接像素的 RGB 延展。自有图像同时作为来源时返回诊断。

Alpha 分类由共享像素对象保存。HG-3 装载时使用 `StandardInfo::reserved` 所保存的 stdinfo Alpha 标记：零直接分类为不透明，非零直接分类为使用 Alpha，像素字节原样保留。普通 112 的空白图像则在首次实际绘制非空区域时扫描像素。分类一旦确定，矩形填充保留旧分类；独立包装共享同一分类。完全位于画面外、不可见或透明度为零的来源不会触发延迟扫描。

`remove` 释放来源包装，将可见条目的历史区域标脏。`clear` 释放全部来源，立即清零自有图像并将全部面块标脏。`release` 同时释放来源与自有图像，可重复调用；其他包装仍共享的输出像素继续保留。全部包装登记到 owner，任务实际回收时自动解除这些引用。`set_offset` 只保存提交到共享画布的偏移，不修改自有图像几何或像素。

`dirty_rectangles()` 按面块顺序返回当前脏矩形。登记保留累计的几何边界，先使用来源基点更新中间边界，再应用请求基点；隐藏状态下也保留中间边界。`update(images)` 先清除所有脏区，再按条目、面块顺序绘制，成功后消费脏区并返回提交矩形。重叠区域因此可能重复混合；几何外的透明 RGB 可以留存至后续覆盖该位置的重绘。来源像素修改和输出偏移修改均不单独产生脏区，需重新登记或调用 `invalidate_all()`。`redraw(images)` 将所有面块标脏后更新。

`set_clip(key, rectangle, images)` 设置条目的全局裁剪矩形，并将历史边界缩至新裁剪范围。再次登记来源保留裁剪。相同矩形不标脏；不同的非空矩形先标记旧历史，再对可见条目标记裁剪后的历史。空矩形恢复完整视口并执行这一变化流程。`None` 直接恢复完整视口，不标脏，也不重新扩大历史边界；后续重新登记或改变显示状态时才重新计算边界。绘制范围同时受脏矩形和条目裁剪约束。

`Runtime::images_mut()` 提供同一图像存储。`update_image_list(&mut list)` 更新自有图像，并仅将返回的脏矩形按偏移复制到当前画布；`redraw_image_list(&mut list)` 重绘全部面块并提交整幅自有图像。上下文模式及两个开关门控提交，关闭时仍更新自有图像并消费脏区；重新开启后可显式整幅提交。结果可由普通 PLANE 画布纹理绘制到独立帧。类型 15 的首批命令与自动更新见下节；其他来源及变换继续接入。

1,280 组位置、基点、来源偏移、透明度及 Alpha 组合的完整自有图像共 245,760 字节与原入口一致；16 组双来源重叠确认默认优先级下的无符号 key 次序。两项常规合成回归固定裁剪、透明 RGB、直接复制、来源替换与释放，以及两种解释器预算下的 KCS 图像创建／原任务释放／列表合成／跨面块画布提交／FES PLANE 最终帧。

## 共享列表原始数据来源

命令 286 的第二来源接收完整图像原始数据对象。基线在登记时建立帧目录并解码各帧，初始选中无符号 ID 最小的帧；负数位模式按对应 u32 排序。重复 ID 保留首个匹配帧。`ImageList::set_hg3(key, bytes, properties, images)` 提供同一无变换登记；登记完成后可释放输入字节或原始数据句柄。解码错误保留旧条目，帧集合总像素受 64 MiB 存储上限约束。类型 15 任务通过 `Host::image_data` 同步借用第二来源的字节，包装宿主应转发该查询。

`select_frame(key, id, images)` 选择已缓存的帧并恢复其基点，缺失 key 或 ID 返回 false，保持当前来源。选帧本身不产生脏区，自动更新仍保留旧画面；重新登记或显式失效后才重绘。像素来源重登记保留帧缓存，并改绑当前选中帧的同一个包装，因此以后再次选择该帧时使用改绑后的像素。原始来源重登记替换全部缓存帧，删除／清空／释放列表或所属任务回收时解除其持有。

`set_source_identity(key, identity)` 只修改不增加引用的来源身份，零也可显式保存，不产生脏区；缺失条目返回 false。`find_source_identity(identity)` 返回匹配身份中有符号 key 最小的一项，零可匹配尚未指定身份的条目。来源重登记保留身份，删除条目后不再匹配。身份反查顺序独立于绘图排序；任务命令 308 返回 key 右移 16 位所得的槽号。十二组、六阶段、四种查询取得 288 份核心与任务输出记录，确认负 key 优先、重复身份、零身份、重登记保留及缺失时不写输出。

基线另存容器首帧的裁剪偏移和几何边界，当前绘制使用选中帧的裁剪偏移；可移植无变换接口尚未提供首帧专属几何查询。动画／控制命令与额外失效通知继续独立接入。

72 份单帧输入及四份含乱序、负数、重复和保留 ID 的多帧输入取得完整来源状态及列表像素。登记后将原始字节设为不可访问，后续绘制和列表析构均正常完成，76 组、84,816 字节输出与未保护时一致；这些普通 HG-3 输入的列表独立持有已解码帧。同组输入的 77,824 字节完整列表像素与可移植实现一致。两组十七阶段序列另核对来源互换、重新登记、选帧／缺失帧、隐藏／恢复及显式重绘：列表像素与脏区分别为 16,864 字节及 25,296 字节，均与原入口一致。两项纯合成回归固定帧排序、缓存改绑、失败保留、选帧不标脏、任务回收，以及真实 KCS 装载／显式关闭原始句柄后列表继续绘制。

## 列表动画与任务时钟

`ImageList::load_animation(key, bytes)` 将 ANM 绑定到已有条目；缺失 key 返回 false。装载成功初始化新的时间线和显示缓存；解析失败移除旧时间线，保留播放控制及旧显示缓存，此时绘制使用条目自身属性。装载本身不选帧或标脏。`animation(key)` 只读查询同一 `ImageAnimation`；解释和时间线契约见 [ANM](anm.md#图像对象的动画装载)。原始来源重登记保留动画并更新最大无符号帧 ID，同时请求下次实际推进重设时间基点；像素重登记保留原有帧缓存和动画。

`set_animation_time` 保存时间并更新现有时间线的 origin，`set_animation_playing` 保存原始播放开关；两者缺失 key 返回 false，设置本身不推进。`update_animations(now, budget, images)` 按有符号 key 次序逐项推进，返回是否整轮完成；`update_animations_with_random` 使用调用方提供的共享随机回调。预算按每个条目独立计算，续跑保留本轮时刻和游标，不重复已执行的随机副作用。`animations_pending()` 查询续跑状态；这期间来源、动画控制、裁剪、排序、显隐和绘制操作返回诊断，`release` 可以取消并释放整个列表。

整轮中的条目更新完成后才应用选帧，缺失帧保留当前像素。列表组合 ANM 的透明度和显隐；当前无变换类别零的几何与绘制仍使用条目自身位置，ANM 整数位移保留在动画状态中。动画变化后仅在新的有效显隐非零时标记旧历史和新几何；变为隐藏时旧像素保留，直到其他失效或显式重绘覆盖该区域。隐藏期间的帧变化继续参与后续几何历史。

类型 15 的 299 按完整文件名以 LooseFirst 读取，不作类别补全或格式展开。文件缺失或空数据保留旧动画；成功读取后的格式错误移除旧动画并返回诊断。读取发生在条目查找前。301 以任务 `clock.elapsed()` 设置目标时间和播放开关，然后用同一时刻推进整个列表；目标不存在时跳过全列表推进。自动主体使用 `Runtime::update(now, increment)` 的第二个参数推进动画，随后才处理脏区。296／298 和显式列表绘制入口只绘制，不推进动画。310 关闭时同时停用自动动画和绘制，292 关闭提交仍推进动画及自有图像。

`restart_animation(key, budget, images)`／`restart_animation_with_random` 强制重启单个条目，保留播放开关；缺失条目直接完成且不标脏。返回 false 时以相同 key 续跑，已完成指令与随机副作用不重复；也可通过普通动画更新接口完成该次续跑。重启只推进目标条目，不推进其他条目。保留帧 10000 存在时使用哨兵选帧规则；无动画或重启后隐藏的条目仍标记历史及新几何。命令 306 使用同一服务，不设置时间或改写返回槽。

宿主的 `update_image_list_animations`／`restart_image_list_animation` 提供对应服务。默认实现使用同一 `Images` 和固定区间动画；需要随机区间时由宿主提供共享随机源。Runtime 与普通 KCS 共用 `HostState::random`，包装宿主转发该服务。二十阶段的动画状态、40 份完整列表像素和脏区共 20,640 字节与原入口一致，覆盖暂停、隐藏、缺失帧、原始来源替换和动画重载。另十一阶段任务对照确认完整文件请求、缺失／失败替换、任务时间和自动主体参数的区别。重启的四十四阶段核对 88 份完整图像／脏区及动画状态，共 45,408 字节一致，预算一和 4096 均通过。三项纯合成回归固定预算续跑、旧像素保留、暂停重启、保留帧、隐藏／无动画失效及运行时共享随机序列。FES 动画资源请求和主体自动调度继续接入。

## FES 场景推进

`runtime::fes::Scene` 保存预先装载的 FES 解释器、对象存储、等待期限及本轮推进状态。调用方绑定已创建的共享列表，并在所属任务主体时点调用 `Runtime::update_fes_scene(owner, scene, now)`。该入口自行消费定义、初始化、已注册的 SUBCOMMAND 声明、已接入的对象控制与 IMAGE 动画命令、`decode`、整数等待、根运动／指定对象／绝对帧等待、块末尾及退出事件。BASE 和三类图像对象的运动子命令已连接资源装载与队列；未知命令、其他声明、其他类型的运动及尚未接入的文字／音频完成等待返回诊断；对应未确认事件保留，先前已完成的脚本副作用不重复执行。

`wait n` 的数值参数小于一时统一等待一个逻辑时刻，普通块结束同样等待一个时刻。期限按 u32 回绕加法保存，以原始无符号大小判断是否到期；等待期间仍逐轮更新对象。期限落入 `0xfffffff9`～`0xffffffff` 时，执行器按保留值分派特殊等待；当前接入 `−1` 的根运动、`−2` 的绝对帧及 `−4` 的指定对象，其他保留值返回诊断。每轮向解释器发布 `_FRAME_`，基点为零时先取当前时刻减一，再保存当前时刻与基点的回绕差值；预算续跑保持本轮原时刻和帧值。

普通主体的 `decode` 对应内部提交事件 23：先完成媒体更新，再确认命令并在同一时刻继续脚本；等待或块末尾先推进运动，再完成本轮最终媒体更新。对象及系统处理器中的 decode 结束当前处理片段并排队提交，后续普通主体统一消费；DEFAULT 片段结束后仍进入对象自身处理器。普通 `exit` 发布通知后，在同一逻辑时刻继续下一语句；子程序返回位置保留。对象遍历按声明顺序展开各银行，在更新前解析当前名称绑定；重复声明保留重复记录，缺失银行跳过。来源装载、动画请求和排序继续沿各对象的既有更新入口执行。预算耗尽时保留更新游标，后续条目失败时也不重复此前已完成的条目。退出码在最终更新完成后可查询。

四类脚本的 28 份数值／期限／返回值记录在预算一和 4096 下均与原入口一致；另三组声明顺序和一组 decode 脚本确认重复记录、中途提交及同轮继续。三项纯合成回归覆盖时间冻结、等待恢复、块循环、未知事件保留，以及完整 FES 到动画画布像素。`Scene::prepare` 可单独完成装载期声明和属性；`Runtime::prepare_fes_scene` 继续创建图像空包装和 BUTTON 下层任务，两者均不执行 START 或更新媒体；纯合成回归覆盖这一边界及预算续跑。退出通知不停止脚本，后续 update 继续遵守等待与块循环规则。显式场景入口仍可由外层驱动；类型 34 的装载及任务树自动调用见下节，其他输入模式及声音联动继续整合。

## FES 运动与帧完成等待

`wait` 保存根运动等待，等待期间仍更新运动和媒体。检查到根子树没有活动运动时，先将期限改为零并完成本轮更新，再由下一轮继续脚本；即使最初没有运动也遵守这一时点。默认取消设置下，左击或跳过模式只向根子树请求运动结束，不清空队列，也不立即继续脚本。运动脚本若忽略结束请求，等待继续。

`wait object[bank]` 保存对象名称与银行，银行表达式求值一次。省略银行时逐个查询现有银行及其子树，中间缺失银行跳过；任意银行仍活动就继续等待。检查到全部完成时在当轮继续脚本。默认取消设置下，左击或跳过模式可立即继续，且不向运动请求结束。若开始时目标不存在，命令改按数值表达式求值，结果小于一时等待一个时刻；数组银行表达式与这一数值回退分别沿解释器作用域求值。

`wait frame [value]` 等待场景 `_FRAME_` 达到原始无符号阈值，缺省零；它使用场景起点，不以命令所在时刻重新计时。已经达到阈值也先结束本轮，下一轮才继续。默认取消设置下，左击可中断普通期限和绝对帧等待，并向根子树请求运动结束；已经到期时直接继续。对象、系统处理器中的上述等待均结束当前片段，保留主等待和调用位置；已解析的目标及绝对帧阈值仍保存。

当前对象类型以运动子树判断完成，IMAGE 的帧动画不参与这一查询。声音、文字、标签和私有标志等待继续接入；等待取消设置见下节。

## FES 等待取消与 keyskip

`keyskip` 从左至右处理参数，选项忽略 ASCII 大小写。每次命令先按开启取消、关闭 ctrl 和 cont 处理；`on`／`off` 设置取消开关，其他数值表达式按非零开启，后面的开关覆盖前面的值。`ctrl` 和 `cont` 在本次命令中置位；不带参数的 keyskip 恢复这三个默认设置。命令不结束对象或系统处理器，后续语句继续执行。

`force` 消耗紧随其后的一个数值表达式，缺省零；非零保存强制标志，并立即设置点击请求、进入跳过模式和写 `_CLICK_L_=−1`。零值只清除保存的强制标志，已经设置的点击请求和跳过模式继续保留。没有 force 的命令不改写该标志。`Scene::forced_key_skip()` 查询最后保存的强制标志，独立于当前输入模式；强制设置不改写 `raw_input()`。

`cont` 跨帧保留点击请求，普通瞬态命名值仍按原时点清理；后续 keyskip 不带 cont 时，普通模式的本轮收尾恢复点击清理。各等待分支使用不同的取消条件：

|等待|取消条件与行为|
|:--|:--|
|根运动|取消开关开启且有点击请求时，请求根子树结束；继续等待运动响应|
|数值期限／绝对帧|取消开关开启，且有点击请求或处于跳过模式时，请求根子树结束并继续脚本|
|指定对象|有点击请求，且处于普通模式、ctrl 置位、取消开关开启中至少一项成立时，直接继续脚本；不请求运动结束|

因此 off 会阻止普通期限和根运动取消；普通模式中的指定对象等待仍接受点击，而跳过模式下可由 off 阻止，ctrl 可再次放开该分支。已经到期的普通期限或绝对帧先按完成处理。

## FES 专属暂停与唤醒

348 比较完整的第二数据项，相同值直接完成；例如 1 → 2 会再次执行睡眠。先保存新值，再分派 `_FES_SLEEP_` 或 `_FES_WAKE_`。系统块完成后按声明／银行次序刷新对象，再隐藏或恢复 CIMAGE／IMAGE／BUTTON 的列表条目及 CPLANE／PLANE 的下层任务；BUTTON 先发送下层 93，睡眠为零、唤醒为当前原始 ENABLE，再设置图像显示。唤醒读取当前 FES 显示属性，最后强制提交共享列表。没有旧显示快照。预算续跑和媒体错误重试保留系统块进度，已完成的系统块副作用不重复。

专属暂停早于首次辅助按钮创建，暂停中的主体不执行输入查询、脚本或对象更新；任务树仍更新时钟和子任务。它与基类时钟暂停独立。暂停中的 9 仍查询 sender 96 并保存两份原始状态，10 只清任务状态，两者以 95 响应并保留外层返回槽；64／65 只返回零。

系统块使用共享变量，不推进 `_FRAME_`。正常结束、`break` 或局部 `wait` 保留主流程位置与等待；`break` 保留返回值，局部 `wait` 后的语句本次不执行。`call` 返回规则沿用对象自身事件：目标名变化且调用深度等于进入时深度才把目标交给主流程并清等待。`next` 清空全部调用位置；进入时已有调用会使目标在系统块内执行，随后恢复主位置和等待。系统块在 `call` 内等待会留下返回位置，供后续主流程使用。普通退出通知之后仍可执行系统块，保留主流程的当前游标与等待。

当前支持变量、条件、控制流、下列对象控制、IMAGE 动画命令、已支持类型的运动子命令和 `decode`；其他对象命令与运动类型返回诊断。decode 结束当前系统处理片段并排队媒体提交，主流程位置和等待保留。系统块 `exit` 结束本次分派并把返回码排队，保留主流程游标、等待和调用栈。下一次已启动且未暂停的主体先推进控制器，再按顺序消费已有通知及本次产生的通知；同轮普通 exit 可以覆盖系统块返回码。暂停和 348 本身不消费该队列。

## FES BUTTON 区域更新

BUTTON 复用 IMAGE 的文件、帧映射、动画、画布登记及固定槽号，同时保存直属 FES 所属任务的类型 6 按钮。`prepare_fes_scene` 和任务 338 按声明／银行次序创建下层任务，尚不登记输入区域。重复声明会再次创建并覆盖当前对象的下层编号，先前任务仍属同一父任务；预算续跑、重复 prepare 和列表重新绑定均不重复已完成的创建。

## FES SLIDER 属性核心

`fes::SliderState` 保存独立控件状态，不继承图像坐标和帧映射。初始文件、平面及元数据请求为空，矩形、数值范围、位置和方向为零，PRI 为 10，DISP 为零，ENABLE 为一，Alpha 为 255。所有请求标记初始为 false；原构造未初始化的范围请求标记在库中确定为 false。

初始化按 FILE、PL、POS2、PRI、DISP、ENABLE 的顺序应用。FILE 即使相同也请求重新装载；PL 仅在名称或银行变化时使对象及后代失效。POS2 保存资源名和帧号前缀，独立请求元数据更新。PRI 最后加 20：整数组初始化使用同一原值，显式银行初始化额外加具体银行号。DISP 即使相同也递归失效；ENABLE 保留原始数值，仅在变化时标记自身。POS、SIZE、COLOR 等图像列不改变此状态。FILE 最多 255 字节，平面名称最多 31 字节，位置资源名称最多 127 字节；错误保留已完成的属性修改。

`set_rectangle` 保存四个原始整数并请求属性更新。`set_range`、`set_position` 和 `set_alpha` 分别设置独立请求，相同值仍请求更新；范围允许倒序，位置不在此层裁剪，位置通知参数独立保留。`set_priority` 只保存原值加 20，不设置显示更新标记。直接修改公开字段时，宿主相应维护请求标记。

运动属性仅使用 DWORD 28 的高字节；其余 35 项及该 DWORD 的低 24 位清零。原始 Alpha 先取低八位再打包，回写取高八位，每次都请求 Alpha 更新，包括值未变化的情况。范围、位置、矩形与显示均不从该运动块回写。

这一接口目前提供独立状态核心。SLIDER 的配置资源、下层任务创建、按钮反向关联、输入调整及实际绘制继续接入。

## FES 对象运动

每个对象独立保存运动队列，BASE 的基准保持队列默认值，CIMAGE／IMAGE／BUTTON 使用二维图像属性布局。`Objects::start_motion` 接收已装载的运动 KCS 和已换算参数，按分组零追加；delay 是相对该运动起点的开始偏移，起点由队列首次更新登记。当前 CPLANE／PLANE 的运动属性尚未接入，启动时返回诊断。

仅当目标和全部后代都没有活动运动时，启动前捕获图像的基准属性；否则沿用原基准。各帧从这一基准组合整条队列，运行期间直接改写属性不会替换基准。目标自身队列已清空但后代仍活动时，目标的新运动仍沿用旧基准。

`Objects::update_motions` 显式推进根对象子树，同级按对象标识顺序，子对象先于父对象；脱离根子树的对象不在本次遍历中。图像回写使用现有属性、来源与排序规则，父对象失效继续递归标记后代。全部运动停止后统一清理目标队列，运动编号继续递增。预算耗尽时保留遍历顺序、时刻、已完成对象和队列内部状态，续跑不重复消费随机数或更新已完成对象。调用方在运动完成后刷新媒体，并在整次续跑期间保持属性与宿主状态。

Scene 的普通主体在等待或帧边界自动推进运动，再刷新媒体；等待尚未到期的每轮仍更新运动。普通 decode 先刷新媒体并继续脚本，在最终边界统一执行本轮运动。对象及系统处理器加入的运动留到后续普通主体更新；该阶段与普通 KCS 共用随机序列及调试消息，媒体错误后的重试不重复运动。

已注册子命令逐银行换算参数并加入运动。资源服务按 mot 类别补全名称，场景缓存每个绑定的名称，Runtime 按忽略大小写的完整名称缓存成功装载的 KCS；类别映射在场景存活期间保持稳定。实例的 VM 数据独立。缺失资源跳过创建并继续脚本，后续调用仍可重新读取；读取错误保留当前银行已换算的参数，重试不重复其副作用。数组遇到缺失银行结束。oneshot／continue 均以分组零加入，使用目标当前保存的运动延迟。延迟初始为零；`object delay [value]` 更新后续插入时使用的原始 32 位偏移，不改写已有运动。`object ismot index` 将目标及后代的活动状态写入共享变量；尚未到开始时刻的运动也算活动。`object stop` 已接入；对象完成等待继续接入。

`object stop` 先向目标及全部后代的运动写入结束请求，再以零时刻按先子后父更新子树，最后只清空目标自身队列并将目标运动延迟归零。它不使用队列的独立 finish 入口；收到结束请求的延迟运动立即执行，elapsed 保留零时刻换算所得的回绕值。后代若忽略结束请求，仍继续活动，后代延迟也保留。Scene 在普通流程和对象／系统处理器中即时执行停止，媒体刷新仍按原边界进行；预算续跑保留已完成对象和当前银行。

## FES 系统键分派

9 的键槽 2／3 及大于 11 的无符号值按 SYSKEY 分派；0／1、4～11 仍走各自保留路径。先按普通按下规则保存当前焦点及原始输入，再按媒体声明顺序扫描 BUTTON。每条记录重新查询当前对象，ENABLE 非零、SYSKEY 不为 −1 且原始 32 位键值相等时，分派该对象的 PUSH_L。重复记录可重复执行同一对象；较早处理器对后续对象属性的修改立即影响扫描。SYSKEY 除 −1 外的负值也可匹配直接传入的原始键值，正常设备扫描使用 0～79。

所有匹配记录均执行，已有对象处理器不提前结束扫描。至少一个对象自身有处理器时跳过 95；仅有 DEFAULT 处理器仍回写默认响应。扫描后统一刷新媒体。该路径不把匹配对象设为焦点，释放仍使用按下前保存的焦点；10 不扫描 SYSKEY，系统键释放没有对应的 PUSH_L／RELEASE_L 配对。预算续跑和错误重试保留当前处理器、已完成的记录与汇总结果，已完成的处理器和响应不重复。

## FES 方向输入与指针定位

按下键槽 4～7 对应上／下／左／右。先保存本次按下前的焦点供释放使用，再寻找方向目标。当前焦点名称可解析时直接导航；否则即时查询指针，按媒体声明顺序查找第一个矩形命中 BUTTON，即使该按钮未启用。矩形使用取整的有效图像位置和当前请求尺寸，不叠加关联平面。TYPE 非零且存在当前图像包装时，还按局部坐标减图像裁剪偏移读取像素，Alpha 非零才命中；没有包装则接受矩形，包装没有可读像素时返回诊断。

没有当前对象且指针未命中时，直接选择有效、已启用的默认焦点；默认焦点无效则回写 95。已有或命中的对象先尝试网格导航。没有方向目标且源 BUTTON 仍启用时回写 95；源无效或禁用时尝试默认焦点，再失败则只刷新媒体，不回写 95。被关联控件消费的结果同样只刷新媒体。默认焦点选择不再进行第二次网格查找。

成功选择后立即保存新焦点，以目标句柄更新 `_PUSH_UP_`／`_PUSH_DOWN_`／`_PUSH_LEFT_`／`_PUSH_RIGHT_`，再计算指针目标并向输入 139 发送一步移动请求，最后刷新媒体，不回写 95。指针位置为有效图像位置取整后加缓存 keypos；关联 CPLANE／PLANE 的 EXPOS 非零时，再加有效平面位置取整值，不减平面基点。各轴按 i32 回绕，发送时只保留低十六位；输入对象继续执行逻辑范围检查。

移动请求由后续输入主体实际执行，方向命令本身不分派 FOCUS／UNFOCUS；后续指针选择更新按正常区域顺序触发它们。10 仍使用导航之前保存的按下目标。媒体错误或预算续跑保留已完成的方向发布和移动请求，因此其间其他命令设置的新指针请求不会被重试覆盖。

## FES 默认焦点与焦点锁

`button noact [value]` 把 BUTTON 名称和银行排队为默认焦点，其他已接入对象类型跳过。value 缺省不求值，存在时求值一次但不使用结果，其后的参数忽略。多银行对象必须显式选择银行，省略银行时整条跳过且不求值 value；单银行省略时选择零，显式无效银行不被改写。不存在的具体银行跳过；缺失名称的整行表达式回退仍返回诊断。命令不要求按钮当前启用，也不直接执行 FOCUS。

`lockactive [value]` 把原始整数排队为焦点锁，缺省零，非零值启用锁。在普通主体中处理通知后同帧继续脚本；在对象处理器或睡眠／唤醒系统块中结束当前处理器，后续语句本次不执行，主流程位置与等待保留。

两类命令与退出通知共用有序队列，处理器分派和专属暂停本身不消费队列。下一次已启动、未暂停的普通主体先推进控制器，再处理通知；普通主体中的命令在对应控制器执行边界生效。`Scene::preferred_focus()` 和 `focus_lock()` 查询最近已消费的值。默认焦点用于方向导航的回退。

## FES 对象控制命令

对象控制支持下列命令。`stop` 由 Scene 推进；其余由 `Objects::dispatch_object_command(interpreter, line, state)` 消费 `Event::Command`，返回 true 后确认事件，未识别的命令返回 false。Scene 的普通推进与睡眠／唤醒系统块均自动处理。目标银行与 `@` 事件对象沿用解释器作用域，命令阶段保存属性和更新请求，媒体修改在 `decode` 或本轮收尾的对象更新阶段提交；`getid` 当场写入共享变量。

|命令|缺省参数与当前类型行为|
|:--|:--|
|`object disp [value]`|缺省一，非零归一为一；CIMAGE／IMAGE／BUTTON 和两类平面在显示值变化时递归使后代失效|
|`object size [width] [height]`|两轴各缺省零；图像仅在尺寸变化时请求来源重建，平面每次请求重建|
|`object keypos [mode] [x] [y]`|各项缺省零；CIMAGE／IMAGE／BUTTON 保存导航定位模式和偏移，不设置媒体更新标记，其他已接入类型跳过|
|`object setid [number]`|缺省零；IMAGE／BUTTON 应用逻辑编号，遵循现有帧映射及有效范围，其他已接入类型跳过|
|`object getid [index]`|缺省共享变量编号零；读取具体 IMAGE／BUTTON 的逻辑编号，写入求值所得的共享变量编号，越界编号跳过写入|
|`object enable [value]`|缺省零，非零归一为一；只修改 BUTTON，变化时仅使自身属性失效，其他类型跳过|
|`object pri value`|缺少参数时跳过；图像使用值加 20 的优先级及独立排序标记，保留列表槽号；平面保存原值并递归失效，即使数值相同|
|`object pos2 file [frame]`|缺少文件时跳过，帧号缺省零；CIMAGE／IMAGE／BUTTON 保存一次性位置元数据请求并递归失效，平面跳过|
|`object delay [value]`|缺省零；所有已接入类型保存原始 32 位运动延迟，负值按无符号回绕|
|`object ismot index`|缺少参数时跳过；将目标及全部后代的活动运动状态写入共享变量，越界编号跳过写入|
|`object stop`|Scene 即时请求子树运动结束并更新，随后只清空目标队列和目标延迟；额外参数忽略|

正常对象分派先求值目标银行，再按参数顺序各求值一次，随后遍历银行。多银行 `getid` 省略银行时整条跳过，目的变量参数也不求值；单银行自动使用零。其他命令省略银行时从零遍历至首次声明数量。`disp`／`setid`／`pri`／`keypos` 遇到缺失银行结束，其他类型跳过；`size` 遇到缺失银行或不支持类型均结束；`pos2`／`enable` 跳过缺失银行及不支持类型，继续后面的银行。`delay` 遇到缺失银行结束，保留此前修改；`ismot` 对各银行子树的活动状态取或，但中途遇到缺失银行时保留目的变量原值。两者仅求值第一个数值参数一次，忽略额外参数。`stop` 跳过中途缺失银行并继续，目标银行表达式仅求值一次；停止逻辑由 Scene 提供，不属于 `dispatch_object_command` 的同步属性接口。

图像导航偏移初始为 `[0,0]`，模式为零。任意尺寸写入，包括相同 SIZE、SIZE2 与装载所得尺寸，在零模式下把缓存重设为 `[width−16,height−8]`，整数减法回绕；非零模式保留缓存。`keypos` 的非零模式直接保存 `[x,y]`，模式保留原值；零模式忽略 x／y 的值，但仍对两项求值，并按每轴尺寸向已有偏移累加：大于 32 加尺寸减 16，大于 16 加尺寸减 8，其余加尺寸除二，负数向零截断，加法回绕。重复零模式会重复累加，不能从当前尺寸单独推导偏移；参数按空格分隔。

`pri` 的图像比较使用当前已加 20 的值与原始参数：当前为 27 时传 27 跳过，传 7 仍登记一次排序变化，结果仍是 27。它不采用初始化 PRI 的逐银行加值，也不改写列表槽号。`pos2` 先组成 `file:frame`，再按第一个冒号和整数前缀解析；因此 `asset:5 7` 保存 asset 的第 5 帧。文件名必须少于 128 字节；元数据读取推迟到属性更新阶段。

IMAGE 的 `size` 变化也会重新读取当前文件并重新登记，相同尺寸不读；普通文件模式保留新的请求尺寸，任一轴设为 −1 时整组恢复物理像素尺寸。它不缩放已加载的像素。原始来源和直接路径继续沿各自的来源更新规则处理。

目标名称或起始银行缺失时，基线改走整行表达式求值，当前库对此返回诊断，不执行对象参数。非 IMAGE 的 `getid` 在基线写入目标名称的进程地址，当前库返回明确诊断；不以零或对象句柄替代该地址。其他类型的扩展语义在实现对应对象时接入。

## FES IMAGE 动画请求

`Objects::dispatch_image_animation(interpreter, line, state)` 消费解释器的 `Event::Command` 中的 `setanm`／`anm`；成功返回 true 后调用方才确认该事件。其他命令返回 false。目标银行及事件对象引用复用 FES 解释器的解析接口；省略银行时依对象数量展开，缺失银行跳过。当前只有 IMAGE 应用请求，CIMAGE、BASE 和两类平面跳过。基线还允许按钮类型，按钮对象仍待接入。

`setanm [name]` 保存已展开的名称，不改变播放开关；没有扩展名或扩展名为空时补 `.anm`，缺省名称得到 `.anm`。显式的非空扩展名暂时保留。`anm [mode]` 将播放开关设为零或一，只有忽略大小写的 `STOP` 表示零；缺省、空参数及 `0` 均表示播放。两类命令总是请求后续更新，相同值也会重新消费，显示属性和来源重建标记保持独立。`Object::image_animation_request()` 只读查询保存的名称、播放开关和待处理标记；名称超过 255 字节返回诊断。

`Runtime::update_fes_object` 在来源准备／登记完成后、排序更新前消费 IMAGE 的动画请求。先清除请求标记；播放非零时以 image 类别补全保存名称，将结果扩展名替换为 `.anm`，再依次发送 299 装载和 301 播放。暂停只发送 301，不读取动画文件。资源读取和预算续跑沿用共享列表服务；再次请求播放会重新装载，普通对象更新不重复读取。解析失败保留此前完成的状态修改并返回诊断，该请求已消费，后续更新不会自动重试。Scene 在提交与本轮边界自动按声明顺序更新对象，独立调用方也可显式推进。

十类合成命令及十四次对象更新取得 67 份状态／资源请求记录，与原入口逐项一致，覆盖默认值、大小写、空名、扩展名替换、类型门控、重复更新以及动画与排序顺序。两项纯合成回归固定银行空洞、类型跳过、未知命令保留、名称边界，以及脚本事件到画布像素、暂停、重复播放读取和失败后的请求消费；常规测试不依赖外部资源或设备。

## FES 媒体记录与来源包装

名称绑定、对象身份和声明记录分别维护。重复声明仍分配未绑定对象，已有名称／银行继续指向首次绑定；每条 CIMAGE／IMAGE／BUTTON 声明记录另分配独立图像包装，BUTTON 另保存各自创建的下层任务。对象上的当前包装与按钮编号由后一次准备覆盖，记录中的旧绑定继续保留。

Scene 按记录顺序查询当前对象并更新，重复记录共享该对象的来源／属性／排序标记。第一条记录消费请求后，后续记录不会重新装填自己的包装。IMAGE 和 BUTTON 的装载、图像登记、矩形尺寸回退及 Alpha 掩码使用本次记录的包装；CIMAGE 装填记录包装，却使用对象的当前包装登记显示。例如两次声明同一对象时，第一份包装有像素，最后一份可能仍为空，CIMAGE 因而移除该显示条目。这一差异按基线保留。

`Objects::media_records()` 提供每条记录的目标和绑定，`Object::image_handle()`／`task_id()` 查询对象的当前值，`image_handles()`／`button_task_ids()` 遍历其全部持有。显式 `Runtime::update_fes_record(owner, objects, index)` 使用记录包装；单对象 `update_fes_object` 使用当前包装。装载准备按记录保存完成状态，按钮创建失败前已经分配的包装在重试时继续使用，不再分配；重新绑定列表也不重新创建媒体。

删除时释放该对象的全部包装，并向全部下层按钮发送删除请求；图像条目按当前像素或原始来源身份反查后移出，避免删除已被其他来源覆盖的槽位。直接调用 `Objects::remove` 时，资源和任务由接收返回对象的调用者清理。所属任务实际回收仍释放其登记的剩余资源。

三类媒体的 36 次更新、6,600 字节完整命令／双包装状态／像素与原入口一致。列表 307 的 216 次查询、7,776 字节另确认有符号 key 次序、槽号转换、缺失与缓冲保留；库查询结果一致。纯合成回归覆盖上述重复声明、小画面、掩码、来源重读、覆盖槽位、删除和创建失败续跑，不依赖外部资源或设备。

## FES CIMAGE 更新

`Runtime::update_fes_object` 将 CIMAGE 的纯色来源接入共享列表。调用方先创建、初始化直属 owner 的类型 15 任务，再通过 `Objects::set_image_list(task, clip)` 保存任务编号及全局裁剪。绑定不使属性失效；切换列表也不迁移旧条目。更新入口核对所属任务与列表类型，`Object::image_handle()` 查询本对象的来源包装，底层像素仍通过 Images 查询。

场景装载为每条声明记录创建空包装；显式单对象更新在尚无包装时创建。后续只在来源重建标记存在时准备像素：读取持续 SIZE2，按实际尺寸重配，再按请求尺寸填充颜色。尺寸检查或分配失败清除本次重建标记，保留属性失效及旧像素并返回诊断。成功后，属性失效或来源重建都会进入登记阶段；POS2 在此时消费。空来源发送 287，已有像素且槽号不为 −1 时发送 286，随后发送 295。实际零尺寸像素属于已有来源。

## 绘图变换

`graphics::Transform` 保存基点、平移、缩放、弧度旋转及可选显式矩阵。默认基点为 `[0, 0, 5000]`，平移和旋转为零，缩放为一，矩阵为单位矩阵，dirty 为 false。属性由同名查询方法读取，`set_base_point`、`set_position`、`set_scale`、`set_rotation` 和 `set_matrix` 更新状态；`clear_dirty` 消费变更标记。

向量属性按浮点相等比较整组：全组相等时保留原值的位模式，任一分量不同才整组替换，因此正负零不会单独触发更新，NaN 会触发更新。显式矩阵按 16 个 DWORD 位模式比较，重复设置同一 NaN payload 不触发更新。`set_rotation` 即使角度相等，也退出显式矩阵模式；`set_scale` 保留该模式。

`matrix()` 为 `Identity × Scale × RotateX × RotateY × RotateZ`，显式矩阵模式则为 `Identity × Scale × matrix_override`。起始单位矩阵相乘保留非有限值的传播和求和顺序。旋转沿用原 x87 三角约化：有限大角度使用 66 位 π，NaN 保留符号和 payload 并置 quiet 位，无穷与超出 FSINCOS 范围的输入保留原异常结果。

`transform_point([x, y, z])` 只减去基点 X／Y，保留输入 Z，以 W=1 乘本对象矩阵，再加四维平移 `[px, py, pz, 1]`。普通仿射路径的结果 W 因而为 2。`transform_point_with_parent(point, parent)` 随后乘父级／绘图上下文矩阵，保留该 W，不执行 W 除法；父矩阵的平移同样受它影响。基点 Z 独立保存，不参与这一顶点变换。

12,981 组状态及 38,943 个完整变换后顶点已与原入口核对，有效属性、矩阵、dirty 和顶点结果一致。三项纯合成回归固定几何顺序、父级 W、正负零与矩阵模式、常规三轴旋转和非有限／大角度行为。该接口已用于二维对象属性和三角形查询；像素栅格化与帧提交继续实现。

## 绘图投影

`Projection` 接收绘图中心 `center`、摄像深度 `camera_depth`、最终平移 `translation` 和矩阵 `matrix`，以及已选择坐标组的 `coordinate_offset`／`coordinate_scale`／`coordinate_matrix`。默认中心、深度、偏移和平移为零，比例为一，矩阵为单位矩阵；实际配置由调用者提供，当前尚未从根对象自动装载。

`project_triangle(vertices, base_depth, origin, perspective)` 接收对象／父级变换后的三个顶点、对象基点 Z、已选择的投影原点及开关，返回 `ProjectedVertex { position, rhw, color }`。颜色原样保留，不自动裁剪，不隐式执行 W 除法。

关闭透视或顶点 Z 为正／负零时，先围绕中心应用坐标组缩放与矩阵，再加中心减坐标组偏移；此时 Z 独立改写为 `(65000 − (z + base_depth)) × f32(1/65000)`，坐标组矩阵不改变该 Z。最后乘最终矩阵，再加最终二维平移。矩阵乘法保留完整四维输入。

透视且顶点 Z 非零时，距离先按单精度计算为 `(65000 − base_depth) − camera_depth`。分母为 `z − distance`，两者浮点相等时改用一；二维比例为 `camera_depth / denominator`，负值钳为零。围绕 origin 处理后的四维顶点乘投影矩阵，其 Z 系数为 f32(1/65000)、W 系数为 `1 / denominator`。然后加 origin、减中心、应用坐标组缩放／矩阵，加中心减偏移，再乘最终矩阵及平移。RHW 参与后续矩阵的平移项，不能固定为一。

`Drawable::projected_triangle(index, parent, projection, origin, perspective)` 组合对象变换、父矩阵、颜色覆盖与上述投影；越界返回 None。它使用本对象的基点 Z，不用变换后顶点 Z 代替排序深度。1,266 组三角形的 75,960 字节完整投影顶点已与原入口一致，覆盖两条分支、两级矩阵、负比例、相等分母、正负零及非有限值。两项常规合成回归固定 RHW 平移、分支深度及图元组合；基础纯色三角形已接入 CPU 绘制，纹理与完整帧提交继续接入。

## 纯色三角形绘制

`Surface::blend_triangle(points, argb)` 接收三个二维画布坐标，绘制普通 Alpha 混合的纯色三角形。像素中心在整数坐标，顶点按 `floor(value × 256 + 0.5) / 256` 对齐八位亚像素，包含左／上边；绕序不影响填充，两三角形共享边只绘制一次。坐标非有限、对齐后退化、完全在画布外或源 Alpha 为零时返回 false 并保留像素。每个 BGRA 通道均按源 Alpha 混合，以 255 为分母并取最近整数；Alpha 通道同样应用这两个混合因子。该设备路径与普通图像 CPU 混合的舍入规则分别保留。

`RenderTarget::blend_triangle` 使用相同的全局顶点处理各面块，不提前平移并舍入顶点；缺失面块跳过，实际覆盖非零 Alpha 像素的块登记 dirty。返回值表示是否覆盖了存在的面块，原像素与混合结果相等时仍可返回 true。

`Drawables::render_triangles(target, projection, parent)` 按基点 Z 和登记顺序绘制，display 为零或空图元时跳过。每个对象最多提交前 32 个三角形；对象基点 Z 用于投影深度，平移 XY 作为投影原点。当前非纹理入口接入默认坐标组、普通混合及顶点颜色插值；特殊混合和需要近远深度裁剪的输入返回诊断。颜色不一致时要求有限的正 RHW，随后按透视权重插值。父矩阵与 `Projection` 由调用者提供；未实现深度缓冲、纹理、着色器或对象专属坐标组切换。

`DrawingContext::render_triangles` 保留模式零、enabled／active 和目标存在性门控；未开启时返回 false。`Runtime::render_triangles(projection, parent)` 使用运行时的同一份登记与绘图目标。调用者在更新完成后显式调用，负责清空目标和随后呈现；连续调用会继续混合当前像素。平面构造及创建矩形仍保持默认 display=0，当前显示开关由宿主通过 `Drawables::set_display` 提供，专属显示命令继续接入。

合成 KCS 已能通过普通 79／84 创建及移动矩形，经运行时绘图登记、投影和分块目标得到完整 BGRA 像素。四项常规合成回归覆盖共享对角线、Alpha 舍入、亚像素边界、空／非法输入、全局面块坐标、排序／可见性、提交上限、上下文门控及脚本到像素的串联。设备视口裁剪的边界差异见[验证记录](runtime-probes.md#纯色栅格化与设备像素)。

## 纹理与顶点颜色插值

`Surface::blend_projected_triangle(vertices)` 接收三个 `ProjectedVertex`，按其屏幕 XY 及 RHW 插值 ARGB，再作普通 Alpha 混合。`Surface::blend_textured_triangle(vertices, uv, texture, filter)` 另接收每顶点的归一化 UV、只读 BGRA8 纹理及 `TextureFilter::Point`／`Linear`，取样结果逐通道乘以插值后的顶点颜色。两种接口均返回是否覆盖非零 Alpha 像素；`RenderTarget` 提供同名接口，跨面块保留全局插值并标记实际覆盖的块。

像素覆盖沿用八位亚像素及左／上边包含规则。插值使用对齐前的顶点，以屏幕重心权重乘各顶点 RHW，再除以三个权重之和；UV 和颜色使用同一组透视权重。常量属性直接保留其值，计算使用 f64，取样、颜色相乘和混合之间不作八位整数舍入，最终写入 BGRA8 时取最近整数。

UV 的两个方向均采用镜像寻址，周期为二。点取样按 `floor(uv × size)` 选择 texel；双线性过滤以 texel 中心为半像素位置，按 `uv × size − 0.5` 混合相邻四个 texel。边缘的镜像 texel 重复，负 UV 和超出一个周期的 UV 同样有效。纹理为非预乘 Alpha，四通道都参与过滤、调制及源 Alpha 混合。

调用者显式选择点取样或双线性过滤，当前没有自动区分缩小／放大、mipmap 或各向异性过滤。空纹理、非有限 XY／UV、非有限或非正 RHW、退化及完全越界三角形返回 false 并保留像素；Z 不参与此核心的裁剪或深度测试。`Drawables::render_triangles` 已使用颜色插值核心，显式画布图元和独立帧提交见下文；矩形包装、图像对象的自动提交及设备呈现继续接入。

设备对照的固定 UV 与颜色插值案例共 528 组、33,792 个像素全部一致。其余 312 组变化 UV 中，315 个像素存在单通道一级差异，9 个点取样像素在 texel 选择边界附近选择不同 texel；CPU 核心固定上述 f64 计算规则，尚未复现设备过滤精度和选择边界的全部细节。具体范围见[验证记录](runtime-probes.md#纹理取样与透视插值)。四项合成回归固定镜像／过滤、非整数调制、RHW 对 UV 与颜色的作用、跨块插值、非法输入，以及 Drawable 到渐变像素的串联；默认测试不使用图形设备。

## 画布图元与独立帧提交

`Drawable::from_canvas(data, count)` 复制 count 条八十字节的画布三角形，保留前置 tag、面块索引、XYZ、ARGB 和归一化 UV。`canvas_triangles()` 返回原记录；None 为非纹理图元，Some 的空列表为已创建的空画布图元。初始颜色覆盖为白色且开启，原记录的颜色仍保留，关闭覆盖后参与插值。

|记录内字节偏移|字段|
|--:|:--|
|0／4|原前置 tag DWORD／按行排列的面块索引|
|8／32／56|三个顶点，各为 XYZ 三个 f32、ARGB u32、UV 两个 f32|

只读取声明数量的完整记录，后续字节忽略；记录长度与数量上限在分配前检查，总记录容量不超过 64 MiB。XYZ 边界以正／负一亿为初值，逐分量作小于／大于比较；零三角形保留这两个初值，NaN 不更新对应边界。它不改变平面任务的尺寸查询结果。

`transformed_canvas_triangle(index, parent)` 保留面块索引及 UV：顶点减基点 XY，Z 加平移 Z，乘对象矩阵，再加平移 XY 并减去半像素，最后乘父矩阵。这条路径保持 W 为矩阵运算的结果；其 Z 平移和半像素时点与非纹理图元分别实现。投影仍复用 `Projection`。

平面对象命令 83 以 `data[0]` 为数量、data1 为记录缓冲区，先移除旧登记再创建。普通 native 83 仍发送清除命令 68，与此对象命令分别解释。创建标志不门控此命令；成功时偏移、尺寸和图元类型保持旧值，新登记恢复默认显示、变换、混合及白色覆盖。零记录不访问输入缓冲区，仍登记空画布图元；删除门控先于输入访问，释放及命令 3／68 清理登记。

`Drawables::render_frame(output, canvas, projection, parent, filter)` 按相同的显示与稳定排序规则处理纹理及非纹理图元。canvas 只读，其面块按原索引取样；索引越界或缺失面块相当于未绑定纹理，使用顶点颜色绘制。纹理三角形按原顺序全部提交，非纹理对象仍只提交前 32 条。过滤显式选择点取样或双线性，特殊混合和深度裁剪继续诊断。

`Runtime::render_frame(output, projection, parent, filter)` 以当前 `drawing().target` 作为画布输入，要求画布已配置。这是显式帧提交接口，由调用者决定调用时点、输出清空与呈现；绘图上下文的 enabled／active 门控继续用于图像写入和旧的 `render_triangles` 接口。连续提交继续混合已有输出，画布及其 dirty 标记保持原样。旧的 `render_triangles` 不具备独立纹理输入，遇到可见的非空画布图元返回诊断。

120 组显式画布图元的已定义状态、原始及变换后记录共 409,920 字节与原入口一致；32 组原整帧入口的 8,192 字节像素一致。合成回归覆盖数据布局与上限、纹理变换顺序、对象替换及删除、缺失纹理、超过 32 条的提交、混合图元排序，以及真实 KCS 的图像创建／填充／画布复制／释放／颜色覆盖到独立输出。命令 41 的对象包装见下文；显示与输入联动及设备呈现仍待接入。

## 画布几何切割

`CanvasLayout::new(tile_size, grid, step)` 指定单块纹理尺寸、面块网格和切割步长。步长必须为正且不超过对应单块尺寸；每轴的细分数使用整数除法。布局独立于像素，缺失面块仍能生成几何。`triangulate(source)` 接收已完成源对象变换的三角形，输出供纹理包装使用的 `CanvasTriangle`；输出尚未施加包装对象变换或半像素偏移。

输出依次按源三角形、网格行、网格列及扇形三角形排列。tag 为源三角形序号；Z 固定为零，颜色取源首顶点。包围盒先向零截断到 i32，再作整数矩形相交检查，因此完全位于同一整数坐标格内的窄图形可能不产生任何记录。实际交点保留 f32 运算与去重规则，不将相邻源三角形合并。UV 使用画布坐标与对应纹理块的原点、尺寸换算，共享边在相邻块内分别为一和零。

基线在计算面块行号时也使用横向细分数作除数。本接口保留这一规则；横纵细分数不等时，结果可能引用下一行面块并产生负 UV。调用者如需普通逐块切割，应令 step 等于 tile_size。

非有限 XY、超出有符号坐标范围的布局、超过一百万个源／网格组合及超过 64 MiB 的输出均返回诊断。1,200 组原入口对照的 635,920 字节全部一致，覆盖负坐标、反向与退化矩形、小数交点、一般三角形及不等细分。两项合成回归固定跨块顺序与 UV、整数包围盒、面块行号及输入上限。

## 画布纹理包装

`Drawable::from_canvas_source(source, layout)` 接收非纹理源的所有权，保留其几何和独立变换，创建初始覆盖关闭的画布包装。它不接受已带纹理的源。包装保留源的声明边界，后续属性修改不更新该边界或平面任务的原始尺寸。

源几何变化后，`prepare_canvas()` 先应用源变换，再按画布切割并生成 UV，最后从输出 XY 减去源平移。因而源平移改变取样区域，包装平移改变屏幕位置；包装属性修改不触发源重新切割。源 Z 在切割输出中归零。`geometry_transform(source)` 查询所选层，显式画布记录选择源时返回 None。登记后的对象可通过 `Drawables::prepare_canvas(id)` 手动准备；`render_frame` 自动准备可见对象，隐藏对象保留待处理的源变化。直接读取 `canvas_triangles()`／`transformed_canvas_triangle()` 前，由调用者完成准备。

CPU 路径直接计算变换后顶点，首次绘制也遵循上述契约。原入口只构造后直接提交时可能读取未初始化缓存；实际启动链中缓存失效和首次更新的自动调用次序仍待核实。240 组对象的四阶段对照中，除 28 个源参数临时 W 未初始化引发的正负零 DWORD 差异，其余 1,108,128 字节一致；本接口的源属性按三个分量比较，相等时保留整组原值。准备缓存后的另 32 帧共 2,048 像素中，24 个点取样像素存在差异，双线性帧全部一致。具体记录见[纹理包装验证](runtime-probes.md#画布纹理包装的属性与整帧对照)。

## 当前绘图目标

`RenderTarget::new(size)` 创建一块零初始化的 CPU 渲染面。`from_tiles(tile_size, grid, tiles)` 接收按行排列的等尺寸面块，`None` 表示缺失槽位。总尺寸为面块尺寸乘列／行数，`size()`、`tile_size()`、`grid()` 和 `tiles()` 提供只读查询。布局必须精确匹配，总像素容量最多 64 MiB，槽位最多一百万个；允许空尺寸。

`pixel(x, y)` 按整个目标的顶端起始坐标查询原始 ARGB，越界或缺失槽位返回 `None`。`clear_rect(rect)` 将相交且存在的面块局部区域全部清零，包含 Alpha，并将对应块的更新标记设为 true；即使该区域已经为零，仍登记更新。`dirty_tiles()` 查询标记，`clear_dirty()` 在呈现宿主消费更新后统一清除标记，像素保持原样。矩形端点沿用 `Rect` 的 i32 回绕及空区域规则。

`RenderTarget::copy_image` 提供普通 115 的全局源坐标和行方向规则，逐块裁剪、跳过缺失块，并标记实际写入的块。

`DrawingContext` 保存 `mode`、`enabled`、`active` 和可选 `target`。`clear_rect` 与 `copy_image` 只在 mode 为零、enabled 与 active 均为 true 且目标存在时执行；其他情况跳过。默认上下文两个开关均关闭、没有目标，由绘图调度宿主设置。`Runtime::drawing()`／`drawing_mut()` 提供当前上下文，普通任务在该上下文上同步操作；对象更新和设备呈现尚未自动切换这些状态。

普通 117 的首参为零时，只读取零句柄、x、y、width、height 五项，清零当前绘图目标。可以传入五项，也可保留第六项，后者的颜色被忽略；未开启绘图或没有目标同样以状态 2 继续，操作栈原值保留。目标坐标从顶部起算；非零图像句柄分支继续从底部起算并写入第六项的原始 ARGB。

普通 8 查询的配置渲染尺寸由宿主单独保存，不随当前目标绑定改变。CPU 渲染目标不执行设备锁定；设备创建、锁定失败和呈现仍由后续平台接入实现。

2,304 组完整 117 调用核对上下文模式、两个开关、缺失目标、缺失面块、跨块裁剪、空／回绕矩形和三种颜色。状态、返回槽、全部像素／保护区、面块标记及锁定／解锁次数一致。紧邻不可读保护页的五参数数组另外确认零句柄分支不读取第六项。四项常规合成回归验证布局、清除、状态门控及真实 KCS 的共享目标操作，覆盖五／六参数、两种预算、无目标和配置尺寸独立性。
