# 图像与像素接口

适用基线为 Windows CatSystem2 **2.6.1.90**。图形模块复用现有资源读取及 HG-3 元数据，开发顺序见 [GOAL.md](../GOAL.md)，子系统边界见 [设计文档](subsystems.md)。

## HG-3 帧解码

`hg3::decode_frame(bytes, id)` 接受完整 HG-3 文件及带原始位模式的 i32 帧 ID，返回 `Result<Option<DecodedFrame>>`。缺失 ID 返回 `None`，结构、压缩流或编码错误返回诊断。按文件顺序选择第一个匹配 ID，与元数据查询一致。

`DecodedFrame` 保存 `id`、完整 `StandardInfo`、`attributes` 和 `pixels`。像素按从上到下、每行从左到右的 BGRA8 紧密排列，行跨度为裁剪宽度乘四；Alpha 保持独立通道，不预乘、不因 Alpha 为零而清除颜色。

`Frame::attributes` 与 `DecodedFrame::attributes` 按 u16 编号保存五个原始 DWORD。小写 `ats` 标签后的编号使用引擎整数前缀规则，取低十六位；支持符号与十六进制，不接受前导空白和十进制小数。重复编号保留最后一条记录，正文取前二十字节；短记录返回诊断。`Image::attribute(id)` 查询同一属性，编号同样截断到低十六位，未找到返回 `None`。

像素只包含裁剪区域。`info.offset`、`canvas_size` 和 `base` 继续交给绘制宿主组合，解码时不扩展到完整画布，也不将偏移或基点加到像素位置。

当前接受 HG-3 0x300、低有符号 16 位位深为 32、覆盖完整裁剪高度的 `img0000` 原生编码。尺寸必须非零，可见像素及完整游程缓冲分别最多 64 MiB。其他位深、切片、JPEG 和 WebP 返回未支持诊断；`Metadata` 仍可单独读取其支持的标准字段。

原生数据通过独立 Zlib 数据／命令流还原，命令按低位先读、正整数 Gamma 长度执行交替复制／清零游程。命令声明的完整输出长度须四字节对齐且至少覆盖可见像素，可以包含填充；游程复制数据的解压长度也可超过可见像素长度。位平面按完整游程长度的四分之一分组，再按帧宽高还原可见部分的有符号差值及行内／行间预测，保持字节回绕。填充不扩展输出尺寸。短于可见像素、超过存储上限、未对齐、游程越界或截断均返回诊断。

## 对照与使用约束

72 份合成图像的 34,384 个像素，以及 32 份实际图像的 33 次帧请求，均按原解码对象的逻辑行顺序逐字节核对；几何字段同时核对。原对象内部倒序存行，公开解码接口使用从上到下的顺序。

常规回归使用固定合成游程数据，覆盖位重排、正负差值、行方向、独立 Alpha、负位模式 ID、缺失帧和完整元数据；另检查尺寸溢出、损坏压缩流、截断／越界游程及未支持编码。原引擎和实际图像不参与默认测试。

7,004 份图像、14,225 帧的结构盘点发现 396 帧使用超过可见区域的 1 KiB 游程缓冲，其中部分帧的复制数据解压长度也超过可见像素长度。125 组原解码调用集中覆盖填充、不同可见尺寸、全零／非零数据、八份实际填充帧和三个未对齐输入；2,582 个像素、完整几何及三次失败结果与实现一致。常规回归保留小尺寸的固定填充案例，并检查短缓冲、未对齐和分配上限。

资源名称补全和文件读取由资源宿主完成，解码器只访问传入字节，不访问归档、文件系统、窗口或 GPU。

## HG-2 存档图像

`hg2::encode_frame(size, pixels)` 将顶端起始的完整 BGRA8 图像写成单帧 HG-2 0x25，裁去透明边界并保留原画布尺寸；完全透明的图像保留最多 2×2 的空区域。透明像素的 RGB 清零，基点和帧编号为零。

`hg2::decode_frame(bytes)` 返回同样的 `DecodedFrame`，保留裁剪尺寸、偏移、画布、Alpha 标记和基点。当前支持单帧 32 位数据；其他版本、位深、多帧以及损坏的数据返回诊断。编解码只访问传入字节，不依赖文件或图形设备。

## 基础渲染面

`graphics::Surface::new([width, height])` 创建零初始化的 BGRA8 像素缓冲区。`from_bgra(size, pixels)` 接收已有像素的所有权，可使用解码帧的像素；长度必须恰好为宽乘高乘四。几何元数据继续由图像对象保存。

渲染面从上到下存行，左上角为 `(0, 0)`，行跨度为宽乘四。`size()`、`stride()`、`bounds()` 提供布局，`pixels()`／`pixels_mut()` 提供固定长度的像素视图，`pixel(x, y)` 返回原始 ARGB DWORD，越界返回 `None`。任一维为零时允许空渲染面；尺寸必须可由正 i32 坐标表示，总像素长度最多 64 MiB。

`clear(argb)` 覆盖整个缓冲区。`fill_rect(rect, argb)` 与渲染面边界相交后覆盖区域，返回是否存在非空目标。两者将 ARGB DWORD 按小端写为 BGRA 字节，保留全部位模式，包括 Alpha 为零时的颜色。

`fill_rect_from_bottom(rect, argb)` 接收原图像对象从底部起算的 Y 坐标，先按原尺寸裁剪，再换算为顶端起始的渲染面行。这是普通 117 非零图像分支所需的坐标适配；该分支覆盖原始 ARGB，始终以状态 2 继续，保留返回槽。2,640 组完整 native 对照的状态、返回槽和带保护区的缓冲区全部一致。

`copy_from(source, rect, at)` 将源矩形映射到目标左上位置 `at`，同时裁剪源和目标边界，并保持请求的相对位置。它直接复制全部 BGRA 位模式，返回是否复制了非空区域；源和目标必须是不同渲染面。

`blend_from(source, rect, at, opacity)` 提供基线普通 32 位 Alpha 绘制，透明度为 0～255。源和目标矩形先分别与各自边界相交，再取两者共同宽高；左上裁剪不会让另一端同步平移。`rect` 的宽高按 i32 回绕端点差生成目标矩形。返回是否存在非空绘制区域，源和目标必须是不同渲染面。

普通混合保持引擎的整数舍入：有效源 Alpha 为 `opacity × (source_alpha + 1) >> 8`；半透明目标使用独立 Alpha 权重及整数倒数，低 Alpha 下可能得到黑色，两个半透明白色像素也可能得到略低于白色的结果。全零目标可保留有效 Alpha 为零的源 RGB；绘制区域左右各一格的全零邻接像素同样接收边缘源 RGB，Alpha 继续为零。透明度为零时仍执行这些颜色写入，已有非零 RGB 或 Alpha 的透明像素保持原值。

`Rect { left, top, right, bottom }` 包含左上边，不包含右下边。`Rect::from_xywh(x, y, width, height)` 用 i32 回绕加法生成端点；反向边界不交换，交集为空时跳过。`intersect(other)` 返回可选的非空交集。

2,640 组原像素填充入口对照覆盖四种尺寸、110 组矩形和六种颜色，返回值及带保护区的完整缓冲区全部一致。对照使用相同的缓冲区行序；原图像对象的倒序存行由其对象适配处理。普通 117 的两条路径已接入运行时，窗口呈现继续开发。

普通混合另外核对所有 256 × 256 种源／目标 Alpha、三种颜色分布、六种全局透明度及两种 CPU 路径，共 2,359,296 个像素；1,296 组矩形对照覆盖两端裁剪、空矩形、透明边缘和完整保护区，全部一致。常规回归只保留固定合成像素及裁剪案例，不依赖外部引擎或图像资源。缩放、翻转和特殊混合继续单独接入。

## 图像对象与名称

`graphics::Image::from_frame(frame)` 将一个 `DecodedFrame` 转为图像对象，保留帧 ID 和全部元数据。`id()`、`info()` 和 `surface()` 提供查询，`pixels_mut()` 允许原位修改固定长度的像素；`fill_rect_from_bottom` 提供普通 117 的填充坐标。像素尺寸和长度须符合渲染面约束，位深的低有符号 16 位须为 32。

`Image::new(size)` 创建普通 112 使用的 BGRA8 空白图像，全部像素清零；帧 ID、偏移、画布尺寸、基点和 Alpha 标记均为零。画布尺寸保留零值，宽高只写入像素尺寸。允许任一维为零，尺寸和存储上限沿用 `Surface`。

`graphics::ImageReference::parse` 专用于普通 111。它以首个冒号定位帧号，从名称末尾逐字节查找最后一个扩展名，先移除扩展名、读取帧号、在原冒号处截断，再替换扩展名。目录分隔符之后的句点才参与扩展名识别；这些步骤按原字节位置执行。十进制数值前缀若紧接句点，帧号为零；十六进制前缀保留整数。无冒号时原样保留名称并选择帧零。名称以首个零结束，长度须小于 260 字节。

|输入|资源名称|帧号|
|:--|:--|--:|
|`a:3.hg3`|`a.hg3`|3|
|`a:3`|`a.`|3|
|`a.hg3:4`|`a.hg3:4`|4|
|`a.b.c:3`|`a.c:3`|3|
|`a:7.gz.hg3`|`a.hg3`|0|
|`a:-0x10.gz.hg3`|`a.hg3`|−16|

这一名称规则与 FES POS2／SIZE2 的 `fes::ImageReference` 分别保留；两者使用不同的原入口。

## 普通 111 的装载与合成

`Images::load(owner, names, services)` 接收已经完成 KCS 格式展开的名称列表，按 ASCII 空格拆分并忽略空段；制表符和换行留在名称中，引号没有分组作用。每段解析后经 `ResourceServices::resolve(b"image", name)` 补全，再以 `LooseFirst` 读取完整资源。缺失文件、空文件及缺失帧跳过；结构损坏、未支持编码和资源服务错误返回诊断。

第一个成功解码对象成为目标，后续对象依序通过 `Image::composite` 合成，处理后释放。首图的裁剪尺寸、偏移、画布、基点和帧 ID 始终保留。全部缺失时返回零；成功时分配非零递增句柄。`get`／`get_mut` 查询该对象，失效句柄返回诊断；`release_owner(owner)` 释放该任务持有的全部图像，句柄不复用。每个图像的像素最多 64 MiB，存活图像最多一百万个。

`Images::default()` 使用独立编号源；与其他资源存储组合时使用 `Images::with_handles(handles)` 共享 `HandleAllocator`。Runtime 已自动共享图像、原始数据、XML 及脚本集合的编号源，各类型查询仍分别检查对象是否存活。

合成保留基线的特殊规则：全局透明度为零，使用普通 32 位混合，因此只向全零目标写入透明 RGB，包括左右邻接像素。目标可见性先由“源偏移加目标尺寸”与目标全局矩形求交，源使用自身完整局部区域；目标起点换算为裁剪后的局部位置，两端独立裁剪，再按底端起始的内存坐标转换至公开像素行。负偏移不会同步移动源起点。这一操作不扩展首图画布。

`Runtime::set_resources(services)` 配置拥有的同步资源服务，普通 111 随后装载并以状态 1 压入句柄；`Runtime::images()` 可读取结果。普通 117 接受该句柄及 x／y／width／height／ARGB，以状态 2 填充并保留操作栈上的原值。任务实际释放时回收其图像；仅设置删除标记时图像继续存活。原始数据 365／366 的句柄属于另一接口，不能传给 117。

每次成功装载独立创建图像；额外绘制使用者可共享持有同一对象。资源管理器缓存及特殊混合仍待接入。

301 组名称／帧号、400 组完整 native 合成调用（其中 107 组进入绘制），以及 432 组保留对象创建、HG-3 解码、合成和释放的完整装载调用全部一致。后者核对 206,304 个像素、几何字段、资源请求和持有列表。常规四项合成回归覆盖名称重组、几何与行方向、缺失跳过、句柄寿命，以及真实 KCS 的装载／填充与两种预算续跑。

## 空白图像与显式释放

`Images::create(owner, size)` 无需资源服务，创建空白图像并分配与 `load` 同一序列的句柄。普通 112 接受 width、height 两项，以状态 1 返回该句柄；零尺寸同样创建非零句柄。超过库的尺寸／容量上限时返回诊断。

普通 114 使用 `Images::release_for(caller, handle)`，解除调用任务的匹配持有登记，并释放一个引用。其他任务调用时仍减少引用，原任务的登记继续保留。`release(handle)` 解除所属任务登记并释放一个引用，供独立调用者使用。两者均跳过零句柄，非零失效句柄返回诊断；后续句柄不复用。114 接受一项，以状态 2 继续且保留操作栈原值。

`retain(handle)` 为额外使用者增加一个引用，`release_reference(handle)` 配对释放且保留任务登记。最后一个引用释放后句柄失效；`release_owner(owner)` 只释放尚有登记的任务引用，可以重复清理。共享使用者持有期间，显式释放或任务回收后仍可查询和修改同一图像，修改对其他使用者立即可见。

`Images::share(handle)` 创建没有任务登记的独立包装，并共享原像素与几何；调用方须显式释放新包装。源包装的最后一个引用释放后，源句柄立即失效，新句柄继续有效。它与 `retain` 保留原包装的行为分别提供；两个包装指向同一像素时，115 仍按同图重叠顺序即时读写。

`pixel_handle(wrapper)` 查询当前绑定的底层像素句柄，不增加引用。包装与像素使用共享编号源分配不同句柄，不能互换；像素句柄在至少一个包装持有时有效。原包装释放后，其他包装或列表条目仍持有的像素句柄可继续登记。

`Images::recreate(wrapper, size)` 保留包装及任务登记，按空白图像创建路径重配像素。基线只在宽高均不同时替换像素；任一轴相同就保留原尺寸、像素、几何和 Alpha 分类。替换后绑定新的全零图像，旧像素由其他包装继续持有。库的尺寸检查或分配失败保留原绑定。该路径用于 FES CIMAGE 的纯色来源准备，后续矩形填充仍按实际像素尺寸裁剪。

`Images::create_empty(owner)` 创建尚未绑定像素的包装，`pixel_handle` 返回零；`get`／`get_mut` 返回诊断。首次 `recreate` 分配像素，包括 `[0, 0]` 请求；后续才应用任一轴相同即复用的规则。`share` 共享调用当时的像素绑定，空包装的独立副本仍为空，后续重建互不改绑。引用及任务回收规则与普通包装相同。

20 组完整创建／释放对照覆盖宽高分别为零和不同非零组合，全部几何、初始像素、状态、返回槽及持有列表一致。常规合成 KCS 回归串联 112 创建、117 填充、115 图像混合、114 释放及任务回收，覆盖零尺寸和两种预算；释放、空源与失效句柄检查复用现有生命周期回归。

CIMAGE 的十三阶段纯色来源核对 496 字节完整像素和实际尺寸，确认单轴复用、双轴重建及零尺寸组合。一项合成回归另固定旧包装共享像素的继续存活、重建后的独立编号和失败保留绑定。

## 独立图像资源

Runtime 接入普通 710 装载及 733 创建的独立图像资源。资源句柄、普通图像包装和像素句柄使用同一编号源，分别检查类型，不能互换。733 接收宽、高，以状态一返回非零句柄；任一轴为零仍创建资源，像素和几何元数据清零。

710 接收名称格式字符串的 VM 地址，以状态一返回资源句柄或零。名称先展开格式，在全局 Unicode 模式下从 UTF-8 转为 CP932，再按 `image` 类别补全；之后才按普通 `ImageReference` 规则提取帧号。无效起始地址、空名称分量、缺失／空文件或缺失帧返回零，不分配资源句柄；资源服务错误、无效编码及容量超限返回诊断。静态 HG-3 来源保留裁剪尺寸、偏移、画布、基点、Alpha 标记和属性表，生命周期沿用 733。

入口先去除扩展名，再用逗号拆分并忽略空分量，只有一个分量时仍以补全后的完整名称装载。因而 `art,1.hg3` 进入组合路径，`art.hg3,1` 按完整名称请求普通文件；空格和制表符不拆分来源。单图路径优先检查同名 ANM；存在时从对应 HG-3 多帧缓存取最小无符号 ID 的初始画面，普通静态来源仍按显式帧号查询。名称须小于 260 字节，拆分后的临时表最多 256 字节，附加分量最多 64 项。

静态组合以第一个分量为名称前缀，后续分量各取首字符，在前缀和下划线之后补上与层序对应数量的零，再追加字符及扩展名。例如 `art,1,2,0,a.hg3` 依次读取 `art_1.hg3`、`art_02.hg3` 和 `art_000a.hg3`；零字符层跳过但占用层序，缺失层继续读取后层。每层先检查同名 ANM；有伴随动画时取缓存初始画面，其他层选择帧零。伴随动画默认暂停，空或无效伴随数据不改变初始画面；当前独立资源提供该静态快照，资源层的动画启停接口尚未接入。

`Image::from_layers(layers)` 合成已解码的静态图层，返回裁剪矩形的并集，画布尺寸逐轴取有效尺寸的最大值，基点取首个成功装载层。各层按首层基点对齐并裁剪到输出范围，属性由后层覆盖同编号记录；输出帧 ID 和文件 Alpha 元数据清零。全部裁剪矩形为空时返回 None。组合资源的 Alpha 分类由最终像素扫描，单图资源继续使用文件标记。

## 图像列表的重绘与脏区

`ImageList::new(owner, size, images)` 创建独立的全透明自有图像，并使用一个完整面块。`new_tiled(owner, size, tile_size, images)` 配置横纵步长；基线以横向配置计算面块高度，纵向步长仍使用纵向配置，非正方形配置可能产生重叠区或间隙。来源、列表自有图像和共享画布分别持有；`image()` 返回自有图像包装。列表与传入的 `Images` 存储配对使用，所属任务释放后应停止使用该列表。

`set(key, source, properties, images)` 接收普通图像包装和 `ImageListProperties`。新条目为来源建立独立包装，已有条目保留自己的包装并替换来源。释放来源包装不影响已登记条目，像素修改仍相互可见。`key(sender, slot)` 按 `(slot << 16) | sender` 打包，不先裁去 sender 的高位；默认优先级取 key 的高 16 位，绘制先按有符号优先级、再按无符号 key 排序。同一 key 的再次登记替换旧条目。

`set_pixels(key, pixels, properties, images)` 直接接收底层像素句柄，与命令 286 的第一来源对应。它同样建立独立包装，拒绝普通图像包装及其他资源句柄；`set` 先查询包装绑定的像素，再执行这一登记。

`Image::set_alpha_mask(channel)` 控制图像作为列表来源时的 Alpha 掩码。零使用普通合成，一至四分别选择来源 B、G、R、A；其他值返回诊断。掩码保持目标 RGB，只按 `((目标 Alpha + 1) × (来源通道 + 1) − 1) >> 8` 更新目标 Alpha，不叠加条目透明度。条目不可见或透明度为零时仍跳过。此属性由共享像素保存，FES 图像属性刷新时应用 `MASK`；它与输入区域的命中掩码分别处理。

`set_resource(key, resource, properties, images)` 使用独立图像资源，供 286／288 的第四来源及 DIFIMAGE 共用。条目额外持有资源；替换、移除、清空和释放列表时解除持有。可见登记消费共享更新标记，动画推进阶段按有符号 key 顺序读取并清零该标记、刷新资源几何和基点。刷新本身不产生脏区；单独处理资源像素后，需要重新登记或其他失效操作才重绘。后续条目和列表读取已经清零的共享标记。

当前支持无变换来源，位置的 Y 从自有图像底部起算，像素查询仍按顶部起算。位置和基点分别转为 i32，再以回绕算术计算 `position - base + source.offset`。裁剪按来源与目标的对应位置进行；有效透明度为零或不可见时跳过。来源分类为不透明且有效透明度恰为 255 时直接复制，其他情况保留普通 Alpha 混合及左右全零邻接像素的 RGB 延展。自有图像同时作为来源时返回诊断。

`ImageListProperties::opacity` 保存完整 `u32`，调用方使用 `u8` 变量时需显式转换。无 ANM 时有效透明度就是该原值；有 ANM 时先按 u32 回绕乘以动画透明度，乘积小于 `0xff00` 时除以 255，否则取 255。实际混合按透明度低十六位建立字节查找表，有效源 Alpha 为 `(((opacity & 0xffff) × (source_alpha + 1)) >> 8) & 255`。因此原值 65536 仍执行绘制，可向全零像素写入透明 RGB；原值零直接跳过。不能在登记时截断为字节或统一钳制到 255。

Alpha 分类由共享像素对象保存。HG-3 装载时使用 `StandardInfo::reserved` 所保存的 stdinfo Alpha 标记：零直接分类为不透明，非零直接分类为使用 Alpha，像素字节原样保留。普通 112 的空白图像则在首次实际绘制非空区域时扫描像素。分类一旦确定，矩形填充保留旧分类；独立包装共享同一分类。完全位于画面外、不可见或透明度为零的来源不会触发延迟扫描。

`remove` 释放来源包装，将可见条目的历史区域标脏。`clear` 释放全部来源，立即清零自有图像并将全部面块标脏。`release` 同时释放来源与自有图像，可重复调用；其他包装仍共享的输出像素继续保留。全部包装登记到 owner，任务实际回收时自动解除这些引用。`set_offset` 只保存提交到共享画布的偏移，不修改自有图像几何或像素。

`dirty_rectangles()` 按面块顺序返回当前脏矩形。登记保留累计的几何边界，先使用来源基点更新中间边界，再应用请求基点；隐藏状态下也保留中间边界。`update(images)` 先清除所有脏区，再按条目、面块顺序绘制，成功后消费脏区并返回提交矩形。重叠区域因此可能重复混合；几何外的透明 RGB 可以留存至后续覆盖该位置的重绘。来源像素修改和输出偏移修改均不单独产生脏区，需重新登记或调用 `invalidate_all()`。`redraw(images)` 将所有面块标脏后更新。

`set_clip(key, rectangle, images)` 设置条目的全局裁剪矩形，并将历史边界缩至新裁剪范围。再次登记来源保留裁剪。相同矩形不标脏；不同的非空矩形先标记旧历史，再对可见条目标记裁剪后的历史。空矩形恢复完整视口并执行这一变化流程。`None` 直接恢复完整视口，不标脏，也不重新扩大历史边界；后续重新登记或改变显示状态时才重新计算边界。绘制范围同时受脏矩形和条目裁剪约束。

`Runtime::images_mut()` 提供同一图像存储。`update_image_list(&mut list)` 更新自有图像，并仅将返回的脏矩形按偏移复制到当前画布；`redraw_image_list(&mut list)` 重绘全部面块并提交整幅自有图像。上下文模式及两个开关门控提交，关闭时仍更新自有图像并消费脏区；重新开启后可显式整幅提交。结果可由普通 PLANE 画布纹理绘制到独立帧。类型 15 的首批命令与自动更新见下节；其他来源及变换继续接入。

1,280 组位置、基点、来源偏移、透明度及 Alpha 组合的完整自有图像共 245,760 字节与原入口一致；16 组双来源重叠确认默认优先级下的无符号 key 次序。两项常规合成回归固定裁剪、透明 RGB、直接复制、来源替换与释放，以及两种解释器预算下的 KCS 图像创建／原任务释放／列表合成／跨面块画布提交／FES PLANE 最终帧。

## 背景快照

普通 455 将列表目标和普通图像包装转为同一 302 命令，裁剪缓冲为空；零来源清除背景。普通 339 将 X、Y、宽、高转换为回绕的四端点裁剪缓冲，再发送 295；槽号继续按发送任务合并 key。462 以 0xffffffff 初始化优先级缓冲并发送 304，以状态一返回缓冲值；463、464、625 分别发送 305、306、301。零目标也正常路由，其余五种入口均以状态二保留返回槽。

663 和 880 的转发协议分别发送 314 的新宽高及 318 的八字节缓冲，两个目标命令已接入列表。288 组原入口命令包逐项核对八种转发的目标、发送者、标量／缓冲、返回值和完整 VM 两区。常规合成回归连接真实普通任务与列表，固定缺失优先级、返回槽、背景复制与来源释放后的像素寿命。

列表任务的 302 先移除完整 key 为零的条目，再复制来源并以默认属性登记到该 key，不合并 sender。来源是普通包装，快照具有独立像素；随后修改或释放来源不影响背景。全图复制保留来源几何，裁剪复制去除来源偏移并使用裁剪尺寸作为画布尺寸，右／下端超出来源时缩小至边界。负起点或反向范围返回诊断，起点在来源之外时保留旧快照；初次复制没有可用快照的路径返回诊断。复制沿用图像重建的单轴复用规则，裁剪保留复用像素的既有基点。

302 随后向列表的子平面发送 47，数据为零、来源是否非零、一。它不立即更新列表或提交画布；后续正常更新或 296／298 消费脏区。零来源只移出背景条目并隐藏子平面，保留快照包装。`ImageListObject::background_image()` 查询该包装，尚未创建快照包装时为 None；`background_active()` 查询是否启用。285 重建列表保留快照及启用值，297 清空后按该值重新登记背景，后续更新才绘制。

FES `baseimg [object]` 连接同一背景路径。CIMAGE、IMAGE 和 BUTTON 在命令执行时保存当前来源包装；PLANE 保存对象身份，消费请求时先更新共享列表、取其自有图像，再按平面的 VRAM 和 SIZE 裁剪复制。缺参或空参数清除背景；不存在的名称／银行直接继续，不遍历数组，其他已接入类型只结束本次脚本片段。额外参数忽略。

主体排队后先消费背景请求，再于同一逻辑帧继续脚本，中间不刷新 FES 媒体。系统块及对象处理器在该行结束当前片段，将背景变化留到下一次普通更新消费。失败和预算续跑保留已解析银行、来源及 PLANE 查询阶段，不重复参数副作用。

## 共享列表原始数据来源

命令 286 的第二来源接收完整图像原始数据对象。基线在登记时建立帧目录并解码各帧，初始选中无符号 ID 最小的帧；负数位模式按对应 u32 排序。重复 ID 保留首个匹配帧。`ImageList::set_hg3(key, bytes, properties, images)` 提供同一无变换登记；登记完成后可释放输入字节或原始数据句柄。解码错误保留旧条目，帧集合总像素受 64 MiB 存储上限约束。类型 15 任务通过 `Host::image_data` 同步借用第二来源的字节，包装宿主应转发该查询。

`select_frame(key, id, images)` 选择已缓存的帧并恢复其基点，缺失 key 或 ID 返回 false，保持当前来源。选帧本身不产生脏区，自动更新仍保留旧画面；重新登记或显式失效后才重绘。像素来源重登记保留帧缓存，并改绑当前选中帧的同一个包装，因此以后再次选择该帧时使用改绑后的像素。原始来源重登记替换全部缓存帧，删除／清空／释放列表或所属任务回收时解除其持有。

`set_source_identity(key, identity)` 只修改不增加引用的来源身份，零也可显式保存，不产生脏区；缺失条目返回 false。`find_source_identity(identity)` 返回匹配身份中有符号 key 最小的一项，零可匹配尚未指定身份的条目。来源重登记保留身份，删除条目后不再匹配。身份反查顺序独立于绘图排序；任务命令 308 返回 key 右移 16 位所得的槽号。十二组、六阶段、四种查询取得 288 份核心与任务输出记录，确认负 key 优先、重复身份、零身份、重登记保留及缺失时不写输出。

基线另存容器首帧的裁剪偏移和几何边界，当前绘制使用选中帧的裁剪偏移；可移植无变换接口尚未提供首帧专属几何查询。动画／控制命令与额外失效通知继续独立接入。

72 份单帧输入及四份含乱序、负数、重复和保留 ID 的多帧输入取得完整来源状态及列表像素。登记后将原始字节设为不可访问，后续绘制和列表析构均正常完成，76 组、84,816 字节输出与未保护时一致；这些普通 HG-3 输入的列表独立持有已解码帧。同组输入的 77,824 字节完整列表像素与可移植实现一致。两组十七阶段序列另核对来源互换、重新登记、选帧／缺失帧、隐藏／恢复及显式重绘：列表像素与脏区分别为 16,864 字节及 25,296 字节，均与原入口一致。两项纯合成回归固定帧排序、缓存改绑、失败保留、选帧不标脏、任务回收，以及真实 KCS 装载／显式关闭原始句柄后列表继续绘制。

## 列表动画与任务时钟

`ImageList::load_animation(key, bytes)` 将 ANM 绑定到已有条目；缺失 key 返回 false。装载成功初始化新的时间线和显示缓存；解析失败移除旧时间线，保留播放控制及旧显示缓存，此时绘制使用条目自身属性。装载本身不选帧或标脏。`animation(key)` 只读查询同一 `ImageAnimation`；解释和时间线契约见 [ANM](anm.md#图像对象的动画装载)。原始来源重登记保留动画并更新最大无符号帧 ID，同时请求下次实际推进重设时间基点；像素重登记保留原有帧缓存和动画。

`set_animation_time` 保存时间并更新现有时间线的 origin，`set_animation_playing` 保存原始播放开关；两者缺失 key 返回 false，设置本身不推进。`update_animations(now, budget, images)` 按有符号 key 次序逐项推进，返回是否整轮完成；`update_animations_with_random` 使用调用方提供的共享随机回调。预算按每个条目独立计算，续跑保留本轮时刻和游标，不重复已执行的随机副作用。`animations_pending()` 查询续跑状态；这期间来源、动画控制、裁剪、排序、显隐和绘制操作返回诊断，`release` 可以取消并释放整个列表。

整轮中的条目更新完成后才应用选帧，缺失帧保留当前像素。列表组合 ANM 的透明度和显隐；当前无变换类别零的几何与绘制仍使用条目自身位置，ANM 整数位移保留在动画状态中。动画变化后仅在新的有效显隐非零时标记旧历史和新几何；变为隐藏时旧像素保留，直到其他失效或显式重绘覆盖该区域。隐藏期间的帧变化继续参与后续几何历史。

`set_animation_variable(key, index, value)` 对应 318，只修改已经存在的时间线，不缓存尚未装载动画的变量请求，不立即推进、更新显示缓存或产生脏区。变量保留原始 32 位模式，后续指令执行时读取；重启保留变量，重装载动画重新初始化变量。下标范围为 0～63，越界及缺失目标均跳过。

透明度的 192 份完整列表图像、全部源／目标 Alpha 组合的 6,291,456 个混合像素及两种 CPU 路径，与原入口一致；512 组动画透明度组合、24 组尺寸重建的 96 份完整图像与脏区、25 次连续 ANM 变量写入也逐项一致。常规回归仅保留固定合成像素、脚本及运行时状态，不依赖外部引擎或图像资源。

## FES 图像预加载

`#PRELOAD` 的每行整体作为图像名称，按 image 类别补全后以 `LooseFirst` 读取原始字节；不计算表达式、不展开字符串，也不拆分空格、引号或冒号。多个声明段按源顺序合并。Runtime 在对象声明与属性初始化完成后、下层媒体创建之前执行预加载。

缓存属于当前 FES 场景，以补全后的完整名称字节区分大小写。重复名称仍补全并读取，缓存保留第一次成功读取的内容；缺失文件不登记，成功读取的空文件保存为空。`Objects::preloaded_image(full_name)` 查询该缓存，名称在首个零字节结束。预算耗尽或读取失败后继续准备同一场景，已完成行不重读，当前行已完成的名称补全不重复。

普通 IMAGE 文件、IDN=−1 的原始来源及 POS2／SIZE2 元数据查询共用缓存；PATHMODE 非零的直接图像路径绕过缓存。缓存只保存原始字节，像素解码仍在对象更新阶段发生。场景释放时回收缓存；已创建的原始来源、像素和共享列表各按既有持有规则继续存活。

## FES 场景推进

`runtime::fes::Scene` 保存预先装载的 FES 解释器、对象存储、等待期限及本轮推进状态。调用方绑定已创建的共享列表，并在所属任务主体时点调用 `Runtime::update_fes_scene(owner, scene, now)`。该入口自行消费定义、初始化、已注册的 SUBCOMMAND 声明、已接入的对象控制与 IMAGE 动画命令、`decode`、整数等待、根运动／指定对象／绝对帧等待、块末尾及退出事件。BASE 和三类图像对象的运动子命令已连接资源装载与队列；未知命令、其他声明、其他类型的运动及尚未接入的标签／音频完成等待返回诊断；对应未确认事件保留，先前已完成的脚本副作用不重复执行。

`wait n` 的数值参数小于一时统一等待一个逻辑时刻，普通块结束同样等待一个时刻。期限按 u32 回绕加法保存，以原始无符号大小判断是否到期；等待期间仍逐轮更新对象。期限落入 `0xfffffff9`～`0xffffffff` 时，执行器按保留值分派特殊等待；当前接入 `−1` 的根运动、`−2` 的绝对帧、`−4` 的指定对象、`−6` 的文字及 `−7` 的局部标志，其他保留值返回诊断。每轮向解释器发布 `_FRAME_`，基点为零时先取当前时刻减一，再保存当前时刻与基点的回绕差值；预算续跑保持本轮原时刻和帧值。

普通主体的 `decode` 对应内部提交事件 23：先完成媒体更新，再确认命令并在同一时刻继续脚本；等待或块末尾先推进运动，再完成本轮最终媒体更新。对象及系统处理器中的 decode 结束当前处理片段并排队提交，后续普通主体统一消费；DEFAULT 片段结束后仍进入对象自身处理器。普通 `exit` 发布通知后，在同一逻辑时刻继续下一语句；子程序返回位置保留。对象遍历按声明顺序展开各银行，在更新前解析当前名称绑定；重复声明保留重复记录，缺失银行跳过。来源装载、动画请求和排序继续沿各对象的既有更新入口执行。预算耗尽时保留更新游标，后续条目失败时也不重复此前已完成的条目。退出码在最终更新完成后可查询。

四类脚本的 28 份数值／期限／返回值记录在预算一和 4096 下均与原入口一致；另三组声明顺序和一组 decode 脚本确认重复记录、中途提交及同轮继续。三项纯合成回归覆盖时间冻结、等待恢复、块循环、未知事件保留，以及完整 FES 到动画画布像素。`Scene::prepare` 可单独完成装载期声明和属性；`Runtime::prepare_fes_scene` 继续创建图像空包装和 BUTTON 下层任务，两者均不执行 START 或更新媒体；纯合成回归覆盖这一边界及预算续跑。退出通知不停止脚本，后续 update 继续遵守等待与块循环规则。显式场景入口仍可由外层驱动；类型 34 的装载及任务树自动调用见下节，其他输入模式及声音联动继续整合。

## FES 运动与帧完成等待

`wait` 保存根运动等待，等待期间仍更新运动和媒体。检查到根子树没有活动运动时，先将期限改为零并完成本轮更新，再由下一轮继续脚本；即使最初没有运动也遵守这一时点。默认取消设置下，左击或跳过模式向根子树请求运动结束，不清空队列，也不立即继续脚本。运动脚本若忽略结束请求，等待继续。

`wait object[bank]` 保存对象名称与银行，银行表达式求值一次。省略银行时逐个查询现有银行及其子树，中间缺失银行跳过；任意银行仍活动就继续等待。检查到全部完成时在当轮继续脚本。默认取消设置下，左击或跳过模式可立即继续，且不向运动请求结束。若开始时目标不存在，命令改按数值表达式求值，结果小于一时等待一个时刻；数组银行表达式与这一数值回退分别沿解释器作用域求值。

`wait frame [value]` 等待场景 `_FRAME_` 达到原始无符号阈值，缺省零；它使用场景起点，不以命令所在时刻重新计时。已经达到阈值也先结束本轮，下一轮才继续。默认取消设置下，左击可中断普通期限和绝对帧等待，跳过模式单独可中断绝对帧等待；取消时向根子树请求运动结束。已经到期时直接继续。对象、系统处理器中的上述等待均结束当前片段，保留主等待期限和调用位置；已解析的目标及绝对帧阈值仍保存。

`wait privateflag index` 求值一次索引，后续只读取场景自身的 512 项局部变量；值为零继续等待，非零或无效索引在下一轮检查时继续。它独立于运行时普通局部数值区，点击和跳过模式不取消；缺少索引时退回一帧数值等待。局部处理器中的同名等待也会改写后续查询使用的索引。

当前对象等待以运动子树判断完成，IMAGE 的帧动画不参与这一查询。文字等待见[文字完成等待](fes-text.md#文字完成等待)；声音、标签等待继续接入。等待取消设置见下节。

## FES 等待取消与 keyskip

`keyskip` 从左至右处理参数，选项忽略 ASCII 大小写。每次命令先按开启取消、关闭 ctrl 和 cont 处理；`on`／`off` 设置取消开关，其他数值表达式按非零开启，后面的开关覆盖前面的值。`ctrl` 和 `cont` 在本次命令中置位；不带参数的 keyskip 恢复这三个默认设置。命令不结束对象或系统处理器，后续语句继续执行。

`force` 消耗紧随其后的一个数值表达式，缺省零；非零保存强制标志，并立即设置点击请求、进入跳过模式和写 `_CLICK_L_=−1`。零值只清除保存的强制标志，已经设置的点击请求和跳过模式继续保留。没有 force 的命令不改写该标志。`Scene::forced_key_skip()` 查询最后保存的强制标志，独立于当前输入模式；强制设置不改写 `raw_input()`。

`cont` 跨帧保留点击请求，普通瞬态命名值仍按原时点清理；后续 keyskip 不带 cont 时，普通模式的本轮收尾恢复点击清理。各等待分支使用不同的取消条件：

|等待|取消条件与行为|
|:--|:--|
|根运动|取消开关开启，且有点击请求或处于跳过模式时，请求根子树结束；继续等待运动响应|
|数值期限|取消开关开启且有点击请求时，请求根子树结束并继续脚本|
|绝对帧|取消开关开启，且有点击请求或处于跳过模式时，请求根子树结束并继续脚本|
|指定对象|有点击请求，且处于普通模式、ctrl 置位、取消开关开启中至少一项成立时，直接继续脚本；不请求运动结束|
|文字|与指定对象使用相同取消条件；只向首个忙碌银行请求显示完当前段，继续等待缓存归零|
|局部标志|不接受点击或跳过模式取消|

因此 off 会阻止普通期限和根运动取消；普通模式中的指定对象等待仍接受点击，而跳过模式下可由 off 阻止，ctrl 可再次放开该分支。已经到期的普通期限或绝对帧先按完成处理。

## FES SLIDER 属性核心

`fes::SliderState` 保存独立控件状态，不继承图像坐标和帧映射。初始文件、平面及元数据请求为空，矩形、数值范围、位置和方向为零，PRI 为 10，DISP 为零，ENABLE 为一，Alpha 为 255。所有请求标记初始为 false；原构造未初始化的范围请求标记在库中确定为 false。

初始化按 FILE、PL、POS2、PRI、DISP、ENABLE 的顺序应用。FILE 即使相同也请求重新装载；PL 仅在名称或银行变化时使对象及后代失效。POS2 保存资源名和帧号前缀，独立请求元数据更新。PRI 最后加 20：整数组初始化使用同一原值，显式银行初始化额外加具体银行号。DISP 即使相同也递归失效；ENABLE 保留原始数值，仅在变化时标记自身。POS、SIZE、COLOR 等图像列不改变此状态。FILE 最多 255 字节，平面名称最多 31 字节，位置资源名称最多 127 字节；错误保留已完成的属性修改。

`set_rectangle` 保存四个原始整数并请求属性更新。`set_range`、`set_position` 和 `set_alpha` 分别设置独立请求，相同值仍请求更新；范围允许倒序，位置不在此层裁剪，位置通知参数独立保留。`set_priority` 只保存原值加 20，不设置显示更新标记。直接修改公开字段时，宿主相应维护请求标记。

运动属性仅使用 DWORD 28 的高字节；其余 35 项及该 DWORD 的低 24 位清零。原始 Alpha 先取低八位再打包，回写取高八位，每次都请求 Alpha 更新，包括值未变化的情况。范围、位置、矩形与显示均不从该运动块回写。

对象表、初始化、数值命令和运动队列已接入。子命令换算使用零基点／位置／旋转／颜色和单位缩放，不把滑块数值或 Alpha 当作图像上下文。配置资源、下层任务创建和实际绘制已接入。父级 27／28 已连接数值回写及事件脚本。FES 媒体更新中的同步通知保留当前场景及内层修改。

BUTTON 的 `control` 独立保存可选名称／银行，`set_control` 或脚本 `attach` 建立关联。导航先搜索当前 KEYBLOCK，未找到目标时尝试关联 SLIDER，最后查相邻网格。横向滑块仅接收左／右，非零方向值表示纵向并接收上／下；每步按 i32 回绕增减一，结果须在有符号闭区间内。成功设置位置通知一并消费方向输入，不移动焦点。滑块自身 ENABLE 和 DISP 不门控这一分支；起始按钮必须启用且有非负 KEYBLOCK 编号。

### SLIDER 下层范围换算

`input::SliderControl` 与 FES 属性分开保存数值范围、像素行程、数值、像素位置和拖动状态。范围写入不调整已有位置；设置位置先按有符号端点作 max(min).min(max)，拖动中保留像素位置。

非拖动状态的像素换算使用 i32 回绕的范围跨度绝对值。数值小于等于零时，两种位置都设零；大于等于跨度时，数值设为跨度，像素位置使用行程终点。中间值按 `abs(travel_end - travel_start) * position * 100 / span / 100` 换算，各乘法保留 DWORD 回绕，两次除法分别向零截断。换算不减数值范围起点，也不加像素行程起点。

像素回读先计算 `step = abs(travel_end - travel_start) * 100 / span`，以 `step / 2` 为首个阈值；像素位置同样乘一百，达到阈值即增加一，再逐步增加阈值，最多到范围跨度。结果从零起算，不补范围起点。零步长时，非负百倍像素值直接返回非负跨度，负数返回零。除数为零、除法商溢出或超过查询上限返回诊断。

`input::SliderObject` 已复用这一核心连接媒体、按钮和任务消息。FES 媒体准备及更新已连接这一任务。

## FES SCROLL2 属性核心

`fes::Scroll2State` 保存滑动控件通用状态 `control` 和独立页长 `page`；`ObjectState::Scroll2` 支持对象身份、银行、父子、初始化、数值命令和 Alpha 运动。通用状态与 SLIDER 的默认值及属性写入规则相同。`set_page(range, page)` 原样保存两项范围及页长，并请求范围更新，不裁剪位置或页长。

FES 侧已连接媒体准备、更新、父级通知及暂停。InputFactory 已提供下层类型 41 的 Scroll2Object，连接状态图像、列表、输入及生命周期。

### SCROLL2 下层范围及几何

`input::Scroll2Control` 保存下层数值与尺寸，和 FES 原始属性分别维护。范围初值为 0～10，页长为 4；其他字段清零。轨道长度与最小滑块长度由资源装载设置，`rebuild_geometry()` 不移动数值或像素位置。

范围跨度使用 `abs(max − min)` 的 i32 回绕结果。跨度小于等于页长时，滑块占满轨道，行程终点等于起点；否则仅在跨度为正时，以回绕乘法计算 `track_extent * page / span`，再取与最小长度的较大值。最小长度可超过轨道，行程终点因此可以为负；此路径终点为 `track_extent − knob_extent`，不加行程起点。跨度非正且大于页长时，原几何保持。

`set_position` 先按原始 min／max 限制，拖动中保留像素。非拖动换算使用有效跨度 `abs(max − min) − page`，从零起算，不减 min：位置非正时两项归零；位置达到有效跨度时保存该跨度和行程终点；其余先计算整数步长 `(track_extent − knob_extent) * 100 / effective_span`，再以 `step * position / 100` 得到像素。两次除法的顺序保留，不能合并。所有乘减按 i32 回绕，除法向零截断。

反向查询以相同有效跨度和百倍步长按半步阈值递增，零有效跨度直接返回零。异常除法及超过查询上限的输入返回诊断。4,224 份几何快照、2,816 份位置快照与完整提交／输入区域路由、18,225 次像素查询均与原入口一致。常规合成回归覆盖比例、超过轨道的最小尺寸、退化跨度、运算顺序、拖动与半步阈值。

### SCROLL2 状态图像

`Scroll2Control::compose_images` 接收已解码帧表，用当前滑块长度和最小长度生成四种交互图像。第 s 组使用 `s * 100 + part`，s 为 0～3；part 0 为中段，1 为起端，2 为末端，3 为中央图案。三段按 1、0、2 排列，缺失段跳过。中段沿滚动轴的目标长度为 `knob_extent − minimum_extent`，非正时不绘制但仍推进拼接位置；两端保持原长度。横向高度或纵向宽度取该组三段像素尺寸的最大值，中央图案不扩大目标。

拼接使用底端起始坐标，三段来源偏移不参与。尺寸相同时直接复制；普通缩放以十五位小数步长采样，四个权重分别截断后求和。四个采样点的 Alpha 全零时保留原目标。任一轴缩小超过四倍时，以 f32 比例定位并对整数块逐通道取平均。当前已实现原入口的默认缩放配置，其他配置继续随平台图形配置核实。

中央图案按滚动轴的两项整数半尺寸之差居中，该轴的来源偏移归零，另一轴保留来源偏移；随后复用普通 Alpha 混合及透明邻接 RGB 延展。结果的偏移、画布尺寸、基点与 Alpha 标记均为零；来源元数据保持。非法目标尺寸或超出可表示范围的插值坐标返回诊断。

六类矩形和四个连续有效装载阶段形成九十六份图像，完整元数据及 9,558 个像素与原入口一致。常规回归仅构造内存帧，固定三段顺序、截断插值、透明颜色、偏移、不同状态尺寸和大比例缩小；下层任务已使用这些图像登记列表并处理交互。

## FES 对象运动

每个对象独立保存运动队列，BASE／DRAW 的基准保持队列默认值，CIMAGE／IMAGE／BUTTON 使用二维图像属性布局，SLIDER／SCROLL2 只捕获及回写 Alpha，SOUND 保存声像与音量。CPLANE／PLANE 使用下述完整平面属性。`Objects::start_motion` 接收已装载的运动 KCS 和已换算参数，按分组零追加；delay 是相对该运动起点的开始偏移，起点由队列首次更新登记。

平面的 `motion_properties()` 捕获基点 X／Y、独立优先级、三维位置、完整矩阵、三轴缩放、完整 ARGB、三轴旋转及显示。`apply_motion_properties()` 将 DWORD 5 回写为基点 Z，保留独立优先级；位置、基点和缩放的 W 归零，旋转 W 保留。每次颜色写入均使属性失效，包括原值未变时，宿主同时递归标记后代。运动不修改尺寸、重建请求或 PLANE 的 VRAM。后续媒体更新把保存的缩放和矩阵提交到下层绘图任务。

`subcommand_context()` 使用本地基点、位置、旋转、缩放和完整颜色，基点 Z 不换成优先级。CPLANE 的速度上下文为零，PLANE 使用自身 VRAM。上下文参数在捕获运动基准之前换算。

仅当目标和全部后代都没有活动运动时，启动前捕获对象的基准属性；否则沿用原基准。各帧从这一基准组合整条队列，运行期间直接改写属性不会替换基准。目标自身队列已清空但后代仍活动时，目标的新运动仍沿用旧基准。

`Objects::update_motions` 显式推进根对象子树，同级按对象标识顺序，子对象先于父对象；脱离根子树的对象不在本次遍历中。图像回写使用现有属性、来源与排序规则，父对象失效继续递归标记后代。全部运动停止后统一清理目标队列，运动编号继续递增。预算耗尽时保留遍历顺序、时刻、已完成对象和队列内部状态，续跑不重复消费随机数或更新已完成对象。调用方在运动完成后刷新媒体，并在整次续跑期间保持属性与宿主状态。

Scene 的普通主体在等待或帧边界自动推进运动，再刷新媒体；等待尚未到期的每轮仍更新运动。普通 decode 先刷新媒体并继续脚本，在最终边界统一执行本轮运动。对象及系统处理器加入的运动留到后续普通主体更新；该阶段与普通 KCS 共用随机序列及调试消息，媒体错误后的重试不重复运动。

已注册子命令逐银行换算参数并加入运动。资源服务按 mot 类别补全名称，场景缓存每个绑定的名称，Runtime 按忽略大小写的完整名称缓存成功装载的 KCS；类别映射在场景存活期间保持稳定。实例的 VM 数据独立。缺失资源跳过创建并继续脚本，后续调用仍可重新读取；读取错误保留当前银行已换算的参数，重试不重复其副作用。数组遇到缺失银行结束。oneshot／continue 均以分组零加入，使用目标当前保存的运动延迟。延迟初始为零；`object delay [value]` 更新后续插入时使用的原始 32 位偏移，不改写已有运动。`object ismot index` 将目标及后代的活动状态写入共享变量；尚未到开始时刻的运动也算活动。`object stop` 已接入；对象完成等待继续接入。

`object stop` 先向目标及全部后代的运动写入结束请求，再以零时刻按先子后父更新子树，最后只清空目标自身队列并将目标运动延迟归零。它不使用队列的独立 finish 入口；收到结束请求的延迟运动立即执行，elapsed 保留零时刻换算所得的回绕值。后代若忽略结束请求，仍继续活动，后代延迟也保留。Scene 在普通流程和对象／系统处理器中即时执行停止，媒体刷新仍按原边界进行；预算续跑保留已完成对象和当前银行。

## FES 系统键分派

9 的键槽 2／3 及大于 11 的无符号值按 SYSKEY 分派；0／1、4～11 仍走各自保留路径。先按普通按下规则保存当前焦点及原始输入，再按媒体声明顺序扫描 BUTTON。每条记录重新查询当前对象，ENABLE 非零、SYSKEY 不为 −1 且原始 32 位键值相等时，分派该对象的 PUSH_L。重复记录可重复执行同一对象；较早处理器对后续对象属性的修改立即影响扫描。SYSKEY 除 −1 外的负值也可匹配直接传入的原始键值，正常设备扫描使用 0～79。

所有匹配记录均执行，已有对象处理器不提前结束扫描。至少一个对象自身有处理器时跳过 95；仅有 DEFAULT 处理器仍回写默认响应。扫描后统一刷新媒体。该路径不把匹配对象设为焦点，释放仍使用按下前保存的焦点；10 不扫描 SYSKEY，系统键释放没有对应的 PUSH_L／RELEASE_L 配对。预算续跑和错误重试保留当前处理器、已完成的记录与汇总结果，已完成的处理器和响应不重复。

## FES 方向输入与指针定位

按下键槽 4～7 对应上／下／左／右。先保存本次按下前的焦点供释放使用，再寻找方向目标。当前焦点名称可解析时直接导航；否则即时查询指针，按媒体声明顺序查找第一个矩形命中 BUTTON，即使该按钮未启用。矩形使用取整的有效图像位置和当前请求尺寸，不叠加关联平面。TYPE 非零且存在当前图像包装时，还按局部坐标减图像裁剪偏移读取像素，Alpha 非零才命中；没有包装则接受矩形，包装没有可读像素时返回诊断。

没有当前对象且指针未命中时，直接选择有效、已启用的默认焦点；默认焦点无效则回写 95。已有或命中的对象先尝试网格导航。没有方向目标且源 BUTTON 仍启用时回写 95；源无效或禁用时尝试默认焦点，再失败则只刷新媒体，不回写 95。被关联控件消费的结果同样只刷新媒体。默认焦点选择不再进行第二次网格查找。

成功选择后立即保存新焦点，以目标句柄更新 `_PUSH_UP_`／`_PUSH_DOWN_`／`_PUSH_LEFT_`／`_PUSH_RIGHT_`，再计算指针目标并向输入 139 发送一步移动请求，最后刷新媒体，不回写 95。指针位置为有效图像位置取整后加缓存 keypos；关联 CPLANE／PLANE 的 EXPOS 非零时，再加有效平面位置取整值，不减平面基点。各轴按 i32 回绕，发送时只保留低十六位；输入对象继续执行逻辑范围检查。

移动请求由后续输入主体实际执行，方向命令本身不分派 FOCUS／UNFOCUS；后续指针选择更新按正常区域顺序触发它们。10 仍使用导航之前保存的按下目标。媒体错误或预算续跑保留已完成的方向发布和移动请求，因此其间其他命令设置的新指针请求不会被重试覆盖。

## FES 默认焦点与焦点锁

`button noact [value]` 把 BUTTON 名称和银行排队为默认焦点，其他已接入对象类型跳过。value 缺省不求值，存在时求值一次但不使用结果，其后的参数忽略。多银行对象必须显式选择银行，省略银行时整条跳过且不求值 value；单银行省略时选择零，显式无效银行不被改写。起始对象或具体银行缺失时改为整行表达式求值。命令不要求按钮当前启用，也不直接执行 FOCUS。

`lockactive [value]` 把原始整数排队为焦点锁，缺省零，非零值启用锁。在普通主体中处理通知后同帧继续脚本；在对象处理器或睡眠／唤醒系统块中结束当前处理器，后续语句本次不执行，主流程位置与等待保留。

两类命令与退出通知共用有序队列，处理器分派和专属暂停本身不消费队列。下一次已启动、未暂停的普通主体先推进控制器，再处理通知；普通主体中的命令在对应控制器执行边界生效。`Scene::preferred_focus()` 和 `focus_lock()` 查询最近已消费的值。默认焦点用于方向导航的回退。

## FES 对象控制命令

对象控制支持下列命令。`stop`、`arc`／`mcarc` 和图形对象的 `pos` 由 Scene 推进，后三者需要运动资源服务；其余由 `Objects::dispatch_object_command(interpreter, line, state)` 消费 `Event::Command`，返回 true 后确认事件，未识别的命令返回 false。Scene 的普通推进与睡眠／唤醒系统块均自动处理。目标银行与 `@` 事件对象沿用解释器作用域，命令阶段保存属性和更新请求，媒体修改在 `decode` 或本轮收尾的对象更新阶段提交；`getid` 当场写入共享变量。

|命令|缺省参数与当前类型行为|
|:--|:--|
|`object disp [value]`|缺省一，非零归一为一；CIMAGE／IMAGE／BUTTON 和两类平面在显示值变化时递归使后代失效，SLIDER 每次都递归失效|
|`object size [width] [height]`|两轴各缺省零；图像仅在尺寸变化时请求来源重建，平面每次请求重建|
|`object keypos [mode] [x] [y]`|各项缺省零；CIMAGE／IMAGE／BUTTON 保存导航定位模式和偏移，不设置媒体更新标记，其他已接入类型跳过|
|`object setid [number]`|缺省零；IMAGE／BUTTON 应用逻辑编号，遵循现有帧映射及有效范围，其他已接入类型跳过|
|`object getid [index]`|缺省共享变量编号零；读取具体 IMAGE／BUTTON 的逻辑编号，写入求值所得的共享变量编号，越界编号跳过写入|
|`object lock [value]`|缺省零；BUTTON 保存坐标锁，非零首次捕获位置，其他类型跳过；不设置媒体更新标记|
|`object enable [value]`|缺省零，非零归一为一；修改 BUTTON／SLIDER，变化时仅使自身属性失效，其他类型跳过|
|`object pri value`|缺少参数时跳过；图像使用值加 20 的优先级及独立排序标记，保留列表槽号；平面保存原值并递归失效，即使数值相同；SLIDER 保存值加 20，不设置失效标记|
|`object pos2 file [frame]`|缺少文件时跳过，帧号缺省零；CIMAGE／IMAGE／BUTTON 保存一次性位置元数据请求并递归失效，平面和 SLIDER 跳过|
|`object delay [value]`|缺省零；所有已接入类型保存原始 32 位运动延迟，负值按无符号回绕|
|`object ismot index`|缺少参数时跳过；将目标及全部后代的活动运动状态写入共享变量，越界编号跳过写入|
|`object stop`|Scene 即时请求子树运动结束并更新，随后只清空目标队列和目标延迟；额外参数忽略|
|`object arc [duration] [angle1] [angle2] [x] [y]`|第一项缺省 30、负值取零，其余各缺省零；两个角度转为弧度，六参数默认运动使用分组零|
|`object mcarc [duration] [angle1] [angle2] [x] [y]`|求值、换算及默认值与 arc 相同，使用分组一|
|`object pos [x] [y] [z]`|CIMAGE／IMAGE／BUTTON 设置本地 X／Y，两类平面设置本地 X／Y／Z；省略的轴使用当前坐标取整。SLIDER／SCROLL2 使用第一项原始位置，缺省零，通知为零；最多三项各求值一次|
|`object page [min] [max] [ignored]`|SLIDER 保存前两项原始范围；三项均求值，缺省零|
|`object getpos [index] [index] [index]`|图像返回本地 X／Y／零，平面返回本地 X／Y／Z，滑动控件返回原始位置／零／零；目的编号缺省 −1，越界跳过写入|
|`object getsize [index] [index] [index]`|图像和平面返回当前保存的宽／高／零，SLIDER／SCROLL2 返回当前位置／零／零；不触发资源读取或媒体更新|
|`object getpos2 [index] [index] [index]`|图像返回包含基点、裁剪偏移及图像父级的绘制位置／零，平面及普通文字返回沿允许父级累加的 X／Y／Z；不支持滑动控件|
|`object load [file] [ignored]`|SLIDER 保存文件并设置重新装载请求；第三词项按每个有效银行求值一次，后续词项忽略|
|`object pl target`|CIMAGE／IMAGE／BUTTON 保存平面名称及银行；引用改变时递归使后代属性失效，保留像素来源与优先级|
|`object attach [target]`|BUTTON 保存名称／银行，省略目标解除关联；目标存在性在导航时查询，字面名称 0 也保留|
|`object settbl [slot] [frame]`|两项各缺省零并求值一次，额外参数忽略；IMAGE／BUTTON 写入 0～31 的帧表槽，SLIDER 写入 0～3；越界槽忽略，负帧号按原始 DWORD 保存|

正常对象分派先求值目标银行，再按参数顺序各求值一次，随后遍历银行。多银行 `getid` 省略银行时整条跳过，目的变量参数也不求值；单银行自动使用零。其他命令省略银行时从零遍历至首次声明数量。`disp`／`setid`／`pri`／`keypos` 遇到缺失银行结束，其他类型跳过；`size` 遇到缺失银行或不支持类型均结束；`pos2`／`enable`／`lock` 跳过缺失银行及不支持类型，继续后面的银行。`delay` 遇到缺失银行结束，保留此前修改；`ismot` 对各银行子树的活动状态取或，但中途遇到缺失银行时保留目的变量原值。两者仅求值第一个数值参数一次，忽略额外参数。`stop` 跳过中途缺失银行并继续，目标银行表达式仅求值一次；停止逻辑由 Scene 提供，不属于 `dispatch_object_command` 的同步属性接口。

`pos` 及滑动控件的 `page` 跳过中途缺失银行；`load` 在缺失银行结束。多银行 `getpos` 省略银行时整条跳过，目的编号也不求值。具体目标的 `getpos` 先按顺序求值三个目的编号，再依 X／Y／Z 顺序写入；目的编号相同时后轴覆盖前轴。它读取对象当前本地坐标，不叠加父级、图像偏移或关联平面。浮点向零截断，非有限或超出 i32 范围时为 i32::MIN。BASE／SOUND／DRAW 的 pos／getpos 仍求值参数，随后跳过修改及查询写入。

`image load [file] [number]` 对 IMAGE 及其已接入派生类型保存文件请求，再应用逻辑帧编号（缺省零），沿普通图像更新装载像素。文件名遵循 FILE 的语言展开和空名称保持规则，编号遵循 setid 的帧表及范围规则。编号在每个有效银行求值一次，额外参数忽略；CIMAGE 只保留编号求值副作用，声音和滑动控件使用各自的 load 处理器。

`getsize` 在多银行省略银行号时直接跳过；具体目标先求值三个目的编号，再按宽／高／零依次写入，同一目的编号保留最后一轴。目的编号缺省 −1，越界跳过写入。VIEWPORT、BASE／SOUND／DRAW 求值目的编号后保留目的槽。查询读取当前保存值，图像资源元数据的更新仍由媒体阶段负责。

`getpos2` 沿用 getpos 的目的编号、数组跳过、求值及写入顺序。平面位置只沿 CPLANE／PLANE／CP932 STRING 父级继续累加，Unicode 文字父级终止累加；先按 f32 从上层向下逐级相加，再转整数。图像复用绘制位置，按钮保留锁定位置规则，不叠加关联平面。BASE／SOUND／DRAW 和滑动控件求值参数后保持目的槽。

图形 `pos` 的缺省坐标也经过上述整数截断，再转回 f32，因此省略参数仍可能改变小数坐标；两类平面将 W 设为一。图像的第三个参数求值但不设置 Z。仅在最终位置向量变化时递归使后代属性失效，来源与排序标记保留。

默认属性运动使用完整名称：`blend` 为 `pColor`，`pos` 为 `pPos`，`arc` 为 `motArc`，`mcarc` 为 `mcArc`；资源类别均为 `mot`。原名称参数是 UTF-16，类别参数为单字节文本，库将完整名称交给资源补全服务。

图形位置提交后按现有活动运动规则捕获基值，再以 `[x, y, z]` 装载默认 `mot/pPos` 运动，图像的 z 参数固定为零；即使位置向量未变也保留这次运动请求。普通主体、系统块与对象事件共用该入口。已完成求值、银行和位置修改在资源失败后保留，重试不重新取整、求值或重复前面的银行；默认运动缺失时继续使用已保存位置。独立 Objects 接口对图形 pos 返回需要场景服务的诊断，滑动控件仍可直接使用。

`arc`／`mcarc` 接受全部已接入对象类型。目标银行与五个数值各求值一次，额外参数忽略；遇到中途缺失银行时结束。按子树活动运动状态决定是否捕获基值后，以 `[duration, angle1, angle2, x, y, 0]` 分别请求默认 `mot/motArc` 与 `mot/mcArc`，使用目标保存的运动延迟。所有参数转为 f32；角度先转 f32、乘 f32 的 π，再除以 180。命令本身不修改坐标或使属性失效，具体运动由所装载的程序执行。资源缺失时继续，资源错误后保留求值、当前银行和此前已插入的运动；主体、系统块及对象处理器共用这一续跑规则。

两条运动命令的 6,600 组原入口调用中，3,960 组有效银行在预算一与 4096 下的六个参数、分组、完整基值捕获、变量副作用及失效状态全部一致；接入整行回退后，包含其余 2,640 组显式缺失银行的全部 6,600 组状态和副作用也已匹配。覆盖十类对象、空参数、整数边界、银行空洞及已有活动运动。两项常规合成回归固定跨银行资源失败重试、三条脚本入口、缺省参数和分组选择。

4,080 组原入口调用中，3,780 组有效银行在预算一与 4096 下的坐标位模式、完整运动基值、三个参数、后代失效及变量副作用全部一致。覆盖十类对象、整数／小数／非有限初值、空参数、数组空洞、混合类型及已有活动运动。其余 300 组显式缺失银行所属入口现已连接下述整行回退。三项新增常规回归使用合成脚本和内存资源，固定三条脚本入口、运动读取失败续跑、本地位置查询，以及父级位置到真实图元与最终像素的提交。

`attach` 遇到缺失银行结束，跳过其他已接入类型；`page`／`load` 的其余类型继续按专属入口诊断。初始化 POS2 列与运行中的 `pos2` 命令分别处理：后者不修改 SLIDER。

`settbl` 遇到中途缺失银行结束，跳过不支持帧表的已接入类型。IMAGE／BUTTON 同时启用帧表并标记映射已修改，当前来源不立即重装；下一次有效 `setid` 即使编号相同也重新选择来源。SLIDER 每次有效写入都请求后续四槽提交和重选，相同值也保留请求。该命令与关联平面的 `pl` 分别登记。

`pl` 先求值目标银行，再解析一次平面引用，额外参数忽略。缺少引用或引用名称为空时结束，不求值引用中的银行表达式。已声明的多银行引用省略银行时保留 −1；单银行或未知名称省略／显式 −1 时取零。关联对象无需存在，字面名称 `0` 原样保存。遍历遇到缺失银行、BASE、两类平面、SLIDER 或 SCROLL2 时立即结束，保留此前银行的修改。同值引用不标脏；实际变更只请求属性登记，不重建像素或修改排序。

图像导航偏移初始为 `[0,0]`，模式为零。任意尺寸写入，包括相同 SIZE、SIZE2 与装载所得尺寸，在零模式下把缓存重设为 `[width−16,height−8]`，整数减法回绕；非零模式保留缓存。`keypos` 的非零模式直接保存 `[x,y]`，模式保留原值；零模式忽略 x／y 的值，但仍对两项求值，并按每轴尺寸向已有偏移累加：大于 32 加尺寸减 16，大于 16 加尺寸减 8，其余加尺寸除二，负数向零截断，加法回绕。重复零模式会重复累加，不能从当前尺寸单独推导偏移；参数按空格分隔。

`pri` 的图像比较使用当前已加 20 的值与原始参数：当前为 27 时传 27 跳过，传 7 仍登记一次排序变化，结果仍是 27。它不采用初始化 PRI 的逐银行加值，也不改写列表槽号。`pos2` 先组成 `file:frame`，再按第一个冒号和整数前缀解析；因此 `asset:5 7` 保存 asset 的第 5 帧。文件名必须少于 128 字节；元数据读取推迟到属性更新阶段。

IMAGE 的 `size` 变化也会重新读取当前文件并重新登记，相同尺寸不读；普通文件模式保留新的请求尺寸，任一轴设为 −1 时整组恢复物理像素尺寸。它不缩放已加载的像素。原始来源和直接路径继续沿各自的来源更新规则处理。

目标名称或起始银行缺失时，库求值行级展开后的原始整行。连续操作数按原运算符栈构树，仅执行最终结果树；参数副作用及银行引用的再次求值由该树决定。普通主体、系统块及对象事件共用，保留 FES 局部变量、命名值和当前银行作用域。已注册子命令通过 `SubcommandCall.source` 保留完整行，回退时不装载运动或执行参数映射。具体数值规则见[整行回退](expressions.md#fes-整行回退)。非 IMAGE 的 `getid` 在基线写入目标名称的进程地址，当前库返回明确诊断；不以零或对象句柄替代该地址。其他类型的扩展语义在实现对应对象时接入。

## FES IMAGE 动画请求

`Objects::dispatch_image_animation(interpreter, line, state)` 消费解释器的 `Event::Command` 中的 `setanm`／`anm`；成功返回 true 后调用方才确认该事件。其他命令返回 false。目标银行及事件对象引用复用 FES 解释器的解析接口；省略银行时依对象数量展开，缺失银行跳过。当前只有 IMAGE 应用请求，CIMAGE、BASE 和两类平面跳过。基线还允许按钮类型，按钮对象仍待接入。

`setanm [name]` 保存已展开的名称，不改变播放开关；没有扩展名或扩展名为空时补 `.anm`，缺省名称得到 `.anm`。显式的非空扩展名暂时保留。`anm [mode]` 将播放开关设为零或一，只有忽略大小写的 `STOP` 表示零；缺省、空参数及 `0` 均表示播放。两类命令总是请求后续更新，相同值也会重新消费，显示属性和来源重建标记保持独立。`Object::image_animation_request()` 只读查询保存的名称、播放开关和待处理标记；名称超过 255 字节返回诊断。

`Runtime::update_fes_object` 在来源准备／登记完成后、排序更新前消费 IMAGE 的动画请求。先清除请求标记；播放非零时以 image 类别补全保存名称，将结果扩展名替换为 `.anm`，再依次发送 299 装载和 301 播放。暂停只发送 301，不读取动画文件。资源读取和预算续跑沿用共享列表服务；再次请求播放会重新装载，普通对象更新不重复读取。解析失败保留此前完成的状态修改并返回诊断，该请求已消费，后续更新不会自动重试。Scene 在提交与本轮边界自动按声明顺序更新对象，独立调用方也可显式推进。

十类合成命令及十四次对象更新取得 67 份状态／资源请求记录，与原入口逐项一致，覆盖默认值、大小写、空名、扩展名替换、类型门控、重复更新以及动画与排序顺序。两项纯合成回归固定银行空洞、类型跳过、未知命令保留、名称边界，以及脚本事件到画布像素、暂停、重复播放读取和失败后的请求消费；常规测试不依赖外部资源或设备。

## FES 媒体记录与来源包装

名称绑定、对象身份和声明记录分别维护。重复声明仍分配未绑定对象，已有名称／银行继续指向首次绑定；每条 CIMAGE／IMAGE／BUTTON 声明记录另分配独立图像包装，BUTTON 另保存各自创建的下层任务。对象上的当前包装与按钮编号由后一次准备覆盖，记录中的旧绑定继续保留。

Scene 按记录顺序查询当前对象并更新，重复记录共享该对象的来源／属性／排序标记。第一条记录消费请求后，后续记录不会重新装填自己的包装。IMAGE 和 BUTTON 的装载、图像登记、矩形尺寸回退及 Alpha 掩码使用本次记录的包装；CIMAGE 装填记录包装，却使用对象的当前包装登记显示。例如两次声明同一对象时，第一份包装有像素，最后一份可能仍为空，CIMAGE 因而移除该显示条目。这一差异按基线保留。

`Objects::media_records()` 提供每条记录的目标和绑定，`Object::image_handle()`／`task_id()` 查询对象的当前值，`image_handles()`／`button_task_ids()` 遍历其全部持有。显式 `Runtime::update_fes_record(owner, objects, index)` 使用记录包装；单对象 `update_fes_object` 使用当前包装。装载准备按记录保存完成状态，按钮创建失败前已经分配的包装在重试时继续使用，不再分配；重新绑定列表也不重新创建媒体。

删除时释放该对象的全部包装，并向全部下层按钮发送删除请求；图像条目按当前像素或原始来源身份反查后移出，避免删除已被其他来源覆盖的槽位。直接调用 `Objects::remove` 时，资源和任务由接收返回对象的调用者清理。所属任务实际回收仍释放其登记的剩余资源。

三类媒体的 36 次更新、6,600 字节完整命令／双包装状态／像素与原入口一致。列表 307 的 216 次查询、7,776 字节另确认有符号 key 次序、槽号转换、缺失与缓冲保留；库查询结果一致。纯合成回归覆盖上述重复声明、小画面、掩码、来源重读、覆盖槽位、删除和创建失败续跑，不依赖外部资源或设备。

## FES 图像属性查询

`object attr id [out0] [out1] [out2] [out3] [out4]` 从当前来源查询五 DWORD 属性，向给定的共享数值槽依次写入原始位模式。缺少 id 时无动作；编号和五个可选目的槽在遍历银行前各求值一次，缺省目的槽为 −1，越界槽跳过，额外参数忽略。同址目的由后值覆盖。

CIMAGE／IMAGE／BUTTON／IMGWND 优先使用共享引用，否则使用自有包装；DIFIMAGE 查询当前持有资源的图像。缺少来源、空像素或缺少属性时保持输出，不装载文件、不刷新媒体、不修改图像属性。单银行目标归零，数组按银行顺序查询，后一个成功查询覆盖前值；遇到银行空洞立即结束。起始目标缺失沿用整行数值回退。

`Runtime::dispatch_fes_image_attributes(objects, interpreter, line)` 提供独立分派，Scene 主体、系统块和对象事件自动调用。普通 native 536 查询普通图像包装中的同一属性记录，详见 [KCS 图像属性](kcs.md#图像属性)。

## FES 共享图像引用

`object refex [source]` 先在当前 FES 作用域中求值来源一次，再作用于目标银行。缺参取零，额外参数忽略；不在命令阶段刷新媒体。单银行对象归零，数组缺省遍历所有银行，空洞跳过。起始目标缺失沿用整行数值回退。

CIMAGE／IMAGE 将非零来源作为普通 111／112 使用的图像包装，释放旧共享引用后持有新包装；重复设置同一值同样执行替换。设置只使对象自身的显示属性失效，保持位置、尺寸、基点、资源重建标记和运动基准。后续列表登记使用共享来源，自有包装继续准备和保留；零引用恢复自有来源，重新准备独立媒体包装时也清除旧共享引用。原所有者释放后，共享来源继续存活至全部使用者解除引用。若先释放旧引用导致同一来源已销毁，再次持有会返回失效句柄诊断。

IMGWND、BUTTON、平面和其他对象类型忽略来源，但保留参数求值。DIFIMAGE 接收独立图像资源句柄，先持有新资源并复制其缓存基点，再释放旧资源，因此重复绑定同一资源有效。零值只释放旧资源，保留基点及待处理捕获请求；两种操作均使对象及后代失效。`DifImageState::resource_handle()` 查询资源句柄，`Object::image_handle()` 借用当前普通包装标识。220 组来源的 1,320 次重复绑定、清除及元数据变更后绑定与原入口一致，覆盖缓存基点和最终引用释放。

`Runtime::dispatch_fes_reference` 提供独立对象存储入口，Scene 自动调用相同分派。`Object::referenced_image_handle()` 查询共享来源覆盖，自有 `image_handle()` 保持。`remove_fes_object` 解除该对象的列表槽和共享引用；任务内场景在任务回收时自动释放，独立存储须在停止使用后调用 `Runtime::release_fes_image_references`。已经提交到列表的像素仍按列表自身的持有规则存活。

## FES CIMAGE 更新

`Runtime::update_fes_object` 将 CIMAGE 的纯色来源接入共享列表。调用方先创建、初始化直属 owner 的类型 15 任务，再通过 `Objects::set_image_list(task, clip)` 保存任务编号及全局裁剪。绑定不使属性失效；切换列表也不迁移旧条目。更新入口核对所属任务与列表类型，`Object::image_handle()` 查询本对象的来源包装，底层像素仍通过 Images 查询。

场景装载为每条声明记录创建空包装；显式单对象更新在尚无包装时创建。后续只在来源重建标记存在时准备像素：读取持续 SIZE2，按实际尺寸重配，再按请求尺寸填充颜色。尺寸检查或分配失败清除本次重建标记，保留属性失效及旧像素并返回诊断。成功后，属性失效或来源重建都会进入登记阶段；POS2 在此时消费。空来源发送 287，已有像素且槽号不为 −1 时发送 286，随后发送 295。实际零尺寸像素属于已有来源。

位置沿直接为 CIMAGE／IMAGE 的父级累计，每一级先计算来源偏移加位置减基点，再加父级结果；本对象基点另传给列表。PLANE 引用仅在实际类型为 PLANE 时生效：其 VRAM 两轴先截断为整数，加到登记位置，VRAM 与平面尺寸组成条目裁剪，替代全局裁剪。无变换路径仍忽略旋转与缩放。两类显示／来源标记在登记阶段完成后清除，排序标记独立消费并发送 305；排序变化不重新准备来源。

`Objects::invalidate(handle)` 为直接显示属性修改或运动回写递归标记对象及后代；直接尺寸／颜色修改另调用 `state.updates.request_rebuild()`。删除 FES 对象时遍历其全部包装，以 307／308 反查当前实际列表条目并移出，随后释放包装；已被其他来源覆盖的槽位保留，列表及其他包装持有的像素按引用继续存活。调用者保持对象存储与 owner 同一生命周期，任务实际释放也会回收登记在 owner 的来源。

动态 `pl` 沿用先登记属性、再替换裁剪的顺序。原列表将新位置的历史范围先裁入旧裁剪；新旧平面不相交时，新区域可能没有脏区，画布保持空白，直到再次登记或强制重绘。四次连续切换的 192 个像素与原入口一致，常规回归同时固定关联变更不重建像素及强制重绘后的新区域。

两组共 26 阶段原入口序列核对请求顺序、完整登记记录、裁剪、标记、尺寸和像素，合计 4,892 字节全部一致；覆盖空来源、重复颜色、元数据时点、优先级、父级及 PLANE 引用。三项纯合成回归覆盖 FES 事件到最终帧、父级与基点变化、来源共享／回收、PLANE 裁剪及元数据／失败时点。IMAGE 普通文件装载见下一节；附加来源、标记元数据、变换类别及 FES 主体自动调度继续接入。

## FES IMAGE 文件更新

FILE 的请求名与当前文件名分别保存；设置非空请求时依次替换 `%LANG%`、`%LANG_M%`。两套语言选择共用前缀表及默认编号，各自越界时回退到默认；默认也越界时保留对应标记。替换区分大小写且覆盖全部匹配，主语言的替换结果还会参与消息语言替换。当前名称变化才请求重建，空请求保留旧名称。运行时语言配置变化后，在下一次媒体更新前刷新本场景的 IMAGE／BUTTON 来源；已有包装和输入任务继续复用，来源变化会重新登记按钮区域与掩码。语言表由宿主提供，类别补全和预加载不执行此替换。

IMAGE 与 CIMAGE 共用来源包装和共享列表绑定。首次更新只建空包装；FILE 或有效 IDN 请求重建后，更新入口才同步读取普通 HG-3 文件。文件列表仅按半角空格分隔，Tab 和冒号保留在文件名中；全部文件使用同一 `selected_frame()`，名称按 image 类别补全。首次成功来源保留几何，后续成功来源沿底端起始坐标以零透明度合成。失败项继续尝试后续文件。

普通文件重建先清空本对象包装的像素绑定，其他共享包装继续持有原像素。全部文件或帧缺失时，包装保留为空，请求尺寸、来源偏移和对象基点保留上次值；登记阶段移除当前槽，并清除本次来源与属性标记。相同 FILE 或相同 IDN 不自动重试；再次改变来源或显式请求重建才重读。非空名称但没有配置资源服务、格式错误及未接入的格式返回诊断，已完成的修改保留。

BTYPE=0 时，对象来源偏移取原图基点，对象基点取原图基点减裁剪偏移；像素来源的裁剪偏移归零，画布改为物理像素尺寸，原图基点保留。BTYPE=1 时，对象来源偏移归零、对象基点取原图基点，来源元数据保持原值。普通文件分支中，两种类别仅在请求尺寸任一轴为 −1 时把整组尺寸改为物理像素尺寸；其他 BTYPE 保留对象几何。SIZE2 引用继续保存，这条普通文件更新路径不读取它。

IMAGE 的无变换登记位置为 `(整数平面偏移转 f32 + 本对象基点) + 逐级有效位置`，保留 f32 运算顺序；逐级有效位置与 CIMAGE 共用来源偏移加位置减基点的父级累加。列表随后减去记录基点，因此默认几何最终显示于局部位置加原图裁剪偏移。POS2 只在属性登记阶段消费，不触发重新装载。空来源且槽号为 −1 时跳过 287；非空来源仍按 286／295 登记，排序独立使用 305。

## 绘图变换

`graphics::Transform` 保存基点、平移、缩放、弧度旋转及可选显式矩阵。默认基点为 `[0, 0, 5000]`，平移和旋转为零，缩放为一，矩阵为单位矩阵，dirty 为 false。属性由同名查询方法读取，`set_base_point`、`set_position`、`set_scale`、`set_rotation` 和 `set_matrix` 更新状态；`clear_dirty` 消费变更标记。

向量属性按浮点相等比较整组：全组相等时保留原值的位模式，任一分量不同才整组替换，因此正负零不会单独触发更新，NaN 会触发更新。显式矩阵按 16 个 DWORD 位模式比较，重复设置同一 NaN payload 不触发更新。`set_rotation` 即使角度相等，也退出显式矩阵模式；`set_scale` 保留该模式。

`matrix()` 为 `Identity × Scale × RotateX × RotateY × RotateZ`，显式矩阵模式则为 `Identity × Scale × matrix_override`。起始单位矩阵相乘保留非有限值的传播和求和顺序。旋转沿用原 x87 三角约化：有限大角度使用 66 位 π，NaN 保留符号和 payload 并置 quiet 位，无穷与超出 FSINCOS 范围的输入保留原异常结果。

`transform_point([x, y, z])` 只减去基点 X／Y，保留输入 Z，以 W=1 乘本对象矩阵，再加四维平移 `[px, py, pz, 1]`。普通仿射路径的结果 W 因而为 2。`transform_point_with_parent(point, parent)` 随后乘父级／绘图上下文矩阵，保留该 W，不执行 W 除法；父矩阵的平移同样受它影响。基点 Z 独立保存，不参与这一顶点变换。

12,981 组状态及 38,943 个完整变换后顶点已与原入口核对，有效属性、矩阵、dirty 和顶点结果一致。三项纯合成回归固定几何顺序、父级 W、正负零与矩阵模式、常规三轴旋转和非有限／大角度行为。该接口已用于二维对象属性和三角形查询；像素栅格化与帧提交继续实现。

## 绘图投影

`Projection` 接收绘图中心 `center`、摄像深度 `camera_depth`、最终平移 `translation` 和矩阵 `matrix`，以及已选择坐标组的 `coordinate_offset`／`coordinate_scale`／`coordinate_matrix`。默认中心、深度、偏移和平移为零，比例为一，矩阵为单位矩阵；实际配置由调用者提供，当前尚未从根对象自动装载。

`project_triangle(vertices, base_depth, origin, perspective)` 接收对象／父级变换后的三个顶点、对象基点 Z、已选择的投影原点及开关，返回 `ProjectedVertex { position, rhw, color }`。颜色原样保留，不自动裁剪，不隐式执行 W 除法。

关闭透视或顶点 Z 为正／负零时，先围绕中心应用坐标组缩放与矩阵，再加中心减坐标组偏移；此时 Z 独立改写为 `(65000 − (z + base_depth)) × f32(1/65000)`，坐标组矩阵不改变该 Z。最后乘最终矩阵，再加最终二维平移。矩阵乘法保留完整四维输入。

透视且顶点 Z 非零时，距离先按单精度计算为 `(65000 − base_depth) − camera_depth`。分母为 `z − distance`，两者浮点相等时改用一；二维比例为 `camera_depth / denominator`，负值钳为零。围绕 origin 处理后的四维顶点乘投影矩阵，其 Z 系数为 f32(1/65000)、W 系数为 `1 / denominator`。然后加 origin、减中心、应用坐标组缩放／矩阵，加中心减偏移，再乘最终矩阵及平移。RHW 参与后续矩阵的平移项，不能固定为一。

普通图元的透视原点模式初值为零，零取包装平移 X／Y，一取绘图中心，其余原始值取 `[0, 0]`；两条栅格化路径均按此选择，再执行投影。平面 82／普通 466 只更新已有登记，重建图元恢复初值，不沿子树传播。原绘图管理器的此入口仅在模式零、后端启用且类型查询为普通绘图后端时写入；72 组原调用确认门控和完整 DWORD 保留，库的 Drawables 表示该绘图后端。合成帧回归覆盖对象原点、绘图中心及零点的像素差别。

`Drawable::projected_triangle(index, parent, projection, origin, perspective)` 组合对象变换、父矩阵、颜色覆盖与上述投影；越界返回 None。它使用本对象的基点 Z，不用变换后顶点 Z 代替排序深度。1,266 组三角形的 75,960 字节完整投影顶点已与原入口一致，覆盖两条分支、两级矩阵、负比例、相等分母、正负零及非有限值。两项常规合成回归固定 RHW 平移、分支深度及图元组合；基础纯色三角形已接入 CPU 绘制，纹理与完整帧提交继续接入。

## 绘图登记与三角形

`Drawable::rectangle(at, size, argb)` 创建两个原始三角形，保留负尺寸和退化边；端点按单精度求和。`bounds()` 返回独立原始边界，矩形为 `[x,y,0]` 至 `[x+width,y+height,0]`；通用列表和空图元的边界为零。

`Drawable::new(triangles)` 保存不带纹理的三角形列表，每个 `Vertex` 含三维位置及原始 ARGB 颜色；`Drawable::default()` 为空列表。单个对象的原始顶点最多 64 MiB。默认使用 `Transform::default()`，覆盖颜色为全一、覆盖开关和 display 为零、混合模式为零。`triangles()` 保留原始顶点，`transformed_triangle(index, parent)` 返回应用本对象及父级矩阵后的三角形，索引越界返回 `None`。颜色覆盖仅影响变换后的查询，原始顶点颜色不被改写。

`Drawables::insert(id, drawable)` 按对象编号登记，成功返回 true，已有编号返回 false 并保留原对象；`remove(id)` 立即移除登记，返回是否存在。`get(id)` 只读查询，`order()` 在有排序更新时按基点 Z 从小到大稳定归并。排序使用上次保留的顺序，相等优先级保留该顺序；删除后重新登记放到末尾。NaN 与其他值比较时不构成大于关系，沿原归并次序处理，不将它转换为整数或强行指定全序。平移 Z 不改变排序优先级。

`set_base_point` 总登记重排，即使向量属性比较相等；`set_position`、`set_scale`、`set_rotation` 和 `set_matrix` 沿用 `Transform` 的更新规则。`set_color(id, argb, enabled)` 保存覆盖颜色及原始启用 DWORD，零值使用每个顶点自己的颜色；`set_alpha(id, alpha)` 保留已保存覆盖色的 RGB，将 alpha 的低八位写入高字节并开启覆盖。`set_display` 保留原始 DWORD，`set_blend_mode` 接受 0～5，其他值归零。以上设置在编号不存在时返回 false。

192 组批量登记的返回值、两轮排序及颜色状态与原入口一致，覆盖重复编号、登记顺序、同级、优先级变化、正负零、无穷及 NaN。两项纯合成回归固定原归并序列、重新登记、父级 W、颜色覆盖和原始顶点保留。基础纯色三角形绘制见下文，纹理与完整帧提交继续实现。

## 纯色三角形绘制

`Surface::blend_triangle(points, argb)` 接收三个二维画布坐标，绘制普通 Alpha 混合的纯色三角形。像素中心在整数坐标，顶点按 `floor(value × 256 + 0.5) / 256` 对齐八位亚像素，包含左／上边；绕序不影响填充，两三角形共享边只绘制一次。坐标非有限、对齐后退化、完全在画布外或源 Alpha 为零时返回 false 并保留像素。每个 BGRA 通道均按源 Alpha 混合，以 255 为分母并取最近整数；Alpha 通道同样应用这两个混合因子。该设备路径与普通图像 CPU 混合的舍入规则分别保留。

`RenderTarget::blend_triangle` 使用相同的全局顶点处理各面块，不提前平移并舍入顶点；缺失面块跳过，实际覆盖非零 Alpha 像素的块登记 dirty。返回值表示是否覆盖了存在的面块，原像素与混合结果相等时仍可返回 true。

`Drawables::render_triangles(target, projection, parent)` 按基点 Z 和登记顺序绘制，display 为零或空图元时跳过。每个对象最多提交前 32 个三角形；对象基点 Z 用于投影深度，平移 XY 作为投影原点。当前非纹理入口接入默认坐标组、六种混合模式及顶点颜色插值。颜色不一致时要求有限的正 RHW，随后按透视权重插值。投影深度在屏幕坐标中线性插值，只有 0～1（含两端）的像素参与混合，跨越近远面的三角形保留可见部分。父矩阵与 `Projection` 由调用者提供；未实现深度缓冲，纹理和对象专属坐标组通过下文的完整帧入口使用。

`DrawingContext::render_triangles` 保留模式零、enabled／active 和目标存在性门控；未开启时返回 false。`Runtime::render_triangles(projection, parent)` 使用运行时的同一份登记与绘图目标。调用者在更新完成后显式调用，负责清空目标和随后呈现；连续调用会继续混合当前像素。平面构造及创建矩形仍保持默认 display=0，当前显示开关由宿主通过 `Drawables::set_display` 提供，专属显示命令继续接入。

合成 KCS 已能通过普通 79／84 创建及移动矩形，经运行时绘图登记、投影和分块目标得到完整 BGRA 像素。四项常规合成回归覆盖共享对角线、Alpha 舍入、亚像素边界、空／非法输入、全局面块坐标、排序／可见性、提交上限、上下文门控及脚本到像素的串联。设备视口裁剪的边界差异见[验证记录](runtime-probes.md#纯色栅格化与设备像素)。

## 纹理与顶点颜色插值

`DrawCommand::blend_mode` 保存图元的混合编号，普通、画布纹理及粒子命令共用。编号超出 0～5 时使用模式零；软件与设备后端在纹理取样、颜色插值及调制之后混合。下表的 S、D 为归一化的源／目标通道，A 为调制后的源 Alpha，四个 BGRA 通道分别应用相同规则，结果饱和到 0～1。源 Alpha 为零时跳过像素。

|编号|通道结果|
|:--|:--|
|0|S × A + D × (1 − A)|
|1|S × A + D|
|2|S + D × (1 − A)|
|3|S × D|
|4|S × (1 − D)|
|5|S × D + D|

`Surface::blend_projected_triangle(vertices)` 接收三个 `ProjectedVertex`，按其屏幕 XY 及 RHW 插值 ARGB，再作普通 Alpha 混合。`Surface::blend_textured_triangle(vertices, uv, texture, filter)` 另接收每顶点的归一化 UV、只读 BGRA8 纹理及 `TextureFilter::Point`／`Linear`，取样结果逐通道乘以插值后的顶点颜色。两种接口均返回是否覆盖非零 Alpha 像素；`RenderTarget` 提供同名接口，跨面块保留全局插值并标记实际覆盖的块。

像素覆盖沿用八位亚像素及左／上边包含规则。插值使用对齐前的顶点，以屏幕重心权重乘各顶点 RHW，再除以三个权重之和；UV 和颜色使用同一组透视权重。常量属性直接保留其值，计算使用 f64，取样、颜色相乘和混合之间不作八位整数舍入，最终写入 BGRA8 时取最近整数。

UV 的两个方向均采用镜像寻址，周期为二。点取样按 `floor(uv × size)` 选择 texel；双线性过滤以 texel 中心为半像素位置，按 `uv × size − 0.5` 混合相邻四个 texel。边缘的镜像 texel 重复，负 UV 和超出一个周期的 UV 同样有效。纹理为非预乘 Alpha，四通道都参与过滤、调制及源 Alpha 混合。

调用者显式选择点取样或双线性过滤，当前没有自动区分缩小／放大、mipmap 或各向异性过滤。空纹理、非有限 XY／UV、非有限或非正 RHW、退化及完全越界三角形返回 false 并保留像素；Z 不参与此核心的裁剪或深度测试。`Drawables::render_triangles` 已使用颜色插值核心，显式画布图元和独立帧提交见下文；矩形包装、图像对象的自动提交及设备呈现继续接入。

设备对照的固定 UV 与颜色插值案例共 528 组、33,792 个像素全部一致。其余 312 组变化 UV 中，315 个像素存在单通道一级差异，9 个点取样像素在 texel 选择边界附近选择不同 texel；CPU 核心固定上述 f64 计算规则，尚未复现设备过滤精度和选择边界的全部细节。具体范围见[验证记录](runtime-probes.md#纹理取样与透视插值)。四项合成回归固定镜像／过滤、非整数调制、RHW 对 UV 与颜色的作用、跨块插值、非法输入，以及 Drawable 到渐变像素的串联；默认测试不使用图形设备。

平面对象命令 83 以 `data[0]` 为数量、data1 为记录缓冲区，先移除旧登记再创建。普通 native 83 仍发送清除命令 68，与此对象命令分别解释。创建标志不门控此命令；成功时偏移、尺寸和图元类型保持旧值，新登记恢复默认显示、变换、混合及白色覆盖。零记录不访问输入缓冲区，仍登记空画布图元；删除门控先于输入访问，释放及命令 3／68 清理登记。

`Drawables::render_frame(output, canvas, projection, parent, filter)` 按相同的显示与稳定排序规则处理纹理及非纹理图元。canvas 只读，其面块按原索引取样；索引越界或缺失面块相当于未绑定纹理，使用顶点颜色绘制。纹理三角形按原顺序全部提交，非纹理对象仍只提交前 32 条。过滤显式选择点取样或双线性，混合模式随绘制命令交给后端。纹理和颜色共享 0～1 的投影深度裁剪，裁剪保留原来的 RHW 插值及纹理坐标。完全越过近远面、位置非有限或按八位亚像素规则退化的图元在插值检查前跳过；可见的纹理及渐变图元仍要求有限的正 RHW。

`Runtime::render_frame(output, projection, parent, filter)` 以当前 `drawing().target` 作为画布输入，要求画布已配置。这是显式帧提交接口，由调用者决定调用时点、输出清空与呈现；绘图上下文的 enabled／active 门控继续用于图像写入和旧的 `render_triangles` 接口。连续提交继续混合已有输出，画布及其 dirty 标记保持原样。旧的 `render_triangles` 不具备独立纹理输入，遇到可见的非空画布图元返回诊断。

120 组显式画布图元的已定义状态、原始及变换后记录共 409,920 字节与原入口一致；32 组原整帧入口的 8,192 字节像素一致。合成回归覆盖数据布局与上限、纹理变换顺序、对象替换及删除、缺失纹理、超过 32 条的提交、混合图元排序，以及真实 KCS 的图像创建／填充／画布复制／释放／颜色覆盖到独立输出。命令 41 的对象包装见下文；显示与输入联动及设备呈现仍待接入。

## 脚本离屏绘制

普通 native 568 接收两个原始 f32：深度下界和上界，最少读取八字节，额外参数忽略。两项在上下文门控之前读取；参数不解释为 VM 地址，不修改 VM 存储，以状态二继续，不添加返回值。

模式为零、`DrawingContext::enabled` 开启且画布目标存在时，使用 `Runtime::set_frame_view` 保存的投影、父变换和纹理过滤绘制到独立离屏帧；不检查 `active`。尺寸取 `HostState::surface_size`，每次实际绘制先清空整幅输出，源画布、画布脏区及上下文开关保持。空范围或无可见图元仍产生清空后的帧。跳过的调用保留旧帧；缺少帧视图或容量无效时返回诊断。绘制中发生错误时保留已写像素。

深度筛选复用 `Drawables::render_depth_range`：按基点 Z 和稳定排序依次遍历，深度小于下界时跳过，大于等于上界时终止；有限值对应 `[lower, upper)`。上界不大于零时不提交图元。浮点比较保持原有序规则：NaN 下界不触发小于下界的跳过，NaN 上界不触发上界提前终止，也不在入口取消绘制。三角形本身仍遵循已有的投影、混合和深度裁剪约束。

`Runtime::offscreen_frame()` 只读借用最近一次离屏目标。DIFIMAGE 捕获共用该绘制路径，先生成完整帧，再依据 `set_frame_capture_rectangle` 截取独立图像；裁剪不缩小保存的完整离屏帧。离屏结果与显式 `render_frame` 的输出分别持有。原设备回调、多目标切换和设备异常恢复继续由后续平台后端整合。

3,456 次原包装调用核对最短输入的保护页边界、原始浮点位模式、准备／绘制调用次序、门控及状态二返回；两种预算下的 6,912 次 Runtime 重放匹配返回栈和 VM 存储。144 组原深度筛选的完整选择列表与库一致，包含负值、无穷、NaN、空／倒序范围及精确边界；对照用合成投影将输出 Z 归零，单独核对选择集合。常规回归仅使用合成图元和内存脚本，固定真实 KCS 到像素、重复清空、关闭上下文后的结果保留、预算、参数边界及 DIFIMAGE 的完整帧与裁剪分离。

## 画布几何切割

`CanvasLayout::new(tile_size, grid, step)` 指定单块纹理尺寸、面块网格和切割步长。步长必须为正且不超过对应单块尺寸；每轴的细分数使用整数除法。布局独立于像素，缺失面块仍能生成几何。`triangulate(source)` 接收已完成源对象变换的三角形，输出供纹理包装使用的 `CanvasTriangle`；输出尚未施加包装对象变换或半像素偏移。

输出依次按源三角形、网格行、网格列及扇形三角形排列。tag 为源三角形序号；Z 固定为零，颜色取源首顶点。包围盒先向零截断到 i32，再作整数矩形相交检查，因此完全位于同一整数坐标格内的窄图形可能不产生任何记录。实际交点保留 f32 运算与去重规则，不将相邻源三角形合并。UV 使用画布坐标与对应纹理块的原点、尺寸换算，共享边在相邻块内分别为一和零。

基线在计算面块行号时也使用横向细分数作除数。本接口保留这一规则；横纵细分数不等时，结果可能引用下一行面块并产生负 UV。调用者如需普通逐块切割，应令 step 等于 tile_size。

非有限 XY、超出有符号坐标范围的布局、超过一百万个源／网格组合及超过 64 MiB 的输出均返回诊断。1,200 组原入口对照的 635,920 字节全部一致，覆盖负坐标、反向与退化矩形、小数交点、一般三角形及不等细分。两项合成回归固定跨块顺序与 UV、整数包围盒、面块行号及输入上限。

## 画布纹理包装

`Drawable::from_canvas_source(source, layout)` 接收非纹理源的所有权，保留其几何和独立变换，创建初始覆盖关闭的画布包装。它不接受已带纹理的源。包装保留源的声明边界，后续属性修改不更新该边界或平面任务的原始尺寸。

源几何变化后，`prepare_canvas()` 先应用源变换，再按画布切割并生成 UV，最后从输出 XY 减去源平移。因而源平移改变取样区域，包装平移改变屏幕位置；包装属性修改不触发源重新切割。源 Z 在切割输出中归零。`geometry_transform(source)` 查询所选层，显式画布记录选择源时返回 None。登记后的对象可通过 `Drawables::prepare_canvas(id)` 手动准备；`render_frame` 自动准备可见对象，隐藏对象保留待处理的源变化。直接读取 `canvas_triangles()`／`transformed_canvas_triangle()` 前，由调用者完成准备。

CPU 路径直接计算变换后顶点，首次绘制也遵循上述契约。原入口只构造后直接提交时可能读取未初始化缓存；实际启动链中缓存失效和首次更新的自动调用次序仍待核实。240 组对象的四阶段对照中，除 28 个源参数临时 W 未初始化引发的正负零 DWORD 差异，其余 1,108,128 字节一致；本接口的源属性按三个分量比较，相等时保留整组原值。准备缓存后的另 32 帧共 2,048 像素中，24 个点取样像素存在差异，双线性帧全部一致。具体记录见[纹理包装验证](runtime-probes.md#画布纹理包装的属性与整帧对照)。

## 当前绘图目标

`RenderTarget::new(size)` 创建一块零初始化的 CPU 渲染面。`from_tiles(tile_size, grid, tiles)` 接收按行排列的等尺寸面块，`None` 表示缺失槽位。总尺寸为面块尺寸乘列／行数，`size()`、`tile_size()`、`grid()` 和 `tiles()` 提供只读查询。布局必须精确匹配，单块最多 64 MiB，已分配的 CPU 像素总量最多 128 MiB，槽位最多一百万个；允许空尺寸。稀疏网格的逻辑范围不按完整像素分配容量计算。

`prepare_tiles(areas, split_row)` 按面块单位补建缺失槽位，返回新增面块数量。区域依次保存 `[起始列, 起始行, 列数, 行数]`，首项为 `u32::MAX` 时跳过；端点按 i32 回绕，反向或空范围不处理。先遍历分界行及以下的 16 位行，再遍历其余 32 位行，每轮按区域、行、列的顺序处理。索引沿用 `行 × 网格列数 + 列` 的回绕结果，落在存储区外时返回诊断，保留已经完成的分配。单次最多访问一百万个面块位置。

已有面块的身份、位深、像素和更新标记全部保留；新面块初始化为零，不标脏。`from_tiles` 传入的面块按 32 位登记，`tile_bit_depth(index)` 查询已分配槽位的有效位深。16 位面块以展开后的 BGRA8 保存 A4R4G4B4 值，写入时各通道取高四位并乘十七；当前采用不加抖动的转换，设备抖动配置尚待接入。

普通 542 不读取参数，模式为零且 enabled 非零、目标存在时，使用全局设置的八组纹理区域及 16 位分界行补建面块。active 不参与门控，调用以状态二继续并保留返回槽；真正需要区域配置时，未提供全局设置返回诊断。启动宿主可先按纹理尺寸、网格建立全空 `from_tiles`，再使用同一配置调用 `prepare_tiles` 完成初始分配。

384 份原补建快照核实两轮分配、重复区域、开关、缺失后端／目标、已有面块及标记保留，Rust 的分配数量、槽位和位深一致。关闭抖动的 256 组原普通 115 调用共 16,384 个转换像素与 CPU 结果一致。常规合成回归连接真实普通任务、两种预算、跨轮补建及已有像素保留，不依赖设备或外部资源。

`pixel(x, y)` 按整个目标的顶端起始坐标查询原始 ARGB，越界或缺失槽位返回 `None`。`clear_rect(rect)` 将相交且存在的面块局部区域全部清零，包含 Alpha，并将对应块的更新标记设为 true；即使该区域已经为零，仍登记更新。`dirty_tiles()` 查询标记，`clear_dirty()` 在呈现宿主消费更新后统一清除标记，像素保持原样。矩形端点沿用 `Rect` 的 i32 回绕及空区域规则。

`RenderTarget::copy_image` 提供普通 115 的全局源坐标和行方向规则，逐块裁剪、跳过缺失块，并标记实际写入的块。

`DrawingContext` 保存 `mode`、`enabled`、`active` 和可选 `target`。`clear_rect` 与 `copy_image` 只在 mode 为零、enabled 与 active 均为 true 且目标存在时执行；其他情况跳过。默认上下文两个开关均关闭、没有目标，由绘图调度宿主设置。`Runtime::drawing()`／`drawing_mut()` 提供当前上下文，普通任务在该上下文上同步操作；对象更新和设备呈现尚未自动切换这些状态。

普通 117 的首参为零时，只读取零句柄、x、y、width、height 五项，清零当前绘图目标。可以传入五项，也可保留第六项，后者的颜色被忽略；未开启绘图或没有目标同样以状态 2 继续，操作栈原值保留。目标坐标从顶部起算；非零图像句柄分支继续从底部起算并写入第六项的原始 ARGB。

普通 8 查询的配置渲染尺寸由宿主单独保存，不随当前目标绑定改变。CPU 渲染目标不执行设备锁定；设备创建、锁定失败和呈现仍由后续平台接入实现。

2,304 组完整 117 调用核对上下文模式、两个开关、缺失目标、缺失面块、跨块裁剪、空／回绕矩形和三种颜色。状态、返回槽、全部像素／保护区、面块标记及锁定／解锁次数一致。紧邻不可读保护页的五参数数组另外确认零句柄分支不读取第六项。四项常规合成回归验证布局、清除、状态门控及真实 KCS 的共享目标操作，覆盖五／六参数、两种预算、无目标和配置尺寸独立性。

## 画布淡入淡出任务

`graphics::FadeObject` 是类型 27 的画布淡入淡出任务，由 `GraphicsFactory` 创建。来源图像由调用者持有，任务只保存句柄及独立的工作面。`is_ready()`、`is_active()`、`duration()`、`size()`、`start_time()` 和 `speed()` 提供当前准备、播放及时间状态；初始未准备、未播放，速度为 1。

以下编号为对象命令，与普通 KCS native 编号分别解释：

|命令|行为|
|:--|:--|
|281|从 data1 的 44 字节记录准备来源和工作面，不自动启动|
|263|已准备时保存当前任务 elapsed、读取效果速度并开始或重新开始|
|264|已准备时提交完整新来源并结束播放；未播放时也提交|
|265|返回当前播放状态零或一|
|266|从 data1 的至少 20 字节记录中替换第 1、4 项来源句柄，要求两个图像的完整尺寸相等；不重做准备或重置播放|
|267|正在播放时提交完整新来源并结束播放|

除 265 外均保留返回槽。281 的记录为十一个小端 DWORD：

|索引|内容|
|:--|:--|
|0|原始时长|
|1|旧来源图像句柄|
|2、3|旧来源 x、y|
|4|新来源图像句柄|
|5、6|新来源 x、y|
|7、8|画布目标 x、y|
|9、10|请求宽、高|

两种来源坐标均从底部起算，画布目标从顶部起算。来源区域按底行到顶行的顺序写入画布；中间帧、自然结束和强制结束采用相同行序。来源句柄为零时保持未准备，不要求提供图像服务。有效来源的时长按有符号整数至少取一，宽高分别限制到两图各自可用的范围；负坐标、越界起点和负尺寸返回诊断。非零失效句柄返回图像存储诊断。266 先保存替换句柄，再检查尺寸，失败保留这次替换；调用者须修正来源后继续使用。

准备会修改对应区域内透明像素的 RGB：旧像素 Alpha 为零时，复制新像素 RGB 并保留零 Alpha；否则新像素 Alpha 为零时，将旧 RGB 写入新像素。按从底部起始的行、列顺序立即读写，两个句柄共享像素时保留重叠反馈。两图的 Alpha 均不因准备改变。

263 将 `Host::effect_speed()` 的 1、2、3、4 映射为 1.5、2、3、4，其他值使用 1；每次开始重新读取，播放中保持该倍率。宿主缺省返回零，Runtime 从 `SystemSettings::effects` 的首个 DWORD 提供配置。主体使用原始输入时刻与开始时刻的回绕差，先转 f32、乘倍率，再截断并保留低 DWORD。时长到期时直接复制新来源的原始 BGRA；未到期时，以 256 份整数权重逐字节插值全部四个通道，再复制到画布，不使用普通 Alpha 混合。进度的左移保留 DWORD 回绕。画布提交复用 `Host::submit_message` 的原始像素服务及 `DrawingContext` 门控。

已删除任务不再处理专属命令或提交像素。任务释放只回收工作面，来源继续由原持有者管理。FES `draw` 的场景连接见下节。


## FES PLANE draw

PLANE 的 `draw [duration]` 创建一个名称为 `__drawobj__` 的临时 DRAW，作为指定 PLANE 的子对象。单银行省略编号时使用银行零；多银行省略编号、目标类型不适用或已有同名对象时直接结束，不求值持续时间。时长缺省 30，显式值按有符号整数至少取一。不存在的目标改走整行表达式求值。

场景按 mot 类别补全默认绘制运动 `dummy` 并尝试装载，资源不存在时不加入运动。资源服务失败时保留已创建对象和已求值时长，重试继续读取；下层任务创建失败也保留同一个 DRAW。默认绘制运动使用现有运动队列，参与对象及父子树的运动查询和停止。

媒体准备创建类型 27、名称 `FE Draw` 的直属任务，查询共享列表的图像包装和输出偏移。按 PLANE 的 VRAM 和尺寸截取旧来源，来源 Y 从底部起算；截图具有独立像素，后续列表变化不会改写它。新来源继续使用共享列表包装；画布目标为列表输出偏移加 VRAM。准备保存 44 字节过渡记录，再以列表命令 292 关闭自动提交。列表仍更新自身像素。

`ObjectState::Draw` 保存 `DrawState`。`duration()` 查询时长，`phase()` 在尚未登记时返回 None；媒体更新依次执行：

|当前阶段|本次更新|
|:--|:--|
|−2|仅改为 −1|
|−1|发送 281 准备来源，再改为零|
|零|发送 263 开始，阶段保存所属任务 elapsed|
|其他值|发送 265 查询；播放结束则移除 DRAW 并恢复列表提交，否则在 DRAW 子树无活动运动时发送 264|

所属任务 elapsed 为零时，后续更新继续发送 263；强制结束后在下一次查询确认停止才移除。移除回收独立截图、请求删除下层任务，并同步清除解释器中的对象绑定；任务实体在正常任务树更新时释放。恢复提交失败时保留列表编号，后续媒体更新先重试恢复。重复转场使用新对象身份，旧 DRAW 记录不跟随同名新绑定，并在下一轮开始时清理。

FES 任务销毁时也恢复共享列表提交，独立于 DRAW 的正常完成路径。子树释放后，`prepare_release` 先向已绑定的非零列表发送 292，参数为 `[0,1,0]`，再向非零辅助输入按钮发送删除命令 3。初始化状态和删除标记不门控清理；目标已被其他子树释放时继续完成。路由错误保留当前项，后续重试跳过已完成项。随后移除场景登记到共享列表的图像来源，并释放自有包装、共享引用和原始图像。共享列表继续存活时，其余场景的条目保留；列表已经随子树释放时仍完成图像清理。

两项常规合成回归覆盖两种执行预算、银行及类型门控、重复命令不求值、底端截图、零时刻、两条完成路径、最终画布、资源／任务失败续跑及连续转场。窗口呈现和完整实际启动继续整合。


## 粒子任务控制

`graphics::ParticleObject` 是类型 38 的粒子控制对象，由 `GraphicsFactory` 创建。`opacity()` 默认 256，`transform_source()` 默认 u32::MAX。两项独立于任务时钟和创建上下文。

命令 326 读取 `data[1]`：按 i32 判断小于 255 时保留原始 DWORD，其他值保存为 256。255 与 256 均映射到全不透明，负值不裁剪。命令 327 将 `data[1]` 的零值转换为 u32::MAX，其他值保留，作为粒子变换的来源编号；u32::MAX 表示关闭外部变换来源。两项保留 output 并消费当前分支，已删除对象跳过。

命令 324 返回保存的播放状态，初值为零；命令 325 从 `CommandBuffers::data1` 复制前 128 字节，按 32 项原始 DWORD 保存，可由 `parameters()` 查询，未设置时为 None。短缺或缺失缓冲区返回诊断且保留旧参数；多余字节忽略。两项消费当前分支，删除标记同样门控。

普通 272／273 分别发送命令 321／322，普通 274 查询命令 324（未到达接收者时返回零）；普通 275 将第二参数指向的 128 字节交给命令 325。普通 426／427 分别转发命令 326／327。所有发送者均为调用任务，零目标仍路由；274 以状态一返回查询值，其余以状态二保留返回槽。粒子装载、播放和绘制尚未接入，相应命令 320～323、591／592 返回明确诊断。
