# 消息标记与布局接口

适用基线：CatSystem2 2.6.1.90。`message::Markup` 把已经解码的消息字符串解析为文字和控制片段，保留样式、注音分组及来源位置。姓名、正文选择和 CSTL 片段绑定由调用者先完成；CP932 与 UTF-8 的输入来源继续分别保存。

## 输入与结果

`Markup::parse(text, &defaults)` 接受 `&str` 和 `StyleDefaults`。五项 `text_sizes`／`ruby_sizes` 依次对应最小、小、普通、大、最大字号，初始使用第三项。正文、注音和阴影颜色由调用者配置。字号和颜色保存原始 DWORD；零字号和回绕结果在此阶段保留，实际度量由布局服务检查。

结果的 `atoms` 按消费顺序排列，每个 `Atom` 包含：

- `source`：当前输入字符串中的 UTF-8 字节区间，转义产生的片段包含已消费的转义部分。
- `kind`：字符、换行、对齐、X／Y 定位、延续或等待操作。
- `style`：该片段生效的正文／注音字号及三种颜色。
- `group`：可选的不可断行组编号和注音标志。

样式标记本身不生成字符。`final_style` 和 `restore_text_color` 保存解析结束时的样式及正文恢复颜色。每次调用从传入配置初始化；正文追加、页级恢复、姓名更新、显示进度和输入等待由后续消息对象管理。

普通字符以 Unicode 标量保存。来源区间按 UTF-8 字节计数，与字形索引及逐字时间分别解释。接口拒绝零字符，输入字节和字符数受库的存储上限约束。

## 分组、换行与转义

`[word]` 生成同组正文，`[word/ruby]` 的斜杠前后分别标为正文和注音；同组二者共享 `TextGroup.index`。分组不递归：组内第二个 `[` 显示为字符，第一个未转义 `]` 结束该组。注音中的第二个 `/` 显示为字符。缺少右括号时，当前组延续至输入末尾；样式修改继续影响组后的文字。

反斜杠转义先于分组分隔处理，因此 `\[`、`\]`、`\/` 和 `\\` 产生字面字符。未知转义同样显示其后字符，如 `\q` 显示 q。末尾独立反斜杠产生换行；末尾 `\f` 恢复普通字号并显示 f。实际换行字符与标记 `\n` 分别保留，布局阶段再按其类型处理。

|标记|片段或状态|
|:--|:--|
|`\n`|换行|
|`\@`|消息延续操作|
|`\pl`、`\pc`、`\pr`|左、中、右对齐|
|`\p`|左对齐；未匹配的后续字符保留|
|`\xnumber`、`\ynumber`|生成原始 X／Y 定位；无数值时不生成片段|
|`\wnumber`|`Wait::Characters(number)`|
|`\wfnumber`|`Wait::Frames(number)`|
|`\wr`|`Wait::Reset`|

标记字母不区分 ASCII 大小写。对齐和 `wr` 不消费可选分号；其后的分号显示为字符。等待按原始操作顺序保存，时长换算、字符间隔累加和等待完成尚未接入。

## 数值、颜色与字号

数值只接受无符号十进制或 `0x`／`0X` 十六进制前缀，累加按 32 位回绕。数值后的一个分号被消费；无数字的 `0x` 仍成功读取为零。正负号和空格不属于数值。`f+`／`f-` 的符号属于标记本身。

消息颜色为 AABBGGRR。`message_color_argb(value)` 交换红蓝字节，得到图形接口使用的 ARGB，保留 Alpha 与绿色。

|标记|有效数值|缺少数值|
|:--|:--|:--|
|`\cnumber`|修改正文颜色|恢复当前正文恢复颜色；紧随 c 的分号被消费|
|`\crnumber`|修改注音颜色|恢复配置注音颜色，并读取一个后续字符；若该字符为分号，再消费一个字符|
|`\csnumber`|修改阴影颜色|恢复配置阴影颜色；后续字符保留|
|`\cdnumber`|修改正文恢复颜色，当前正文色保持|恢复配置正文恢复颜色；后续字符保留|
|`\fnumber`|修改正文尺寸|恢复配置普通正文尺寸；紧随 f 的分号被消费|
|`\frnumber`|修改注音尺寸|恢复配置普通注音尺寸，消费规则与无数值 cr 相同|
|`\f+number`、`\f-number`|正文尺寸按 DWORD 加减|恢复配置普通正文尺寸，后续字符保留|

例如，`\cr;b` 会消费 b；`\cs;b` 会显示分号和 b。上述消费差异来自基线入口，不能统一改成“读取到分号”。

`\fss`／`\fs`／`\fn`／`\fl`／`\fll` 同时选择最小／小／普通／大／最大正文和注音尺寸。除 `fn` 外，紧随预设的一个分号被消费；`fn` 后的分号显示为字符。

`$`、`i`、`r`、`s`、`t`、`u`、`z` 是基线已登记但当前尚未实现的标记入口。遇到这些转义时返回反斜杠的 UTF-8 字节位置，不以普通转义越过其专属语义。

## 确定度量的布局

`Markup::layout(&settings, measure)` 接受 `LayoutSettings` 和字宽闭包。闭包收到字符与当前正文／注音字号，返回整数前进宽度；字体选择、字形栅格化和资源持有由字体服务负责。布局按 32 位整数回绕运算，保留负位置和负间距，不进行窗口高度裁剪。

`LayoutSettings` 提供：

- `encoding`：`TextEncoding::Cp932` 或 `Unicode`，选择原文字对象路径；输入已经解码后仍保留这一来源。
- `width`：逻辑窗口宽度；`margins` 依次为左、上、右边距。
- `offset`：独立的消息局部偏移；右侧换行边界仍为窗口宽度减右边距。
- `character_spacing`／`line_spacing`：字符和行间距；`normal_size` 为没有可用正文字号时的普通行高。
- `vertical_alignment`：保留水平布局的 Y，或按行顶部／底部对齐；`ruby_offset` 在注音垂直定位时使用。

结果 `Layout.entries` 按原登记次序保存文字和控制记录。`atom` 是 `Markup.atoms` 下标；自动插入的换行使用 None，尺寸与初始位置均为零。每条记录保存位置、尺寸、行号及分组。`Wait::Characters`／`Frames` 不占据布局记录，`Wait::Reset` 和延续操作保留控制记录；这些记录的字符间距仍按相应布局路径处理。

`cursor` 是水平布局阶段最后一个文字记录的右边缘和顶部，`bottom` 是该阶段记录的最大下边缘。垂直对齐和注音重排后，两者保留原值。自动换行的初始行号为零，若该记录随后被布局扫描，按本轮行号更新。首个字形已经越过边界时仍登记该字形，并可能在末尾追加换行。

水平排版依实际宽度、右边界和当前对齐方式决定分行。对齐标记可在同一行切换，模式延续到后面的行。垂直对齐独立按换行记录分段，使用该行的最大字形高度，不改写换行记录本身的 Y。

注音在正文排版后定位，宽度计算不叠加字符间距。短注音按剩余整数宽度逐次分配间隙；长注音先相对正文居中，再限制到逻辑窗口，注音宽于窗口时可得到负 X。`display_anchor` 指向绑定的正文布局条目，后续逐字显示沿这一关系决定注音何时可见。已经跨行分开的分组可能保留未绑定注音；没有任何前一条记录可供绑定时返回诊断。

此接口当前对应关闭禁则与悬挂缩进的布局路径，分组仍可能在宽度边界分行。禁则、不可断行组的整体移动和悬挂缩进继续沿原配置接入。

## 编码路径及定位标记

基线的 CP932 路径在行首宽度扫描时，若当前排版 Y 不等于配置上边距，会把首个参与宽度累计的全角空格记录改为零宽；字形的登记尺寸和实际换行因此改变。Unicode 路径保留全角空格宽度。两条路径使用相同消息字符串仍可能产生不同的行数与游标，不能在解码后丢弃来源编码。

`x`／`y` 标记保留原记录构造行为：x 的数值进入记录类别，坐标参数保持零；值为一／二时分别登记当前组的正文／注音类别，大于二时保留零字号及组号零。y 的数值进入记录 X 字段，Y 字段保持零。后续水平布局按这些实际字段处理，调用方不能直接把标记数值当成最终 X／Y 坐标。

## 验证与后续边界

首批 736 个合成输入在 CP932 与 Unicode 两条路径共执行 1,472 次，6,610 条文字／控制记录、分组、等待参数和最终样式一致；覆盖颜色与尺寸恢复、预设、参数边界、32 位回绕、对齐、等待、字面转义、不闭合分组和非递归分组。常规回归仅使用合成内存字符串，另覆盖多语言字符的 UTF-8 来源区间。

布局的 CP932 路径共核对 1,894 组输入，Unicode 路径另核对 1,280 组；20,290 条字符／控制记录的位置、尺寸、行号、关联及游标状态一致。扩展批次同时以独立标识核对注音显示绑定，确认两条编码路径在全角空格上的差异。常规回归使用合成度量，不依赖系统字体或图形设备。

禁则、悬挂缩进、实际字形服务、消息页状态和逐字播放继续实施。UTF-16 代理对对应的原始显示计数、页级样式恢复及其他已登记标记继续核实。
