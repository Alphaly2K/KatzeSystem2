# 消息标记与布局接口

适用基线：CatSystem2 2.6.1.90。`message::Markup` 把已经解码的消息字符串解析为文字和控制片段，保留样式、注音分组及来源位置。姓名、正文选择和 CSTL 片段绑定由调用者先完成；CP932 与 UTF-8 的输入来源继续分别保存。

## 输入与结果

`Markup::parse(text, &defaults)` 接受 `&str` 和 `StyleDefaults`。五项 `text_sizes`／`ruby_sizes` 依次对应最小、小、普通、大、最大字号，初始使用第三项。正文、注音和阴影颜色由调用者配置。字号和颜色保存原始 DWORD；零字号和回绕结果在此阶段保留，实际度量由布局服务检查。

结果的 `atoms` 按消费顺序排列，每个 `Atom` 包含：

- `source`：当前输入字符串中的 UTF-8 字节区间，转义产生的片段包含已消费的转义部分。
- `kind`：字符、换行、对齐、X／Y 定位、延续或等待操作。
- `style`：该片段生效的正文／注音字号及三种颜色。
- `group`：可选的不可断行组编号和注音标志。

样式标记本身不生成字符。`final_style` 和 `restore_text_color` 保存解析结束时的样式及正文恢复颜色。单次 `Markup::parse` 从传入配置初始化；需要追加时使用下文的 `Page`。姓名更新、显示进度和输入等待由后续消息对象管理。

普通字符以 Unicode 标量保存。来源区间按 UTF-8 字节计数，与字形索引及逐字时间分别解释。接口拒绝零字符，输入字节和字符数受库的存储上限约束。

## 分组、换行与转义

`[word]` 生成同组正文，`[word/ruby]` 的斜杠前后分别标为正文和注音；同组二者共享 `TextGroup.index`。分组不递归：组内第二个 `[` 显示为字符，第一个未转义 `]` 结束该组。注音中的第二个 `/` 显示为字符。缺少右括号时，当前组延续至输入末尾；样式修改继续影响组后的文字。

反斜杠转义先于分组分隔处理，因此 `\[`、`\]`、`\/` 和 `\\` 产生字面字符。未知转义同样显示其后字符，如 `\q` 显示 q。末尾独立反斜杠产生换行；末尾 `\f` 恢复普通字号并显示 f。实际换行字符与标记 `\n` 分别保留，布局阶段再按其类型处理。

|标记|片段或状态|
|:--|:--|
|`\n`|换行|
|`\@`|消息延续操作|
|`\pl`、`\pc`、`\pr`|左、中、右对齐|
|`\p`|左对齐；未匹配的后续字符保留|
|`\xnumber`、`\ynumber`|生成原始 X／Y 定位；无数值时不生成片段|
|`\wnumber`|`Wait::Characters(number)`|
|`\wfnumber`|`Wait::Frames(number)`|
|`\wr`|`Wait::Reset`|

标记字母不区分 ASCII 大小写。对齐和 `wr` 不消费可选分号；其后的分号显示为字符。等待按原始操作顺序保存，通过下文的显示时序接口换算；等待完成和消息页推进由消息对象处理。

## 数值、颜色与字号

数值只接受无符号十进制或 `0x`／`0X` 十六进制前缀，累加按 32 位回绕。数值后的一个分号被消费；无数字的 `0x` 仍成功读取为零。正负号和空格不属于数值。`f+`／`f-` 的符号属于标记本身。

消息颜色为 AABBGGRR。`message_color_argb(value)` 交换红蓝字节，得到图形接口使用的 ARGB，保留 Alpha 与绿色。

|标记|有效数值|缺少数值|
|:--|:--|:--|
|`\cnumber`|修改正文颜色|恢复当前正文恢复颜色；紧随 c 的分号被消费|
|`\crnumber`|修改注音颜色|恢复配置注音颜色，并读取一个后续字符；若该字符为分号，再消费一个字符|
|`\csnumber`|修改阴影颜色|恢复配置阴影颜色；后续字符保留|
|`\cdnumber`|修改正文恢复颜色，当前正文色保持|恢复配置正文恢复颜色；后续字符保留|
|`\fnumber`|修改正文尺寸|恢复配置普通正文尺寸；紧随 f 的分号被消费|
|`\frnumber`|修改注音尺寸|恢复配置普通注音尺寸，消费规则与无数值 cr 相同|
|`\f+number`、`\f-number`|正文尺寸按 DWORD 加减|恢复配置普通正文尺寸，后续字符保留|

例如，`\cr;b` 会消费 b；`\cs;b` 会显示分号和 b。上述消费差异来自基线入口，不能统一改成“读取到分号”。

`\fss`／`\fs`／`\fn`／`\fl`／`\fll` 同时选择最小／小／普通／大／最大正文和注音尺寸。除 `fn` 外，紧随预设的一个分号被消费；`fn` 后的分号显示为字符。

`$`、`i`、`r`、`s`、`t`、`u`、`z` 是基线已登记但当前尚未实现的标记入口。遇到这些转义时返回反斜杠的 UTF-8 字节位置，不以普通转义越过其专属语义。

## 确定度量的布局

`Markup::layout(&settings, measure)` 接受 `LayoutSettings` 和字宽闭包。闭包收到字符与当前正文／注音字号，返回整数前进宽度；字体选择、字形栅格化和资源持有由字体服务负责。布局按 32 位整数回绕运算，保留负位置和负间距，不进行窗口高度裁剪。

`LayoutSettings` 提供：

- `encoding`：`TextEncoding::Cp932` 或 `Unicode`，选择原文字对象路径；输入已经解码后仍保留这一来源。
- `width`：逻辑窗口宽度；`margins` 依次为左、上、右边距。
- `offset`：独立的消息局部偏移；右侧换行边界仍为窗口宽度减右边距。
- `character_spacing`／`line_spacing`：字符和行间距；`normal_size` 为没有可用正文字号时的普通行高。
- `vertical_alignment`：保留水平布局的 Y，或按行顶部／底部对齐；`ruby_offset` 在注音垂直定位时使用。
- `line_breaking`：开启禁则、连续符号及分组边界调整；关闭时依宽度直接分行。
- `hanging_indent`：独立控制开括号后的悬挂缩进，不要求开启禁则。
- `word_wrap`：Unicode 路径在禁则调整后按半角空格保持单词；CP932 路径忽略此值。此开关仅在 `line_breaking` 开启时生效。
- `break_characters`：五类字符集合，由 `BreakCharacters::for_encoding(encoding)` 按当前编码初始化；`Default` 使用 CP932 集合。可追加配置字符，也可显式替换或清空集合，重复字符不改变成员判断。

结果 `Layout.entries` 按原登记次序保存文字和控制记录。`atom` 是 `Markup.atoms` 下标；自动插入的换行使用 None，尺寸与初始位置均为零。每条记录保存位置、尺寸、行号及分组。`Wait::Characters`／`Frames` 不占据布局记录，`Wait::Reset` 和延续操作保留控制记录；这些记录的字符间距仍按相应布局路径处理。

`cursor` 是水平布局阶段最后一个文字记录的右边缘和顶部，`bottom` 是该阶段记录的最大下边缘。垂直对齐和注音重排后，两者保留原值。自动换行的初始行号为零，若该记录随后被布局扫描，按本轮行号更新。首个字形已经越过边界时仍登记该字形，并可能在末尾追加换行。

水平排版依实际宽度、右边界和当前对齐方式决定分行。对齐标记可在同一行切换，模式延续到后面的行。垂直对齐独立按换行记录分段，使用该行的最大字形高度，不改写换行记录本身的 Y。

注音在正文排版后定位，宽度计算不叠加字符间距。短注音按剩余整数宽度逐次分配间隙；长注音先相对正文居中，再限制到逻辑窗口，注音宽于窗口时可得到负 X。正文起点为负 X 时继续检查后续正文，直到取得非负起点或该组结束。`display_anchor` 指向绑定的正文布局条目，后续逐字显示沿这一关系决定注音何时可见。已经跨行分开的分组可能保留未绑定注音；没有任何前一条记录可供绑定时返回诊断。

## 禁则、分组与悬挂缩进

`BreakCharacters.no_start`／`no_end` 分别配置行首和行尾禁止字符，`repeated` 配置连续相同字符的分组。禁则调整先回退行尾禁止字符，再按剩余宽度追加标点；追加失败时最多检查四条尾部记录，再决定回退正文或保留原位置。分组处理随后检查正文、注音及连续符号的边界。组本身宽于可用行宽时仍持续推进，允许拆分，不产生无限换行。显式换行、对齐及其他控制记录继续参与对应阶段的处理。

`indent_open` 确定初始悬挂宽度，取首个文字的度量宽度加字符间距；首行不缩进，后续行按此宽度平移。后续行首再次遇到该集合中的字符时，本行暂时取消缩进；`indent_keep` 保持前一行的缩进开关，其他字符恢复缩进。字符集合检查跳过控制记录；宽度扫描与最终对齐均使用相同的缩进量。

Unicode 的 `word_wrap` 按半角空格确定单词边界，空间不足时回退到当前行前面的空格；超长单词仍可分行。开启后使用单词边界处理，正文／注音的显式分组与关闭时的调整结果可能不同。

## 编码路径及定位标记

基线的 CP932 路径在行首宽度扫描时，若当前排版 Y 不等于配置上边距，会把首个参与宽度累计的全角空格记录改为零宽；字形的登记尺寸和实际换行因此改变。Unicode 路径保留全角空格宽度。两条路径使用相同消息字符串仍可能产生不同的行数与游标，不能在解码后丢弃来源编码。

禁则追加也保留编码差异：CP932 对全角空格使用特殊追加规则，Unicode 对半角空格使用该规则；Unicode 另区分半角句点、句号及后续闭引号。Unicode 默认行首／行尾集合增加了部分引号和横线字符，因此应按编码初始化集合，避免沿用另一条路径的默认配置。

内部控制码 8 在 Unicode 路径中参与换行、禁则边界及垂直分段，CP932 路径保留普通控制记录。布局仍保留原始记录类别，调用者不必将其改写为文本换行。

`x`／`y` 标记保留原记录构造行为：x 的数值进入记录类别，坐标参数保持零；值为一／二时分别登记当前组的正文／注音类别，大于二时保留零字号及组号零。y 的数值进入记录 X 字段，Y 字段保持零。后续水平布局按这些实际字段处理，调用方不能直接把标记数值当成最终 X／Y 坐标。

## 逐记录显示时间

`Markup::schedule(&layout, &settings, initial_units)` 接受本片段的布局和 `TimingSettings`，两者使用同一 `TextEncoding`。返回 `Schedule.deadlines`，与 `Layout.entries` 一一对应；`accumulated_units` 保留最终计数，可传入后续片段。此接口不读取时钟，也不改变布局或输入状态。记录时间可能回退，调用者不得假定数组递增。

`TimingSettings` 提供全局原始时间比例 `time_scale`、普通字符间隔 `character_delay`、句末间隔 `period_delay` 和空格跳过开关 `skip_spaces`。生成普通记录时间时，先将当前计数乘时间比例、按 DWORD 回绕，再除以十；随后才为该字符增加间隔。CP932 仅对句号使用句末间隔，Unicode 同时处理半角句点。启用 `skip_spaces` 后，半角与全角空格均不增加计数；其他控制记录和保留字符 U+FFFF 同样不增加计数。

等待操作按输入顺序执行：

|操作|计数变化|
|:--|:--|
|`Wait::Frames(n)`／`\wfn`|加 n，按 DWORD 回绕，不生成布局记录|
|`Wait::Characters(n)`／`\wn`|当时间比例按 i32 解释为正数时，将计数重设为 `(character_delay × n × 10) / time_scale`；乘法先按 DWORD 回绕，除法使用无符号整数；其他比例保留计数|
|`Wait::Reset`／`\wr`|清零后生成控制记录，因此自身时间为零|

注音初始时间为零，布局完成后沿 `display_anchor` 继承正文记录的时间。注音内的等待仍改变后续正文的计数。自动插入的换行时间为零；显式换行、对齐、定位和延续控制保留生成时的时间。X 类别大于二的记录保留零时间。

`time_scale: None` 对应尚无全局时间上下文：普通记录时间为零，普通字符不推进计数，`wf` 和 `wr` 仍修改计数。`w` 在此情况下返回来源位置诊断。零比例与缺少上下文分别处理：零比例仍使普通字符推进计数。非 BMP 字符的逐字时间映射尚未接入，当前返回诊断。布局中的来源下标、自动记录类型及显示绑定必须有效；绑定目标须位于当前记录之前。

## 消息页追加与清空

`Page::new(defaults, encoding)` 创建空页，保存配置和编码路径。`append(text)` 追加来源并使页失效；直到 `prepare(&layout_settings, &timing_settings, measure)` 才解析新增文字、度量整页并更新布局。一次准备前的多个追加可共同构成一个标记或注音分组。

`prepare` 返回 true 表示完成了重新准备，返回 false 表示页未失效、继续使用已有结果。`source()` 包含完整输入和待处理追加；`markup()`、`layout()` 与 `schedule()` 查询最近一次成功准备的结果。原子片段的来源区间相对于整页 UTF-8 字节。页、布局及时间配置必须选择相同的编码路径。

成功准备后，当前字号、三种颜色、正文恢复色、下一个分组编号及累计时间保留到后续追加。已经准备过的未闭合分组在该次解析末尾结束并占用一个编号，后续追加从组外开始；准备前仍待处理的来源则一起解析。旧记录的时间保持，新的时间设置只参与新增记录的计数和换算。

改变布局配置后调用 `invalidate_layout()`，再调用 `prepare`。既有自动换行继续保留；增大宽度不会删除先前已经插入的换行。整页字宽重新度量，既有坐标继续参与定位标记和注音的重新排版。注音取得新绑定时继承绑定时间；未取得新绑定时保留上次显示时间，`display_anchor` 为 None。

`clear()` 清空来源、解析及布局记录、显示进度和累计计数，恢复创建时的字号与颜色，并重置分组编号；当前显示速度保持。下一次准备重新使用传入的布局和时间配置。追加前检查零字符和存储上限；解析、度量或布局失败时保留上次成功结果及待处理来源，重试不会重复累计时间或应用相对样式。

## 普通逐字显示

完成准备后，`Page::advance(now, segment_limit)` 按传入时刻推进普通显示，返回 `DisplayUpdate { newly_visible, complete }`。`newly_visible` 是当前 `Layout.entries` 中本轮首次显示的字形下标，保留记录顺序，正文和注音均包含在内；控制记录不显示。`is_visible(index)` 查询上次准备结果中的字形是否完整显示，控制记录返回 Some(false)，越界返回 None。`glyph_state(index)` 提供 `Hidden`、`Complete`、`Revealing` 三种状态；普通显示只使用前两种，控制记录为 Hidden。重新准备和追加保留旧字形的显示状态。

每次调用独立检查当前范围的全部字形，允许后面的记录先到时。已显示的字形保持可见，同时仍参加本轮时间检查；时钟回退或速度基准变化后，`complete` 可以重新为 false。`remaining(segment_limit)` 只统计该范围内尚未显示的字形，因此可能为零而本轮时间检查尚未完成。页失效时，这两个推进／计数接口要求先完成 `prepare`，避免使用待处理文字的旧结果。

消息流中的 U+FFFF 是分隔记录。`segment_limit` 为零时只扫描第一个分隔之前的记录，为一时扫描到第二个分隔之前；u32::MAX 表示全部记录。其他值在分隔比较时保留 i32 解释。达到分隔上限时立即返回当前范围的完成状态，并保留上次处理时刻。

初始 `speed()` 为十，`set_speed(value)` 修改原始速度；十对应普通速度，零停止时间推进。速度改变时，以最近一次完整扫描的时刻及已到时记录的最大原始显示时间建立新基准；设置相同值保持基准。经过时间按 `(now - time_origin) × speed / 10` 换算，减法和乘法先按 DWORD 回绕；字形时间减去显示时间基准后，按无符号值与经过时间比较。`now` 为 u32::MAX 时忽略逐字时间、强制显示当前分隔范围。

此接口提供普通显示状态；字形绘制可使用下文的前景或效果接口，或由调用者消费 `newly_visible`。后文的 `Display` 将页面状态与持久像素、渐显更新一起管理。消息对象的脚本命令继续接入。

## 显式字体与前景绘制

`Font::from_bytes(bytes, collection_index)` 从显式 TrueType／OpenType 字体或字体集合构造拥有自身数据的字体服务。调用者负责提供有权使用的字体字节并选择集合成员；服务不查询系统字体，不提供默认字体，也不自动回退。`has_character(c)` 查询可用字符，缺字在度量或绘制时返回包含 Unicode 编号的诊断，不替换为默认缺字图形。

`Font::measure(c, size)` 返回四舍五入到整数的水平前进宽度，可直接传入 `Page::prepare`。`Font::rasterize(c, size)` 返回 `GlyphMask`，保存顶端起始的覆盖、尺寸、相对于布局记录的偏移和同一整数前进宽度。像素字号按 em 解释，基线使用不超过字号的整数 ascent，并保留一像素留边；负的横向起点加留边后限制到零。字号为零返回空遮罩；字号超过 i32 范围、无效字体、集合成员或超出像素存储上限均返回诊断。

当前字体后端采用 fontdue 的轮廓栅格化，并将 0～255 覆盖按最近整数换算为 0～64。它没有 GDI 的 hinting 和字体选择／回退流程；GDI 原字形的字宽与边缘像素一致性仍需沿字体适配层核实。消息标记、布局和显示时间继续使用前述基线规则，调用者也可提供其他确定的度量与遮罩服务。

`GlyphMask::new(size, offset, advance, coverage)` 接受显式灰度遮罩，检查尺寸、长度和每个覆盖值。`colorize(color, double_coverage)` 将消息的 AABBGGRR 颜色转换为 BGRA 渲染面。正常 Alpha 为 `coverage × 255 / 64`；加倍路径在该整数结果上乘二并限制到 255。颜色本身的 Alpha 不参与，零覆盖仍保留 RGB。

`Page::paint_foreground(&mut surface, origin, glyph)` 按登记顺序混合已显示的正文和注音。字形闭包接受字符及当前记录字号，可使用 `|c, size| font.rasterize(c, size)`；正文与注音分别采用对应颜色。目标位置为 origin、布局位置和遮罩偏移的回绕整数和，裁剪与普通混合复用图形接口。返回 true 表示存在裁剪后非空的绘制区域。

页须先完成准备；接口保留目标原内容，调用者在重绘整页前清空或恢复消息背景，避免重复混合边缘。字形服务失败时返回诊断，之前的绘制继续保留。此接口只绘制前景；需要阴影或轮廓时使用下文的效果绘制。加粗／斜体配置及完整字形缓存继续接入。

## 轮廓、偏移阴影与字形合成

`GlyphEffects { outline, shadow, shadow_offset }` 配置两种可叠加效果；默认均关闭，原始偏移为 [1, 1]。`apply(&mut target, &source, font_size, shadow_color)` 接受同尺寸的 BGRA 字形面，返回是否启用了效果；两种效果均关闭时直接返回 false 并保留目标。启用效果时先执行轮廓，再执行偏移阴影，保留输入颜色的低三字节，Alpha 只由来源和目标覆盖决定。

轮廓分别沿横、纵方向累加相邻三点 Alpha，每一步限制到 255，边缘使用零。基线纵向复制列时使用宽度作为长度，输出仍使用高度，因此高大于宽时仅保留前 width 行及其相邻覆盖。宽大于高会越过原目标的逻辑像素边界，此接口在修改目标前返回诊断。正常消息绘字使用方形临时面。

字号按无符号值小于二十时，阴影的每个偏移先按 i32 回绕加一，再算术右移一位；否则使用原始偏移。处理时从末行向前、每行从左向右，在偏移后的目标位置累加该位置原 Alpha、未偏移目标 Alpha 和来源 Alpha，再限制到 255。同一行的新目标值会参与后续像素计算。偏移超出渲染面时对应区域为空；有效偏移为负会导致基线越界，此接口在写入前返回诊断。

阴影保留基线独立的颜色写入规则：消息 AABBGGRR 的低三字节直接作为目标 BGRA 的前三字节，因此彩色阴影的实际红蓝次序与前景不同。零 Alpha 的效果像素仍写入这些 RGB；不得为了透明像素归零而改变结果。颜色自身的 Alpha 不参与效果。

`GlyphMask::paint(&mut target, &GlyphPaint)` 将遮罩按自身偏移放到与目标同尺寸的临时面，生成效果后合成前景。`GlyphPaint` 提供前景色、阴影色、原始字号、覆盖加倍开关及 `GlyphEffects`。没有效果时直接复制前景像素；有效果时使用普通 Alpha 混合。调用者负责目标的初始内容；轮廓会覆盖整个字形面，偏移阴影会累计已有内容。

返回的 `Rect` 从 [0, 0] 开始，其右／下端点分别为遮罩偏移加尺寸、原始阴影偏移及二像素留边，按 i32 回绕；即使阴影关闭或小字号缩小了实际偏移，范围仍使用原始配置。前景合成按此范围裁剪，效果计算覆盖整个字形面。

`Page::paint(&mut target, origin, &effects, double_coverage, glyph)` 使用基线的 128 × 128 临时字形面，依布局登记次序绘制当前可见的正文与注音；两者采用各自字号与颜色，阴影颜色来自片段样式。字形服务仍接受字符与字号，空遮罩跳过。字形位置保存在临时面内，消息 origin 与布局位置在最终混合时相加。此接口同样要求页面已准备，保留背景，返回是否存在裁剪后非空区域；持久显示与页面级渐显使用下文的 `Display`，字体适配继续接入。

## 水平渐显核心

`Reveal::new(width)` 建立从左到右显示文字的过渡表；宽度须非零且不超过存储上限，`width()`／`gradient()` 查询配置。表项为 `255 - ((i × 255) / width)` 的低字节，乘法先按 DWORD 回绕。宽度为零时，上层消息配置需要选择普通显示路径；此构造器返回诊断。

`Reveal::phase(now, normal_size, character_delay)` 使用原始时刻、配置中的普通正文字号与字间隔，返回有符号像素进度。普通情况为 `(now × normal_size × 2) / character_delay`，乘法按 DWORD 回绕，除法使用无符号整数，结果再按 i32 解释；now 的最高位为一或字间隔为零时返回 i32::MAX。这条路径不使用普通逐字播放的速度基准和逐记录 deadline。

`Layout::reveal_starts()` 返回与布局等长的 `Vec<Option<i32>>`，控制记录为 None。每行以按无符号值比较的最小 X 为起点；跨行累计采用上一行在登记顺序中最后一个字形的右边缘，注音同样参加计算。内部控制码九使本次扫描的累计距离归零，所以同一行控制码前后的字形可能使用不同基准。距离的加减保留 i32 回绕。

`RevealGlyph { position, bounds, start }` 保存消息面内的字形位置、字形局部绘制范围及上述渐显起点。bounds 可直接使用 `GlyphMask::paint` 的返回范围。来源面保留完整字形像素，目标面保留逐次显示状态；新增完整字形写入来源后，调用 `Reveal::copy_colors(&mut target, &source)` 同步整个面的 RGB，目标 Alpha 保持。

`reveal.apply(&mut target, &source, &glyph, phase)` 只更新 Alpha，返回该字形是否完成。两个面必须同尺寸且非空。进度尚未到达字形起点时保留目标并返回 false；完整显示以 `phase - width >= bounds.right + start` 的回绕有符号比较判断，成立时恢复范围内的来源 Alpha。其他情况按每列在过渡表中的位置计算 `(table[i] + 1) × source_alpha >> 8`；已经经过的列恢复完整 Alpha，尚未到达的列保留目标现值，因此时间回退不会清除这些列。

范围的四个端点分别加字形位置、按无符号值限制到面尺寸减一，再按左上包含／右下排除遍历。负端点因此可能限制到最后一个像素，裁剪后的末列、末行继续保留原 Alpha；不能改成通常的有符号矩形裁剪。返回值按字形时间范围判断，即使实际像素范围为空仍可完成。

这些接口提供渐显位置与 BGRA 像素更新；下文的 `Display` 负责页面级预生成、显示状态转换和分隔范围。脏区提交和脚本完成等待仍待接入消息对象。独立的 `Page::advance` 与 `Page::paint` 继续使用普通逐字显示。

## 持久消息显示

`Display::new(defaults, encoding, size, settings)` 创建拥有消息页和持久 BGRA 像素的显示对象，尺寸与编码在创建时确定。`DisplaySettings` 保存 `effects`、`double_coverage` 和 `reveal_width`；渐显宽度为零选择普通逐字显示，非零时另建完整来源面。渐显要求非零面尺寸，过渡宽度受前述存储上限约束。

`append(text)`、`prepare(&layout, &timing, measure)` 与 `invalidate_layout()` 遵循 `Page` 的追加和重新准备规则。成功准备后保存最新字间隔供渐显换算使用；普通字号来自创建时的默认字号配置。`page()` 以只读方式提供解析、布局、时间和字形状态查询，`settings()` 查询显示配置。追加或布局失效后须先准备，再推进显示。

`advance(now, segment_limit, glyph)` 接受字符／字号到 `GlyphMask` 的服务，返回 `DisplayProgress { prepared, completed, complete }`。两个下标列表均对应当前 `Layout.entries`，按登记顺序保存本轮首次处理和首次完成的字形。普通显示的两个列表相同；渐显先把当前分隔范围内尚未处理的字形写入完整来源面，标为 Revealing，再同步来源 RGB、推进各字形 Alpha。字形完成后标为 Complete，后续时间回退保留该状态及像素。

正文与注音使用各自的颜色与字号，并共同遵守分隔上限。普通模式按逐记录 deadline 检查完成，已经显示的字形仍参加本轮时间判断；渐显只处理尚处于 Revealing 的字形。`page().remaining(limit)` 统计 Hidden 和 Revealing，`page().is_visible(index)` 只对 Complete 返回 true。渐显中的实际部分像素通过 `surface()` 查询。

新处理字形的 128 × 128 区域完全位于消息面外时跳过字形服务，仍按对应模式推进状态。渐显的局部绘制范围保存在该字形记录中，完成检查沿前述像素核心执行。达到 U+FFFF 分隔上限时，保留上次处理时刻；完整扫描才更新该时刻。`set_speed(value)` 维护普通播放的速度与基准，渐显继续使用独立的原始时间换算。

`surface()` 是当前可合成的消息像素，`source_surface()` 在渐显模式下返回完整来源面，在普通模式下返回 None。推进只绘制首次到时或首次预生成的字形；重新准备和追加保留已有像素，不重复混合旧字形。重新排版改变记录位置时，既有像素继续保留，后续新字形与渐显更新使用新位置。调用者将 `surface()` 合成到消息背景及最终画面。

`clear()` 清空文本、字形状态、累计时间和两份像素，保留创建配置及当前速度；下一次显示先重新准备。字形服务失败时，已处理的字形与像素保持，失败字形仍为 Hidden。重试只请求尚未成功处理的字形；此前待同步的来源颜色在下次推进时补齐，即使下次缩小分隔范围也不会丢失。

此显示对象已承担普通／渐显页面推进；运行时字体重配、消息任务命令、脏区提交、输入翻页和脚本等待继续接入。
