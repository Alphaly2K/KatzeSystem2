# 任务树与生命周期

适用基线为 Windows CatSystem2 **2.6.1.90**。本页记录通用任务更新和销毁的原入口行为，作为连接 KCS、FES 和对象调度的依据。现有接口见 [API 文档](api.md)，普通任务的消息及运行开关见 [KCS](kcs.md)。

## 单轮更新

通用任务按以下顺序推进：

1. 更新自身整数时钟，包括暂停平移起点及单步标记消费。
2. 按 i32 编号升序更新直属子任务，每个子任务递归执行相同步骤。祖先索引中的深层别名不会使同一任务重复更新。
3. 清理当前层索引中的空项。
4. 检查自身删除标记。任意非零值进入销毁并返回零；标记为零时返回成功，派生对象随后执行自己的更新主体。

因此，各任务的时钟先于其子任务更新，而对象主体在子任务之后执行。父任务已经标记删除时，其子任务仍先完成这一轮更新。子任务在主体中标记父任务，父任务本轮就会跳过主体并销毁；任务在自己的主体中标记自己，则留到下一轮通用更新处理。

普通任务主体在上述过程之后检查 running、处理排队消息并恢复 VM。时钟 paused、任务 running 和 VM 执行模式各自独立。单任务 `OrdinaryTask::update` 组合时钟及主体；树调度可在子任务更新前调用 `clock.update`，子任务结束后调用 `OrdinaryTask::update_body`，保持这两个时点。子任务期间设置的单步标记留到下一轮时钟更新，主体不会再次消费。

## 销毁顺序

通用析构在进入后按以下顺序处理：

1. 从各级祖先索引撤销当前任务编号的值。对象仍存活，父指针及后代编号的索引值仍保留。
2. 按 i32 编号升序向存活的直属子任务发送删除命令 3：sender 为当前任务编号，三个 data 项均为零。
3. 按对象类型处理自身通知并标记删除：通用基类使用基类路径，普通任务保留专属通知路径；已有删除标记时跳过重复通知。
4. 再按同样顺序逐个析构直属子任务，递归完成其子树处理，最后释放自身索引和对象存储。

向所有直属子任务发送请求的阶段先于逐个析构。已存在非零删除标记的子任务跳过专属处理器；未标记的普通子任务可以在收到请求时同步执行删除通知。每个子任务自己的析构继续处理其直属子任务，因此通知与释放不能合并为一次无回调的扁平移除。

`TaskTree::unregister` 已提供撤销当前编号的中间状态，`remove` 在对象释放时移除整个子树。`TaskTree::update`／`destroy` 已组合时钟、对象通知、子树释放及主体调度，类型专属行为由 `Lifecycle` 服务提供。服务负责派生类额外资源释放；根关闭后树不再接受更新。

## 撤销注册期间的查询

当前编号被撤销后，祖先索引保留一个空值，该编号暂时无法从祖先查询；后代编号的别名继续指向仍存活的对象路径。因此外部可以在同一时刻查不到父任务，却仍然查到该任务的存活后代。75 的枚举也会跳过父编号并继续列出后代编号。任务自身的直接引用、自己的编号查询及父指针继续有效。

发送普通命令时先查发送任务自身的索引，再沿父指针向上转发。后代可以沿父指针直接发送给已撤销注册的祖先；其他分支无法直接找到这个编号。广播针对存活后代时，仍可能通过别名进入该已撤销注册的父任务；从根广播全树时，直属子任务遍历跳过已撤销的父编号及该分支。

`node(id)` 继续提供存活对象元数据，`find_in_subtree` 与消息路由遵循索引可见性。`children` 枚举仍登记的直属子任务；`subtree_ids` 和 `remove` 处理实际拥有的整个子树，包括已撤销编号。编号回收仍在同步通知及析构完成后的根层清理中进行。

## 更新期间修改树

更新遍历使用当前索引的有符号编号游标：

- 在某一父层的当前游标之后插入新子任务，本轮会更新它；插入到游标之前，则从下一轮开始。
- 任务主体开始时，该任务自身的子任务遍历已经结束。此时向自身加入新子任务，新任务从下一轮开始更新。
- 在主体中标记尚未更新的兄弟任务，该兄弟仍更新时间及子任务，随后进入销毁，跳过主体。
- 在主体中直接销毁后续兄弟任务，后续游标跳过已清除的对象。
- 销毁已更新的另一分支不会使该分支在本轮再次执行。

析构留下的空编号在根索引清理前继续占用自动编号。子任务主体查询自动编号时，仍可能遇到此前销毁留下的占位；根完成清理后，其主体可以复用这些编号。

## 验证范围

使用十节点合成树覆盖全部 512 种非根删除标记组合、三种暂停分布及三个连续时刻，共 4,608 次更新、57,792 个更新／主体／通知／析构事件。事件顺序、时钟全部字段、删除状态、存活节点及下一自动编号均与原入口一致。

另外十二组动态修改各连续更新三次，共 36 次更新、720 个事件，覆盖游标两侧插入、向自身及祖先插入、标记自身／父级／兄弟，以及直接销毁兄弟或其他分支。完整事件及状态同样一致。原入口验证独立运行，常规测试使用本项目构造的合成输入。

撤销注册期间另核对九组析构场景的 579 份快照，包括 6,369 次查询、6,948 次 native 75 枚举及 6,369 次命令发送；库接口全部一致。十六种撤销组合的 10,560 次直接／广播调用和 22,075 次处理器调用也全部一致，覆盖从内部和外部分支访问、类型筛选及处理器消费。

同步调度器已直接重放上述 4,608 次静态更新和 36 次动态更新，原入口额外记录最终释放时点。全部 57,792 个静态及 720 个动态更新／通知／释放事件、时钟、节点状态及自动编号一致。常规合成集成测试使用真实 OrdinaryTask，覆盖分段更新、同层通知先于递归释放、根关闭和游标两侧新增任务。

`runtime::Runtime` 按上述契约实现 `Lifecycle`。普通对象执行期间继续接受删除标记和排队消息；同步回信给仍在执行的发送者返回零。消息处理阶段新增的消息继续在本轮消费，无消息恢复阶段新增的消息留到下一轮。执行中的完整对象暂时取出，其他需要直接借用该对象的操作返回诊断；嵌套执行结束后恢复宿主记录的任务编号、时刻与起点。对象协议和工厂见 [接口文档](api.md#任务运行时)。

对象命令的六个 DWORD 保持原布局，进程指针通过额外的 `CommandBuffers` 显式字节借用传入运行时；同一次树分派共享其中的修改。基础二维对象的属性处理器另有内部子级转发，不依赖外层 `data[2]`，以当前对象为 sender 并共享返回槽，契约见[二维对象](graphics.md#基础二维任务对象)。
