# KCS 宿主调用清单

适配基线为 CatSystem2 2.6.1.90。完整统计保存在 [native-calls.tsv](native-calls.tsv)，仅记录宿主表、程序版本、编号、参数字节数和调用点数量。

## 编号与函数表

编译后的 KCS 使用 `2B` 调用宿主。第一个操作数求值为索引，第二个操作数求值为参数字节数；原处理器从当前 VM 已注册的表取得该索引对应的函数指针。普通任务的装载链在程序装载后注册引擎内置表，运动与粒子任务注册各自的表。粒子任务还依据程序版本选择接口表。

因此接口身份须包含宿主表及适用版本。同一基线、同一表的槽号固定；其他版本的槽号、参数和返回协议须另行核对。源语言声明如何映射函数名与编号仍待核实，现有结论针对编译产物和宿主注册行为。

## 跨游戏调用表核实

两套独立游戏材料均已核实脚本和宿主注册链，下称 A（适配基线）与 B（对照样本）。两套引擎的 PE 版本资源均为 **2.6.1.90**，代码、数据布局和部分实现存在差异。

结论：两套样本使用相同的固定槽号契约，没有按游戏或按 KCS 文件重排 native 编号。函数表来自引擎宿主；普通程序装载后直接登记内置表，调用处理器按 `table[index]` 取得函数指针。编译 KCS 的字符串初始化表不参与这一步绑定。源语言可以通过声明隐藏数值编号，编译产物仍记录槽号。

|宿主表|A 表项数|B 表项数|逐槽对应结果|
|:--|--:|--:|:--|
|ordinary|1,080|1,080|顺序保持，953 个不同入口及全部别名关系一致|
|motion|45|45|顺序保持|
|particle，旧程序版本|44|44|顺序保持|
|particle，2.0|51|51|顺序保持，前 44 项完整保留旧表，末尾追加 7 项|

普通表中相同槽位的入口仅随两个连续代码区整体移动；运动表的全部入口作同一整体移动。代表入口另核对了参数读取、返回状态、任务字段及转发命令号，覆盖原样数值返回、字符串格式写入、任务编号、消息等待、图像资源装载及列表登记。两套宿主都在装载后登记自己的常量表地址，没有从 KCS 读取每份程序的编号映射。

两套编译脚本的完整静态统计如下。B 的分组清单见 [native-calls-comparison.tsv](native-calls-comparison.tsv)。两套输入均经独立解压和指令遍历复核，全部调用的索引及参数字节数都是标志 `03` 的立即数。

|宿主表|A 程序数／调用点数／不同编号数|B 程序数／调用点数／不同编号数|共同编号数|
|:--|:--|:--|--:|
|ordinary|14／7,550／587|12／7,423／585|584|
|motion|72／541／16|72／541／16|16|
|particle|17／393／28|111／3,005／32|28|

各表共同编号的参数字节数组合全部一致。B 普通脚本额外使用 1063，参数区八字节；粒子脚本额外使用 21／22／23／43，参数区分别为四／八／八／八字节。另有 7 份普通程序、72 份运动程序和 10 份粒子程序与 A 的完整容器逐字节相同。B 的三个补丁归档没有额外 KCS 容器。

适配应先复用同一宿主表的已有编号和签名，再依据实际差异扩展。当前两套引擎的版本标记相同，跨引擎版本的槽位变化幅度尚待不同版本样本核实；已观察到的粒子程序版本演进采用末尾追加。相同槽号的内部行为仍可调整：对照样本的普通 245 增加了全局条件分支，265／268 的内部对象分配尺寸发生变化，而脚本参数区长度保持一致。后续成本需要分别统计新增接口、既有行为差异和子系统缺口。

## 静态统计

|宿主表|程序数|指令数|宿主调用点|不同编号数|
|:--|--:|--:|--:|--:|
|ordinary|14|144,199|7,550|587|
|motion|72|9,477|541|16|
|particle|17|6,670|393|28|
|合计|103|160,346|8,484|631，按表分别计数|

全部调用的两个操作数标志均为 `03`，即直接 DWORD 立即数；未发现动态索引或动态参数长度。独立的头部解压和指令遍历与 CLI 的全部分组结果一致。

例如普通表 710 有两个调用点，参数区均为四字节；728 有一个调用点，参数区为八字节；737 有两个调用点，参数区为八字节。这些需求可在执行游戏前从编译脚本取得。参数的类型、句柄生命周期、返回状态及完成条件需结合宿主函数及其调用上下文确认。

`call_sites` 统计代码中的调用位置。一个位置可能反复执行，也可能位于尚未触发的分支；流程依赖和子系统依赖共同决定实现顺序。

## 批量提取

```sh
cargo run --release --locked --bin katze-script -- native-calls ordinary core-programs/
cargo run --release --locked --bin katze-script -- native-calls motion motion-programs/
cargo run --release --locked --bin katze-script -- native-calls particle particle-programs/
```

输入为一个或多个 KCS 文件或单层目录。目录只读取 `.kcs` 文件，表类别由调用方依据宿主装载链指定。结果按程序版本、索引和参数字节数分组。CLI 将标志 `03` 的 DWORD 立即数作为静态值；其余索引计入 `unresolved_indices`，其余参数长度显示 `?`，留待进一步求值分析。输出不列出输入文件名。相同输入路径去重，读取或解析失败会返回错误。

CLI 只读取和解码程序，不执行任何脚本或宿主函数。合成输入已核对重复调用、同编号不同参数长度、动态索引、动态长度和重复输入。
